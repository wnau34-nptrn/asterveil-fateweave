## ความตรงของภูมิภาค 1

`region_rect = {x:60, y:1900, w:432, h:936}` บนภาพ 1080×3000 สเกล **0.4** ของต้นฉบับ 1080×2340 โดยไม่หมุน ไม่บิด ไม่ตัดขอบ ตำแหน่งบน master คูณสองทั้งหมด

สคริปต์คืนภาพต้นฉบับทั้งสี่เหลี่ยมเป็นขั้นตอนสุดท้ายเสมอ ไม่ใช้ภูมิภาค 1 ที่เครื่องมือวาดใหม่ ภาพก่อนบีบอัดมี RGB ตรงกับต้นฉบับที่ย่อด้วย Lanczos ทุกพิกเซล ไฟล์ WebP ใช้การบีบอัดแบบสูญเสียรายละเอียดเพื่ออยู่ในงบ จึงมีความต่าง RGB เล็กน้อย (บันทึก mean absolute error จริงใน validation.json) แต่ไม่มีการเปลี่ยนตำแหน่ง/สเกล เส้นทาง 9 เส้นและจุด 10 จุดแปลงด้วยสูตร `worldX=60+0.4*x`, `worldY=1900+0.4*y` ใน `region1_world_geometry.json` ความคลาดเคลื่อนการวางทางเรขาคณิต 0px ไม่ใช่การอ้างว่าใช้ computer vision วัดจุดจากภาพบีบอัด

`match_region1.png` แสดงซ้าย=ภาพโลกก่อนบีบอัดตรง region_rect กลาง=ต้นฉบับที่ย่อ ขวา=ซ้อนทับ 50% ทั้งสามควรตรงกัน ภาพนี้เป็นหลักฐานจัดวาง ไม่ใช่ภาพเกม

## วิธีสร้างและข้อจำกัดของความละเอียด

ใช้ built-in image generation สร้างภาพใหม่สำหรับโปรเจกต์นี้เท่านั้น ไม่มีภาพจากเกมอื่น prompt จริงและ reference แต่ละครั้งอยู่ใน `prompts.json` ไม่มี base64 หรือ seed สุ่มที่แต่งขึ้น เครื่องมือไม่ได้เปิดเผย generation id; เก็บไฟล์ผลลัพธ์จริงใน raw และชื่อ output ของเครื่องมือใน `generation_outputs.json`

ภาพจัดองค์ประกอบแรกมี native **753×2089** จึงไม่ใช้ภาพนี้ขยายเป็นงานสุดท้ายโดยตรง สร้างท่อนรายละเอียดใหม่ 3 ท่อน native **1189×1323** แต่ละท่อน อิง crop ที่ยึดองค์ประกอบร่วมกัน ประกอบที่ขนาด 2160×2400 โดยวาง origin y=0,1800,3600 บน master 2160×6000 มี overlap 600px ต่อรอยต่อ แก้ท่อนกลางเพื่อลบ landmark บทที่ 1 ที่ซ้ำเหนือ rectangle และแก้ท่อนล่างให้ขอบภายนอกรับกับต้นฉบับ วิหารดินดอนแก้เป็นขั้นบันได

`build_handoff.py` เลือกรอยต่อด้วย minimum RGB squared-error path แบบ dynamic programming และ feather 16px รอบเส้นทางอัตโนมัติ จึงไม่เกิดภาพ landmark ซ้อนจากการ crossfade กว้าง ลด saturation ภูมิประเทศใหม่ด้วย factor 0.86 แล้วคืนภาพบทที่ 1 เดิม ไม่ปรับสีบทที่ 1 ใช้ collar ขอบต้นฉบับที่ต่อออกไปด้านนอก 48 master pixels และลด alpha ตามระยะอย่างคำนวณได้ ก่อนคืนภาพต้นฉบับด้านในอีกครั้ง ไม่มีการต่อด้วยมือหรือแต้มสีที่รอยต่อ

**2160×6000 เป็นขนาดส่งออกของงานประกอบ ไม่ใช่ native generation 6K** ท่อนที่สร้างใหม่ให้รายละเอียดใกล้ความกว้างภาพเกม 1080px ส่วน master 2× ยังมีการ resample ภาพอ้างอิงบทที่ 1 คงรายละเอียดตามต้นฉบับเดิม ไม่อ้างว่าวาดจุดเหล่านั้นใหม่ที่ความละเอียดสูงกว่า

## หมอกและพื้นที่แตะ

หมอกเป็น RGBA จริง ใช้ texture เมฆต้นฉบับจาก `region_ch1_fog.webp` ใน intake เดิม ปรับ pearl-blue และ alpha 200–228 ก่อน mask ให้เห็นเพียงเงาจางของ landmark มี alpha 0 ครอบคลุมภูมิภาค 1 ทั้งหมด และ feather ด้านนอกเท่านั้น ไม่วาดภูมิประเทศในชั้นหมอก

โพลิกอน 6 ชุดเป็น partition ของ canvas รวมทะเลตกแต่งด้วย ขอบร่วมมีพื้นที่ 0 จึงไม่มี interior ทับกัน ครอบคลุมแผ่นดินทุกส่วน ไม่ใช่เส้นเขตการเมืองในภาพ ตรวจ Shapely ทั้ง validity, intersection, union, anchor containment และการครอบคลุม region_rect ภูมิภาค 1 ใช้ขอบไม่เป็นสี่เหลี่ยมเพื่อให้หมอกเป็นธรรมชาติ `anchor` เป็นจุดโฟกัส/หมุดที่เสนอ ไม่ใช่เนื้อเรื่องใหม่

## ไฟล์และการสร้างซ้ำ

- `world_map.png`: 2160×6000 RGB, embedded sRGB, ทึบ
- `world_map.webp`: 1080×3000, quality 90, ≤1,600,000 bytes
- `world_map_2x.webp`: 2160×6000, quality 88, ส่งเฉพาะเมื่อ ≤3,500,000 bytes
- `world_map_fog.webp`: 1080×3000 RGBA, ≤600,000 bytes
- `preview_390.png` และ `preview_fog_390.png`: ภาพรวม 3 ช่อง แต่ละช่อง viewport 390×844; scroll offsets บนภาพที่ย่อ=0,120,239px มีการซ้อนช่วงเพราะแผนที่เต็มที่ความกว้าง390สูงเพียง1083px ไม่มี UI จำลองที่อาจถูกเข้าใจว่าใช้งานจริง
- `regions_overlay.png`: ขอบและหมายเลขเฉพาะตรวจงาน ห้ามนำเข้าเกม
- seeds/raw/prompts: หลักฐานที่ใช้จริง; `validation.json` และ `SHA256SUMS`: ขนาด decode และ hash

ต้องมี Python 3, Pillow, numpy และ Shapely (`python -m pip install Pillow numpy shapely`) แล้วรัน `python build_handoff.py` จากที่ใดก็ได้ สคริปต์เขียนเฉพาะในโฟลเดอร์นี้ ไม่เชื่อมต่อ network การสร้าง seeds/layout จาก composition ใช้ Lanczos ไปที่2160×6000 วาง region_ch1 ที่120,3800 ขนาด864×1872 แล้ว crop ท่อนที่y=0,1800,3600 สูง2400; เก็บ layout ที่ใช้จริงไว้ครบ

validation.json บันทึก hash ทุก payload ยกเว้นตัวมันเองและ SHA256SUMS เพื่อหลีกเลี่ยงวงจร hash; SHA256SUMS ครอบคลุมทุกไฟล์รวม validation.json ยกเว้นตัว manifest เอง หลัง commit/push ใช้ `git fetch origin art/art-world-map-003` และ `python verify_remote.py FETCH_HEAD` ตรวจ blob จาก git ของสาขาที่ fetch กลับมา ทุก hash/ทุกภาพรวม seeds และ raw ต้อง decode ได้ และตรวจ hash ของ manifest เทียบสำเนาในเครื่องด้วย
