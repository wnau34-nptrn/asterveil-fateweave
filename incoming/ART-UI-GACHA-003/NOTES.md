## จุดยึดและจังหวะที่เสนอ

- แต่ละเฟรมเป็น PNG straight RGBA ใช้ normal blend ขอบใสอย่างน้อย 12px ค่า `pivot` ใน [layers.json](layers.json) เป็นพิกัดบน canvas จุดศูนย์กลางผลึกบน key art 853×1844 อยู่ที่ `[431,683]` และจุดฐานแท่นอยู่ที่ `[426,1187]`
- Idle และ Charge ยึดกลางผลึกที่ `[197,313]` บนจอทดสอบ 390×844 เสาแสงและ Ten Burst ใช้ผลึกเป็น anchor อ้างอิงแล้วบวก offset ไปฐานแท่น `[195,543]` ด้วย pivot ล่างกลาง `[256,1024]` ตำแหน่งปลายด้ายทั้งสิบเก็บตามภาพพีคจากซ้ายไปขวา ลำดับเปิดผลให้มาจากรายการผลจริง
- Reveal ยึดกลางกรอบที่ `[195,347]` บนจอทดสอบ ใช้ `frames/mask.png` กับการ์ดทั้งสอง และ `frames/mask-shard.png` กับเศษ พื้นที่สีขาวของมาสก์คือช่องแสดง portrait วาง portrait หลังกรอบและวาง VFX หลังรางวัล
- แนะนำสุ่มครั้งเดียวประมาณ 2.345 วินาทีสำหรับตัวเต็ม หรือ 2.115 วินาทีสำหรับเศษ เริ่มนับเมื่อออกจาก idle ที่วนเฟรมละ 220ms สำหรับสุ่มสิบให้เล่น Ten Burst ก่อน แล้วใช้จังหวะเปิดแบบย่อใน `ten_short_suggested_ms` ปุ่มข้ามตัดไปแสดงผลที่ยืนยันแล้วทันที
- แอนิเมชันแบ่งด้วยชนิดผลสองแบบตามโจทย์ การ์ดใหม่ใช้เฉพาะสถานะได้รับตัวครั้งแรก ใช้สถานะจากผล server สำหรับชนิดผลและจำนวนเศษ

## ภาพต้นฉบับและการปรับ

[Prompts](prompts.json) เก็บคำสั่งที่ใช้จริงและลำดับแนบภาพทั้งห้าจาก PR #212 ทุกครั้ง [Source](source/) เก็บ 17 PNG ดิบครบทุกคำสั่ง สองแบบแรกของ Ten Burst และ Charge R2 วาดตัวแท่นติดมา จึงใช้แถวที่สร้างใหม่ในชั้นส่งมอบ ภาพจำลองใช้ key art เดิมลดขนาดและ crop portrait จาก `public/assets/art/portraits_mercs.webp` (SHA-256 `ac81630729a1c302fe508d4ce0b6154b4e88cd390ac3ccbd09666ac1f2f2cb25`) โดยใช้เฟรม 6, 1 และ 2 สำหรับคอริน มิร่า และโทมะ ตาม `actorArt` ในเกม

สคริปต์ตัดแถวตามช่อง ใช้ scale ร่วมต่อชุด จัดตำแหน่งตามจุดยึด และล้างพิกเซล alpha ต่ำ ใน Idle ใช้วงเต้นแสงจากเฟรมดิบทั้งสี่เป็นชั้นคงที่และจัดประกายให้เดินรอบวงทีละหนึ่งในสี่รอบ รวมช่วง 4 → 1 ใน Ten Burst เอียงวงแหวนเล็กน้อยและบันทึกพิกัดปลายด้ายจากแถวที่เห็นสิบเส้น ใน Reveal เศษทำให้ขอบเศษเล็กที่ชนขอบบนภาพดิบจางก่อนย่อ และทุก Reveal กันพื้นที่ใบหน้าจากชั้นเอฟเฟกต์โดยตรง

## ตรวจรับและขนาดดาวน์โหลด

- ตรวจ decode, ขนาด, alpha, ระยะขอบ, SHA-256, ช่อง portrait ทั้งสาม, พื้นที่หน้า `[149,288,241,385]` และพื้นที่ปุ่มตั้งแต่ y=590 บนภาพจำลอง 390×844 ทุกจังหวะ รวม R2 ตรวจปลายด้ายพีคสิบจุดและตำแหน่งประกาย idle สี่เฟส
- ตรวจภาพที่ขนาดจริงบนพื้นกรมท่าและ key art ไอคอนต่างกันที่ 24px การ์ดตัวเต็มทรงตั้งกับเศษทรงทแยงแยกได้ และกลีบตัวเต็มกับเกล็ดเศษแยกได้ใน grayscale ภาพส่งมอบใช้ตัวภาพและจุดประกายโดยไม่มีอักษร ตัวเลข หรือเครื่องหมายระดับความหายาก
- ชุด R1 รวม PNG 3,377,163 ไบต์ ประเมิน lossless WebP ก่อนจัด atlas ที่ 2,744,568 ไบต์ รวม R1+R2 ทุกชิ้นประมาณ 3,990,320 ไบต์ โหลดแบบที่เจ้าของเลือกต่อท่าเพียงแบบเดียว หากใช้ PNG และต้องย่อต่อ ให้เริ่มด้วย trim ขอบใสพร้อมเก็บ offset และวัดพีคของ `thread-pillar`, `reveal-character` และ `loom-charge` ก่อนพิจารณาย่อเฟรมหรือใช้จังหวะ settle ร่วมกับ fade
- เจ้าของยังต้องเลือกภาพและอนุมัติ motion จากคลิปจริง 390px ผลการตรวจในแพ็กนี้อ้างอิงภาพจำลองตาม anchor และ width ที่เสนอ

## สร้างซ้ำและตรวจจาก Git

ติดตั้ง Pillow และ NumPy ตาม [requirements.txt](requirements.txt) แล้วรันจากราก repository

```sh
python3 -I incoming/ART-UI-GACHA-003/build_handoff.py
python3 -I incoming/ART-UI-GACHA-003/build_handoff.py --verify
git fetch origin art/art-ui-gacha-003
python3 -I incoming/ART-UI-GACHA-003/build_handoff.py --git-ref FETCH_HEAD
```

การ rebuild ใช้ไฟล์ในแพ็กได้โดยตรง [validation.json](validation.json) บันทึก SHA-256 ของทุกไฟล์ในแพ็ก โดยเทียบ manifest เองแยกจากรายการ hash พร้อมตรวจ inventory และ decode PNG จาก Git blob หลัง fetch
