## 1. เพิ่ม Lv อุปกรณ์

ปัญหาที่ประเมิน: ข้อความปลดเพดานยาวอยู่รวมกับเงื่อนไขคืนทุน ทำให้เทียบผลและเห็นขั้นถัดไปช้า แยก badge “เพดานปลดล็อก Lv N” และลิงก์ “วิธีปลดเพดานถัดไป” ออกจากตารางผล

ลำดับหน้าที่เสนอ: ชิ้น/ผู้สวม → Lv ปัจจุบัน→ถัดไป → เพดาน → ผลต่อผู้สวม → ค่าที่คงเดิม → ค่าใช้จ่าย → ตรวจรายการ

เพิ่มทีละ 1 Lv ตาม UI ปัจจุบัน ไม่เสนอ slider ข้ามหลาย Lv เมื่อถึงเพดานแสดงเหตุผลและขั้นปลดที่มีอยู่จริง ไม่พาผู้เล่นไปกดซ้ำทั้งที่ไม่เปลี่ยนอะไร สี/เซ็ต/คุณภาพ/คุณสมบัติ/+ คงเดิม ค่าสถานะจาก preview เดิมไม่ใช้สูตรใหม่ใน UI

ตัวอย่างภาพ: Lv6→7 และเพดานปลด Lv9; ใช้แร่ `4×7=28` และฝุ่น1 จากแร่120/ฝุ่น48 เหลือ92/47 ทุนเพิ่ม Lv บันทึกไว้คืนตามกฎเดิม ไม่ใช้ Lvค่ายเป็นเพดานอัตโนมัติ

## 2. เลื่อนสีอุปกรณ์

ต้องแยกการเลือกวัตถุดิบจากการอ่านผลสุ่ม หน้าซ้ายบนเป็นชิ้นหลักคงอยู่ รายการด้านล่างคือชิ้นที่ถูกใช้หมด มีสถานะ “เลือกแล้ว N/จำนวนที่ต้องใช้จริง” คัดกรองช่องและสีเดียวกัน แสดง owner/lock/UID และเหตุผลที่ใช้ไม่ได้

กฎปัจจุบันใช้ชิ้นหลัก1+วัตถุดิบ2 (`fuseCount=3`) วัตถุดิบอยู่ในคลัง ไม่ใช่ของสวม/ล็อก/บอส จำนวนนี้ต้องอ่านจาก config ตอน implement ไม่ hardcode ตามภาพ

`fuseMaterials` แนะนำเฉพาะของไม่ลงทุนและไม่มี transferSlot แต่ `fuseReason` อาจรับของลงทุนได้เมื่อเลือกเอง จึงห้ามเขียนว่าของลงทุนทุกชิ้นใช้ไม่ได้ ให้ติดป้าย “เคยลงทุน” และแสดงทุนคืน/คุณสมบัติที่จะเสียก่อนยืนยัน ไม่ผ่อนกฎของที่ core ปฏิเสธ

ชิ้นหลักรักษาอาชีพ Lv + เซ็ต คุณภาพ คุณสมบัติเดิมและทุนเดิม เพิ่มสีหนึ่งขั้น คุณสมบัติใหม่/พลังตำนานที่เพิ่มเป็นผลสุ่ม ห้ามวาดผลใหม่เหมือนรับประกัน ให้แยก “สิ่งที่คงเดิม” กับ “ทราบหลังยืนยัน” ไม่สัญญาว่าค่าใหม่เหมาะกว่าทุกบิลด์

ผลการคืน: คืนเฉพาะทุนพัฒนาของวัตถุดิบ ไม่ใช่มูลค่ารีไซเคิลพื้นฐาน และตรวจเพดานทรัพยากร การเลือกแนะนำไม่ยืนยันแทนผู้เล่นและไม่ทำลายของทันที

## 3. สุ่มคุณสมบัติหนึ่งช่อง

ชื่อคำสั่ง “สุ่มคุณสมบัติ” ชัดกว่า “ปรับค่า” ผู้เล่นเลือกแถวคุณสมบัติที่เปลี่ยนได้หนึ่งช่อง ส่วนอื่นระบุ “คงเดิม” เปิดอ่าน pool ของชนิดที่มีโอกาสออกได้โดยไม่แต่งเปอร์เซ็นต์อัตราออกที่ไม่มีในข้อมูล

สุ่มชนิดใหม่ที่ไม่ซ้ำคุณสมบัติอื่น และคุณภาพ80–120% ตาม config จึงอาจไม่ตรงบิลด์หรือคุณภาพต่ำกว่าเดิม แม้เป็นชนิดใหม่ ต้องแจ้ง “ทราบผลหลังยืนยัน” ไม่มีตัวเลือกเก็บผลเดิม/ยกเลิกผลหลังสุ่ม เพราะระบบนี้ไม่มี

ค่าบริการปัจจุบันตรา1 เหลือ2เมื่อมี3 ค่าบริการไม่คืนเมื่อรีไซเคิล สถานะไม่มีช่อง/ไม่มีชนิดใน pool/ตราไม่พอต้องมีข้อความเฉพาะ หลังสุ่มแสดงผลจริงและค่าใช้จ่ายครั้งนั้น ไม่สุ่มซ้ำจากปุ่มค้าง/animation callback การสุ่มช่องที่ผูก transferSlot ยังใช้ได้ตามกฎและไม่ย้ายช่องที่ผูก

## 4. ถ่ายโอนคุณสมบัติ

จัดเป็นสามขั้นในหน้าคำสั่งเดียว: เลือกช่องชิ้นรับ → เลือกชิ้นต้นทางในคลัง → เลือกคุณสมบัติของต้นทาง จากนั้นแสดงผลเทียบเฉพาะช่องและผลต่อผู้สวม

ครั้งแรกผูกช่องชิ้นรับถาวรครั้งต่อไปใช้ได้เฉพาะช่องนั้น จึงต้องมีข้อความนี้ก่อนเข้าหน้าตรวจรายการ ไม่ซ่อนไว้ใน tooltip อย่างเดียว ใช้ไอคอน “ช่องผูกแล้ว” ต่างจาก “ล็อกอุปกรณ์” ซึ่งเป็นคนละสถานะ

ต้นทางต้องเป็นช่องอุปกรณ์เดียวกัน อาวุธต้องอาชีพเดียวกัน ไม่ใช่ตัวเอง/ของบอส/ของล็อก/ของสวม ต้องไม่ทำคุณสมบัติซ้ำช่องอื่นหรือค่าเดิมตาม `transferCandidate` อย่าเพิ่มเงื่อนไขสีเดียวกันเอง เพราะไม่ได้บังคับในกฎถ่ายโอน

คัดลอกชนิดและคุณภาพ ไม่คัดลอก Lv ค่าตัวเลขจากต้นทาง เซ็ต สี คุณภาพหลัก หรือพลังตำนาน ค่าใหม่คำนวณด้วย Lv ของชิ้นรับ ชิ้นต้นทางหายทั้งชิ้น ไม่ใช่สลับหรือคืนอุปกรณ์ต้นทางหลังถ่ายโอน

แยก ledger 3 ส่วน: ค่าบริการจ่ายล่วงหน้า (แร่12/ฝุ่น3/ตรา1) → คืนทุนตีบวก/เพิ่ม Lv ของต้นทางตามจริง → ยอดคงเหลือหลังทำ ต้องมีค่าบริการครบก่อนรับทุนคืน ห้ามแสดงยอดสุทธิเป็นราคาที่ใช้ตรวจว่าจ่ายไหว ค่าบริการไม่คืนเมื่อรีไซเคิล

## 5. สร้างอาวุธ

เลือกอาชีพจากสมาชิกที่มีในค่าย รวมคนไม่ได้พามา แล้วเลือก Lv ไม่เกินเพดานช่าง แสดง blueprint คงที่: rarity1/สีดี คุณภาพ100% ไม่มีเซ็ต ไม่สุ่ม ไม่แอบสุ่มอาวุธดีกว่าจากภาพ

เทียบกับอาวุธปัจจุบันได้ แต่ต้องบอกว่าสร้างแล้วเข้าคลัง1ชิ้น ไม่สวมให้อัตโนมัติ ตรวจของรอรับ/คลังเต็มก่อนยืนยันและมีทางไปจัดคลังพร้อมกลับบริบทเดิม

ตัวอย่าง Lv3: ราคาแร่ `18+6×(3−1)=30` ฝุ่น `4+(3−1)=6` จาก120/48 เหลือ90/42 ค่าผลิตไม่ใช่ทุนพัฒนาที่คืน100%; รีไซเคิลคืนเพียงมูลค่าพื้นฐานและทุนตีบวก/เพิ่ม Lv ที่จ่ายภายหลังจริง การสร้างไม่นับรับประกันฟาร์ม

## 6. รีไซเคิล

หน้าเฉพาะเตือนชิ้นที่จะหาย ชื่อ UID Lv + และพลัง/เซ็ตที่เสีย แจกแจงมูลค่าพื้นฐาน, คืนทุนตีบวก, คืนทุนเพิ่ม Lv, รวมที่จะได้รับ และยอดคงเหลือ ใช้ `salvageValue`/investment เดิม ไม่รวมทุนคืนเป็นบรรทัดเดียวที่ทำให้ผู้เล่นเข้าใจว่าได้อุปกรณ์กลับมา

ของล็อกต้องปลดเอง ของสวมต้องถอดเอง ไม่ปลด/ถอดอัตโนมัติเพื่อให้คำสั่งผ่าน กรณีของบอสที่ย่อยได้ตามระบบต้องเตือนพลังบอสหาย ไม่เหมาว่าของบอสห้ามรีไซเคิลเพียงเพราะห้ามใช้เป็น donor

ไม่คืนของที่เคยใช้หลอม ค่าบริการสุ่ม/ถ่ายโอนหรือค่าผลิตอาวุธ ปุ่มแรก “ตรวจรายการรีไซเคิล” หน้าตรวจระบุชิ้นและยอดอีกครั้งก่อน “ยืนยันทำลายอุปกรณ์” ไม่เพิ่ม bulk selection ที่เปลี่ยนขอบเขตจาก UI ปัจจุบัน

## 7. หลอมแร่เป็นฝุ่น

ชื่อหน้าให้บอกทิศทางการแลก “หลอมแร่เป็นฝุ่น” ไม่ใช้เพียง “หลอม” ซึ่งสับสนกับเลื่อนสี อัตราปัจจุบันแร่8→ฝุ่น1 จำนวนใน UI เลือก1หรือ5 อ่าน config ตอนนำเข้า ไม่สร้าง slider/แลกย้อนกลับเอง

แสดง ใช้/ได้รับ, ยอดก่อน→หลัง และโควตาที่เหลือในรอบนี้พร้อมกัน ตัวอย่างหลอม5 ใช้แร่40 จากแร่120/ฝุ่น48 เหลือ80/53; โควตา30 ใช้ไป10 หลังทำใช้ไป15 เหลือ15 ต้องยืนยันจำนวนเดียวกับที่ review ไว้ ห้าม re-read จำนวนใหม่ระหว่างยืนยันจนผิดยอด

กรณีโควตาเหลือไม่ถึง5 ให้ปิดตัวเลือก5พร้อมเหตุผล แต่ยังเลือก1ได้เมื่อพอ กรณีใช้ครบระบุวิธีเริ่มรอบใหม่ตามการกลับค่ายจริง ไม่ใช้คำว่าโควตารายวันหรือผูกกับการซื้อ

## ข้อกำหนดร่วมและการส่งต่อ

- ทุกหน้าใช้ compact item header พร้อม owner/lock, เปลี่ยนชิ้นโดยคง operation ที่เปิด, เส้นทางกลับไปตัวละครพร้อม hero/UID/tab/filter/scroll/focus
- ค่าสถานะทุกภาพใช้ “เดิม→ใหม่” ไม่แต่งตัวเลขผลจริง หน้าที่สุ่มห้ามใช้ preview คาดเดาผล outcome ส่วนหน้าผลแน่นอนใช้ preview จาก core เดิม
- ข้อความ placeholder ในการ์ด “คุณสมบัติเดิม” ของภาพ05ต้องแทนด้วย affix ปัจจุบันจริงเสมอ โดยเฉพาะคำ “ว่างอยู่” ที่ยังหลงเหลือในการ์ดก่อน–หลังไม่ใช่กฎว่าถ่ายโอนเข้าช่องว่างได้; transferCandidate ต้องมี affix เดิมในช่องนั้น เช่นเดียวกับไอคอนคืนทุนในภาพ06ต้องใช้แร่/ฝุ่นตามรายการเงินจริง ไม่เพิ่มสกุลเงินจากภาพประกอบ
- ข้อความราคา/คืนทุนต้องมีชื่อและหน่วยครบ เลขติดลบหรือผลสุ่มที่ยังไม่ทราบไม่ใช้สีเขียวทำให้เหมือนรับประกันว่าคุ้มกว่าเดิม
- กลไก review เดิมต้อง invalidate เมื่อ profile/ชิ้น/ช่อง/จำนวน/วัตถุดิบเปลี่ยน ยืนยันได้ครั้งเดียวจาก state ล่าสุด หากเปลี่ยนชิ้นระหว่างกลับจากจัดคลังให้ตรวจใหม่
- ปุ่ม≥44px, bodyเลื่อนหนึ่งพื้นที่, dockไม่บังข้อมูล, keyboard/focus และ reduced-motion เดิม ไม่เพิ่มชั้น modal ซ้อนโดยไม่จำเป็น
- หน้าระบบยังไม่ปลดแสดงเงื่อนไขจริงจาก featureOpen/config ไม่ใช้บทที่เดาจากภาพ; UI นี้ไม่เปิดฟีเจอร์ก่อนกฎอนุญาต
