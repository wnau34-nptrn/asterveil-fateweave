## โครงสร้างที่แนะนำ

### โรงตีเหล็ก — แยกคำสั่งตามงาน

หน้าแรกเป็นรายการคำสั่งพร้อมคำอธิบายสั้น ใช้การ์ดแตะสูงอย่างน้อย 64px เรียง “ตีบวก”, “เพิ่ม Lv อุปกรณ์”, “เลื่อนสีอุปกรณ์”, “สุ่มคุณสมบัติ”, “ถ่ายโอนคุณสมบัติ”, “สร้างอาวุธ”, “จัดวัตถุดิบ” ส่วนจัดวัตถุดิบเปิดเลือก “รีไซเคิล” หรือ “หลอมแร่” คำสั่งที่ยังไม่เปิดต้องมีเงื่อนไขอ่านได้ ไม่ใช้กุญแจอย่างเดียว

เมื่อเข้าคำสั่ง ให้แสดงชื่อคำสั่งเป็นหัวหน้า ไม่มีแท็บหลัก 4 หมวดกับปุ่มวิธีพัฒนา 5 แบบซ้อนกัน ผู้เล่นเปลี่ยนงานผ่าน “เปลี่ยนวิธีพัฒนา” ซึ่งเปิดรายการคำสั่งและเก็บชิ้นเดิมเฉพาะกรณีที่ใช้ได้

เข้าจากอุปกรณ์ที่เลือกแล้ว: ข้ามหน้าเลือกชิ้น เก็บ UID กับเจ้าของ เข้าจาก NPC: เลือกงาน → เลือกชิ้น → ตรวจผล ไม่ถามเลือกชิ้นซ้ำเมื่อเปลี่ยนวิธี

หน้าตีบวก: บัตรชิ้นกะทัดรัด → +ปัจจุบัน/ถัดไป → ผลต่อผู้สวม → ค่าใช้จ่าย/ยอดมี/ยอดคงเหลือ → ปุ่ม “ตรวจรายการตีบวก +N” หน้าตรวจใช้ตำแหน่งปุ่มเดิม แต่เปลี่ยนข้อความเป็น “ยืนยันตีบวก +N” และมี “กลับไปแก้ไข” หลังสำเร็จคงชิ้นเดิม แสดงผลจริงและให้ตรวจรายการขั้นถัดไปได้ ไม่สั่งซ้ำอัตโนมัติ

ตีบวกสำเร็จแน่นอนและครั้งละ 1 ขั้น เพิ่ม Lv ครั้งละ 1 Lv ตามระบบเดิม ไม่มีเปอร์เซ็นต์ล้มเหลว ไม่มีสไลเดอร์เพิ่มหลายขั้นในข้อเสนอนี้

หลอมสี/ถ่ายโอน/รีไซเคิล: รายการชิ้นที่จะหายต้องเห็นชื่อ, UID, Lv, +, lock/owner และรูป แยก “ชิ้นหลักคงอยู่” จาก “ชิ้นที่ใช้หมด” แสดงเงินจ่ายล่วงหน้ากับทุนที่คืนคนละบรรทัด ห้ามเอาทุนคืนไปทำให้ปุ่มดูว่าจ่ายไหวล่วงหน้าเมื่อกฎบอกว่าไม่พอ ผลสุ่มระบุ “ทราบหลังยืนยัน” โดยไม่วาดผลรับประกัน

### ตัวละคร — รวมงานสกิล และเพิ่มทางเข้าพัฒนา

แท็บหลักเสนอ 4 แท็บ: “ภาพรวม / อุปกรณ์ / สกิล / พัฒนา” แท็บความถนัดเดิมย้ายเป็น “ผังสกิล” ภายใต้สกิล ไม่ลบความสามารถเดิม

สกิลมี segmented control 3 ส่วน: “ติดตั้ง / เพิ่ม Lv / ผังสกิล” ติดตั้งเห็นจำนวนช่องที่ใช้จริงและกฎอย่างน้อย 1 สกิล เพิ่ม Lv เลือก 1 สกิลแล้วเห็นผล/ค่าใช้จ่ายของสกิลนั้น ส่วนอื่นเป็นแถวสั้นพับได้ ผังสกิลแสดงโครงเดิมและแผงรายละเอียดโหนดที่เลือก ปุ่มจากสกิลที่ล็อกพาไปโหนดตรงตัว รักษา selected skill เมื่อเปลี่ยนส่วน

“แลกตำรา” เปิด sheet ในบริบทของสกิล/สายตำราปัจจุบัน กลับมาแล้วยังเลือกสกิลเดิม การ preview ไม่ซื้อ ไม่แลก และไม่บันทึก

แท็บพัฒนาเป็นทางเข้ารวม: เลเวลค่ายร่วม, ดาวรายตัวพร้อมไปเงื่อนไขเพิ่มดาว, ลิงก์พัฒนาสกิล และอุปกรณ์ที่สวมอยู่ ไม่มีปุ่มอัปเลเวลรายตัว ไม่เพิ่มเลื่อนขั้นอาชีพ/ระบบดาวใหม่ตามภาพ คำสั่งเพิ่มดาวต้องใช้ adapter/กฎเดิมและแสดงทรัพยากรจริง

หน้าภาพรวมเก็บค่าสถานะ บทบาท บาดแผล/ความล้าและรายละเอียดที่มีอยู่ หน้าอุปกรณ์คง paper doll 6 ช่อง, ตัวกรอง, เปรียบเทียบและจัดชุดแนะนำ เพิ่มทางเข้าโรงตีเหล็กด้วยชิ้นเดิม ไม่รวมทุกเครื่องมือไว้ในหน้าภาพรวม

## ข้อกำหนดภาพและ interaction

- มือถือออกแบบที่ logical 390×844; กรอบ desktop แนวตั้งกว้างไม่เกิน 480px และสูงไม่เกิน 960px ตามข้อกำหนดเดิม ไม่มีการเปลี่ยนเป็นหน้ากว้างในงานนี้
- ใช้ navy `#08121f`, panel `#14243a`, gold `#f2d596`, cyan `#74d4ef`, mint `#68e5b6`, coral `#ed927f`; หัว Kanit 600 เนื้อหา Noto Sans Thai 400/700 จากไฟล์เกม
- ตัวหนังสือหลัก 14–16px หัว 22px; touch target ≥44px; ชื่อยาวตัดเฉพาะส่วนที่เปิดอ่านเต็มได้ ไม่ตัดค่าใช้จ่ายหรือเหตุผลปิดปุ่ม
- Header + action dock คงที่เฉพาะในกรอบเกม; พื้นที่เนื้อหาเลื่อนหนึ่งจุด มี padding ให้รายการสุดท้ายไม่อยู่ใต้ dock และรองรับ safe area/คีย์บอร์ด
- ยอดค่าใช้จ่ายใช้ “ใช้ / มี / คงเหลือ” พร้อมชื่อทรัพยากร; ค่าลด/เพิ่มมีเครื่องหมายและคำ ไม่อาศัยสีอย่างเดียว
- ผลต่อผู้สวมกับผลตัวอุปกรณ์ต้องระบุหัวข้อ; ค่าสกิลคือค่าพื้นฐานก่อนเงื่อนไขจริง ไม่ตั้งชื่อเป็นดาเมจรับประกัน
- ปุ่ม back คืน context; Escape ปิดชั้นบนสุด; dialog กัก focus และปิด input ฉากด้านหลัง; focus กลับปุ่มต้นทาง
- feedback หลังทำ 180–280ms, ไม่บังจำนวนคงเหลือ; reduced-motion ใช้ข้อความ/สีโดยไม่สั่นหรือกระพริบแรง

## แผนส่งต่อและเกณฑ์ตรวจรับ

1. โรงตีเหล็กและปุ่มกลับ: แยก launcher/operation view ใน `forge-workbench.ts` และ host เดิม จัด dock และพับรายละเอียด รักษา review guard กับ preview จาก core เดิม
2. สกิล: ปรับ presentation ของ `character-panel.ts`/`character-view.ts` ให้รวมติดตั้ง เพิ่ม Lv ผังสกิล; ไม่เปลี่ยนวิธีคิดแต้ม กฎสกิลหรือ save
3. พัฒนาตัวละคร: เพิ่มทางเข้าไปดาว/เลเวลค่าย/อุปกรณ์ตาม capability ที่เปิดจริง; ถ้ากฎใน P04 ยังไม่เข้า ให้ใช้คำอธิบาย runtime ปัจจุบัน
4. QA focused ที่ 390×844, 390×650, กรอบ desktop 480px: ไม่มี horizontal overflow, dock ไม่บังข้อมูล, ทุกงานทำด้วย keyboard ได้, กลับจากโรงตีเหล็กได้บริบทเดิม, preview/cancel ไม่เสียทรัพยากร, confirm ครั้งเดียวไม่ทำซ้ำ, locked/equipped/boss donor ถูกกฎเดิม, สลับแท็บไม่แอบส่งคำสั่ง
5. เป้าหมายใช้งานที่ต้องวัดจริงภายหลัง: จากอุปกรณ์ที่เลือกถึงหน้าตรวจตีบวก ≤2 taps; จากสกิลล็อกถึงโหนดตรงตัว 1 tap; ผู้ทดสอบอธิบายได้ว่า Lv ค่ายร่วมแต่ดาวแยกคน; บันทึกจำนวน taps/การย้อน/จุดที่หาไม่เจอแทนการอ้างว่าดีขึ้นเป็นเปอร์เซ็นต์ล่วงหน้า

ขอบเขตส่งมอบนี้: วิเคราะห์และ concept artwork สำหรับตัดสินใจทำต่อ ยังไม่ได้แก้ runtime, balance, rules หรือ saves; ไม่มีการทดสอบเล่นเกมหรือรับรอง iOS/อุปกรณ์จริง ตัวเลขในภาพใช้สื่อ hierarchy เท่านั้น ให้ implementation ใช้ค่าจาก state/preview เดิม
