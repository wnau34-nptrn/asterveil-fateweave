## 1. สรุปสั้น

- Asterveil มีพื้นฐาน game feel ที่ดีกว่าที่คาด: เปลี่ยนหน้าแบบ fade/settle 320 ms, ปุ่มกดยุบ, ค่ายมี ambient (ไฟ ถ่าน NPC idle), กระโดดบนแผนที่มี squash + ฝุ่น, flash ก่อนเข้าต่อสู้, ต่อสู้มี shake และตัวเลือก “เอฟเฟกต์: ลด” และ **ปิด animation ทั้งหมดเมื่อ OS ตั้ง reduced motion** (วัดได้ 21 → 0)
- ช่องว่างหลักอยู่ที่ **เมนูชั้นใน**: เปลี่ยนตัวละครและเปลี่ยนแท็บ “ไม่มีการเปลี่ยนผ่านเลย”, sheet เปิดมีอนิเมชันแต่ปิดหายทันที, ภาพตัวละครเปลี่ยนรูปแบบระหว่างแท็บ, empty state ไม่บอกทางไปต่อ
- จอเล็ก 360×640 มีปัญหาที่วัดได้ 2 จุด: ป้าย “กระดานเควสต์” ตัดคำไทยเป็น 3 บรรทัดและล้นกรอบ และปุ่มสุ่มกาชาตกขอบจอ
- Sprint 1 ที่แนะนำ (ความเสี่ยงต่ำ ไม่แตะ rules/save/balance): **S1** จอเล็ก 2 จุด · **S2** การเปลี่ยนตัวละคร · **S3** การเปลี่ยนแท็บ + ภาพตัวละครคงที่ · **S4** sheet ปิดแบบมีอนิเมชัน · **S5** empty state ที่มีทางไปต่อ

## 6. Gap และข้อค้นพบตาม Priority

นิยาม: **P0** = ใช้งานผิด/อ่านไม่ได้บน viewport ที่รองรับ · **P1** = ผลต่อความรู้สึกและความเข้าใจสูง ความเสี่ยงต่ำ · **P2** = ปรับเพิ่มหรือต้องวัด/ขออนุมัติก่อน
Effort: S ≤ 0.5 วัน · M 1–2 วัน · L > 2 วัน

### P0-1 ป้าย “กระดานเควสต์” ตัดคำไทยและล้นกรอบที่ 360 px

- **หลักฐาน**: 360×640 ข้อความแตกเป็น “กระ / ตาน / เควสต์” 3 บรรทัด, `#lobby-board` `scrollHeight 75 > clientHeight 62`; ป้ายบอสโลกถูกตัดเป็น “สิทธิ์ 0/5 · เหลื…” (ภาพ `07-camp-360x640.jpg`). ที่ 393 px `64 > 62` (ล้นเล็กน้อย)
- **Reference**: ป้ายทางเข้าระบบอ่านได้เต็มคำ (00–02 s)
- **Impact** สูง (ทางเข้าระบบหลัก) · **Effort** S

### P2-2 Screen shake ใช้ค่าสุ่มต่อเฟรมและไม่มี hit-stop (จาก Game Feel Skill, ไม่ใช่จาก Reference)

- **Impact** ต่ำ–กลาง · **Effort** S (shake) / M (hit-stop) · **ข้อจำกัด**: `CLAUDE.md` ของเกมกำหนดว่า presentation ต้องไม่เปลี่ยน playback timing และต้องให้เจ้าของดูคลิป 390 px ก่อนขยาย effect — hit-stop เปลี่ยน timing จึง **ต้องขออนุมัติแยก**

## 9. คำถามที่ต้องให้เจ้าของตัดสินใจ (ไม่ขวาง Phase 2a)
