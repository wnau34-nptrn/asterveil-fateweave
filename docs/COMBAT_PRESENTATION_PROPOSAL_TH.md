# ข้อเสนอจังหวะ เอฟเฟกต์ และคัตซีนการต่อสู้

วันที่ 21 ตุลาคม 2026 · สถานะ: ข้อเสนอเพื่อพิจารณา ยังไม่พัฒนาหรือเผยแพร่

## ข้อเสนอหลัก

เพิ่มความอลังการด้วยจังหวะที่มีน้ำหนัก: เตรียมท่า → เคลื่อนเข้าหา/ส่งพลัง → ปะทะ → รับแรง → คืนสู่เทิร์นถัดไป แต่ละสกิลต้องมีรูปร่างและเสียงที่สื่อหน้าที่ของมัน และเก็บการกำกับฉากใหญ่ไว้ให้บอสหรือเหตุการณ์สำคัญ

ให้เริ่มจากการประสานจังหวะภาพ/เสียง/HP และการเชื่อมผู้โจมตีกับเป้าหมาย แล้วทำผู้คุมรอยแยกเป็นตัวอย่างคุณภาพ ก่อนขยายทุกอาชีพ ตัวเลขเวลาทั้งหมดด้านล่างเป็นค่าเริ่มต้นสำหรับทดลอง ไม่ใช่ผลการเล่นทดสอบที่พิสูจน์แล้ว

## 1. จังหวะการโจมตีที่เสนอ

ตัวอย่างโจมตีธรรมดา 600 ms:

| เวลา | ภาพ | เสียงและข้อมูล |
|---|---|---|
| 0–90 ms | ย่อ/เอียงตัวเตรียมท่าเล็กน้อย | เสียงเตรียมท่าเบา ๆ; คง HP ก่อนโดน |
| 90–210 ms | พุ่งสั้นพร้อมเส้นฟัน หรือ projectile เดินทางถึงเป้า | เสียงเหวี่ยง/พลังเคลื่อน |
| 210 ms | impact เฉพาะจุดสัมผัส | hit sound, HP, ตัวเลข และ recoil เริ่มตรงกัน |
| 210–250 ms | ค้างท่าปะทะประมาณ 40 ms เฉพาะชั้นภาพ | ไม่หยุด resolver, DOM หรือระบบเซฟ |
| 250–420 ms | เป้าหมายรับแรง ตัวเลขยกตัวขึ้น | เผยผลรองตามลำดับที่เกิดจริง |
| 420–600 ms | กลับท่าเดิม ลดแสง และเตรียมคิวถัดไป | เปิดคำสั่งเมื่อ stage จบจริง |

ไม่จำเป็นต้องพุ่งข้ามสนามทุกครั้ง ใช้เส้นฟัน/พลังที่ต่อถึงเป้าและตำแหน่งปะทะบนลำตัวเพื่อเชื่อมเหตุและผล หลีกเลี่ยงวง impact ที่เกิดตรงพื้นใต้เท้าโดยไม่มีภาพโจมตีมาถึง

ช่วงเวลาที่แนะนำให้ทดลอง:

- โจมตีธรรมดา: 500–650 ms
- บัฟ/ตั้งรับ/ติดตรา: 400–650 ms
- สกิลโจมตีหลัก: 700–950 ms
- ท่าประจำบอส: 1,000–1,400 ms
- ปิดฉากบอส: 1,400–2,000 ms

hit-stop เริ่มทดลองที่ 35–50 ms สำหรับท่าธรรมดาที่เหมาะกับการค้างภาพ และ 60–90 ms สำหรับท่าหนัก ไม่เพิ่มเวลาค้างทุก event ในการโจมตีหลายเป้า; การหลบหรือโดนโล่รับทั้งหมดใช้ feedback ของตนเอง

## 2. ภาษาภาพประจำสกิล

| กลุ่ม/ตัวอย่างที่มีจริง | ภาพที่เสนอ | จุดเน้น |
|---|---|---|
| โจมตีกายภาพ | โค้งฟันสั้น / แทงเป็นเส้น / impact แตกเป็นสะเก็ด | แยกตามอาวุธและอาชีพ แม้ใช้ action `attack` ร่วมกัน |
| Knight: กระแทกโล่ | โล่สะบัด + คลื่นอัดสั้น + เป้าหมายเสียหลัก | เมื่อ interrupt สำเร็จ แสดงสัญลักษณ์ท่าศัตรูแตกและคำว่า “ขัดจังหวะ” |
| Duelist: ติดตรา → ฟันเจาะจุด | ตราล็อกเป้าชัด; เมื่อเข้าเงื่อนไข ตราสว่างก่อนเส้นฟันพุ่งผ่าน | ขยายความสำเร็จจากการวางแผน; ไม่เขียน CRITICAL ถ้า resolver ไม่มีคริติคอล |
| Mage: ศรเวท | จุดรวมแสง → ลูกพลังฟ้า/ม่วง → ระเบิดเฉพาะเป้า | ผู้เล่นตามเส้นทางจากผู้ร่ายถึงผู้รับได้ |
| Mage: โล่เวท | แผ่นโล่หกเหลี่ยมประกอบรอบตัว | ตอนรับดาเมจให้โล่รับแรงก่อน; โล่แตกเฉพาะเมื่อ barrier หมดจริง |
| Priest: รักษา/พรฟื้นฟู | แสงมิ้นต์ไหลขึ้น พร้อมประกายอุ่น | แยกการฟื้น HP กับการให้โล่; ไม่ใช้แรงสั่นจากการโจมตี |
| Spear / Archer | แทงแคบมีทิศ / ลูกศรและเส้นวิถี | ห่าธนูต้องมีเป้าจริงตาม events ไม่สร้างเป้าหรือ hit เพิ่ม |
| Alchemist / Scout | ขวดโค้งแตกเป็นละออง / afterimage สั้น | แสดงกรด หลบ และเงื่อนไข Backstab ให้ตรงเหตุการณ์ |
| Hammer Warden / Bard / Mage (ตรึงเวท) | คลื่นกระแทกพื้น / เส้นเสียง / อักขระ | ทำให้ support ดูมีพลังด้วยแสงและรูปทรง ไม่ต้องใช้ shake ทุกครั้ง |
| Guard / Counter / Dodge | เส้นคุ้มกันรับแทน / ปะทะแล้วสวน / เงาเลี่ยงออกจากวิถี | สื่อว่าใครช่วยใคร และเหตุใดความเสียหายจึงลดหรือไม่เกิด |

ใช้ฟ้า–ทองกับทีมและม่วงรอยแยกกับศัตรูเป็นฐาน แต่ต้องแยกด้วยรูปทรง/ไอคอน/ข้อความด้วย ไม่พึ่งสีอย่างเดียว

เอฟเฟกต์อุปกรณ์บอสเป็นตราเล็กของผู้สวม เมื่อเกิดพลังจริง: Aegis เป็นโล่ทอง, Focus เป็นเส้นโฟกัสเข้าตรา, Lantern เป็นแสงโคมคุ้มกันเพื่อน แสดงค่าที่เพิ่มจริงตาม event ไม่เขียน “+6” ทุกครั้งเพราะเป็น floor-6 barrier และต้องตรวจแหล่งกำเนิดให้ได้ก่อนแสดงชื่อพลัง จำนวนครั้งต้องตรงกติกาหนึ่งครั้งต่อผู้สวมต่อ resolver round

## 3. คัตซีนผู้คุมรอยแยก

ตัวอย่างนี้ใช้บอสปัจจุบัน `rift-warden` / ผู้คุมรอยแยก ที่ใช้ภาพ Sentinel สีทอง–ม่วง ไม่แทนเป็นวาร์กอธ และไม่เพิ่มบอสใหม่

### เปิดตัวครั้งแรก ประมาณ 3.2 วินาที

| เวลา | การกำกับฉาก |
|---|---|
| 0.0–0.5 s | ฉากแผนที่มืดลง รอยแยกเปิดเป็นเส้นม่วง ลดเสียงพื้นหลังให้ได้ยินแรงสั่นต่ำ |
| 0.5–1.2 s | เผยเงาร่างและแสงตามรอยเกราะ เศษหินลอยเล็กน้อย |
| 1.2–2.2 s | ภาพบอสระยะใกล้เลื่อนคนละชั้นกับฉากหลัง แสดง “ผู้คุมรอยแยก” และฉายาที่ตรวจ lore แล้ว |
| 2.2–2.8 s | บอสลงน้ำหนัก เกิดวงฝุ่นต่ำ เสียงหิน/โลหะ และเปิดเพลงบอสเดิม |
| 2.8–3.2 s | คืนภาพสนามจริง แสดง HP และ intent ก่อนให้เริ่มลำดับต่อสู้ |

ข้อความคำราม/คำพูดเป็นงานเขียนใหม่ที่ต้องตรวจเนื้อเรื่องก่อนใช้ ไม่มีเสียงพากย์ในชุดเริ่มต้น ใช้ข้อความสั้นอ่านทันและไม่บังคับผู้เล่นรีบอ่าน

ใช้ภาพ 2D หลายชั้นที่ควบคุมเวลาได้ ข้ามได้ และปรับเข้ากรอบแนวตั้งได้ ฉากเต็มพื้นที่เกมเกิดเฉพาะก่อนเริ่มการต่อสู้; ระหว่างเลือกคำสั่งคงความชัดของสนามและ HUD

รอบฟาร์มให้ intro สั้น 0.6–0.9 s เป็นค่าเริ่มต้นหลังเคยเห็นฉากเต็ม มีตั้งค่า “ฉากบอส: ครั้งแรก / ทุกครั้ง / แบบย่อ” และปุ่มข้ามตั้งแต่ต้น ข้ามแล้วคืนสู่จุดเริ่มต่อสู้เดียวกัน ต้องทดสอบว่า tap/Enter เดิมไม่หลุดไปเริ่มท่าหรือยืนยันเป้า

### ท่าประจำตัวระหว่างไฟต์

- **Crushing Blow:** เกราะเรืองแสง → เตรียมทุบ → คลื่นทองปะทะเป้าหมายจริง → ฝุ่นและหินกระเด็นต่ำ ท่ากายภาพยังถูก Guard/Bash แทรกแซงตามกติกาเดิม เมื่อถูกขัดจังหวะต้องเปลี่ยนเป็นพลังสะดุด ไม่เล่นท่าทุบสำเร็จ
- **Rift Bolt:** เส้นม่วงรวมตัว → แสงชาร์จสั้น → พลังพุ่งถึงเป้า → โล่เวทหรือ HP รับผลตามจริง ไม่สร้างภาพโดนทั้งทีมจากท่า single-target
- **คัตอินสั้น:** ภาพดวงตา/แกนเกราะ 0.25–0.4 s รวมอยู่ในเวลาท่าประจำตัว ใช้เฉพาะครั้งแรกที่แสดงท่านั้นในไฟต์ หรือปิดในโหมดฟาร์ม ไม่แทรกก่อนโจมตีทุกครั้ง
- **ช่วง HP ต่ำ:** อาจให้รอยเกราะเรืองและฉากมืดขึ้นอย่างนุ่มนวลหนึ่งครั้งเมื่อข้าม 50% เป็นภาพตกแต่ง ห้ามเรียกว่า “คลั่ง” หรือแสดง ATK เพิ่มหากไม่มีกติกานั้นจริง การเพิ่มเฟส/ท่า/ความยากต้องเป็นข้อเสนอระบบต่อสู้อีกงานหนึ่ง

### ปิดฉาก

เมื่อ `down` และ `victory` ยืนยันแล้ว: ค้างภาพโจมตีสุดท้าย 70–90 ms → รอยเกราะแตกและพลังรั่ว → ร่างทรุดหรือสลาย → คืนแสงอุ่น → เปิดรางวัล ใช้เวลาเต็มประมาณ 1.4–2 s และย่อได้ในรอบฟาร์ม

ประกาย legendary แสดงหลังทราบผลดรอปจริงเท่านั้น ต้องไม่สื่อว่าทุกไฟต์ได้ของบอสหรือสุ่มของใหม่ตอนเล่นคัตซีน ไม่เปลี่ยนดรอป พิตี้ หรือการเก็บของเมื่อรีโหลด

### มินิบอสยักษ์หินรอยแยก

ใช้โครง intro เดียวกันแต่สั้น 1.4–1.8 s: เศษหินประกอบร่าง → แกนม่วงติด → ชื่อปรากฏ ท่า Stone Fist เน้นหินปะทะ; Veil Quake ใช้รอยแตก/ฝุ่นตกแต่งโดยไม่สื่อว่าโดนหลายคน หาก resolver ยังมีเป้าหมายเดียว

## 4. ภาพ เสียง และข้อจำกัดจอ

- รักษางานวาดแฟนตาซีเรืองแสงของเกม ใช้เส้นฟันสว่างที่มีแกนคม ขอบนุ่ม ฝุ่น/สะเก็ดพอดี สงวนแฟลชและความสว่างสูงไว้ให้เหตุการณ์สำคัญ
- สั่นเฉพาะชั้นสนามในจังหวะ impact ปกติเริ่มทดลอง 1–2 CSS px ท่าหนัก 3–4 px และคืนศูนย์ทุกครั้ง ไม่ย้ายกรอบเกม แถบสกิล HP/status หรือ DOM hit targets; ไม่ใช้ camera zoom จนพิกัด canvas/DOM คลาดเคลื่อน
- ขณะเลือกเป้าให้ทุกตำแหน่งกลับสู่ฐานเสมอ ช่วงนำเสนอปิดคำสั่งอยู่แล้วแต่ต้องคงการตรวจ input เดิมทุกเส้นทาง
- ถ้ามีหลาย damage/heal/barrier ใน stage เดียว จัดคิวตัวเลขตามลำดับเหตุการณ์ ไม่กองตัวเลขที่จุดเดียว และไม่รวม damage หลัก/สวนกลับ/ดูดเลือดจนเข้าใจผิด
- ใช้เสียง 3 ชั้นเมื่อจำเป็น: เตรียมท่า → เสียงสัมผัส → หางเสียง แบ่ง hit โลหะ/ทิ่ม/หิน/เวท/โล่/ฟื้นฟูให้ต่างกัน จำกัดเสียงซ้อนและ duck เพลงเฉพาะบอส/ปิดฉาก แล้วคืน volume ที่ผู้ใช้ตั้ง
- รองรับระบบลดการเคลื่อนไหวและตัวเลือก “แรงเอฟเฟกต์”; ปิด shake/zoom/afterimage และใช้ข้อความ+ไอคอน/การเปลี่ยนค่าที่อ่านได้ คง feedback สำคัญไว้แม้ไม่เล่นภาพเคลื่อน
- กรอบเกม max-width 480px, named container `game`, ปุ่มข้ามอย่างน้อย 44px, overlay อยู่ในกรอบเดียวกัน ทดสอบ 320×568, 390×844 และเดสก์ท็อป พร้อม orientation gate เดิม

## 5. แผนทำงานที่แนะนำ

| ลำดับ | ขอบเขต | ผลที่ควรได้ | ความซับซ้อนสัมพัทธ์ |
|---|---|---|---|
| P1: น้ำหนักการปะทะ | คิวเวลาแบบ prepare/travel/impact/recover; HP และเสียงตรง impact; melee/projectile; แยก hit/guard/dodge; ความยาว stage ตามแอ็กชัน | ทุกไฟต์รู้สึกกระชับและเห็นสาเหตุของดาเมจ | กลาง–สูง เพราะต้องรักษาการแสดง snapshot และผลรอง |
| P2: บอสตัวอย่าง | intro ผู้คุมรอยแยก, Crushing Blow, Rift Bolt, defeat, ข้าม/ฉากย่อ | บอสมีเอกลักษณ์และเป็นจุดสูงสุดของการเดินทาง | กลาง หลังมี P1 |
| P3: เอกลักษณ์ทีม | เอฟเฟกต์สิบอาชีพ, interrupt/counter/Mark, พลังเครื่องรางและเซ็ตที่พิสูจน์แหล่งกำเนิดได้ | ความสำเร็จจาก build และยุทธวิธีมองเห็นได้ | กลาง–สูง ตามจำนวนสกิล |
| P4: ขัดเกลางานศิลป์/เสียง | ภาพแยกชั้นและ SFX จริง, มินิบอส, ปรับคุณภาพมือถือ | ภาพและเสียงสม่ำเสมอทั้งเกม | ขึ้นกับงาน asset และอุปกรณ์ทดสอบ |

ให้ทำ P1 และ P2 ก่อนขยาย P3 ใช้ภาพเดิมทำต้นแบบเวลาได้ แต่ intro ระยะใกล้ควรมีภาพบอสความละเอียดสูงแยกชั้น เพื่อไม่ขยาย cell 512px จนภาพนิ่ม

ชุด asset เริ่มต้นที่เสนอ: เส้นฟัน/แทง, ประกายกายภาพ, ลูกพลัง/impact เวท, เกราะหกเหลี่ยม, แสงรักษา, ตรา Mark, ฝุ่นหิน, รอยแตก และภาพบอสระยะใกล้พร้อมชั้นแสง ตรวจสิทธิ์และที่มาทุกไฟล์ใหม่ ไม่ดึงโค้ดหรือภาพจาก Rise Beyond

## 6. แนวทางพัฒนาที่รักษาความถูกต้อง

คง pure resolver และการ commit/save ก่อนนำเสนอ ใช้ `TurnStage`/events เป็นข้อมูลจริงและเพิ่มตัวกำกับการนำเสนอที่ยกเลิกได้ ไม่ใส่ damage, RNG หรือ cooldown ใน tween/timer

การเลื่อน HP ไปที่ impact ต้องมี projection ระหว่าง snapshot ก่อน stage กับหลัง stage ที่เปิดเผยเหตุการณ์เป็นลำดับ ใช้ข้อมูลจาก resolver หรือ adapter ที่พิสูจน์ได้ ห้ามให้ UI คำนวณกฎ damage/โล่/ดูดเลือดซ้ำเอง ถ้า event ปัจจุบันไม่พอระบุสาเหตุของพลังอุปกรณ์ ให้เพิ่มข้อมูลสำหรับการนำเสนออย่างชัดเจนและตรวจ replay compatibility ก่อนใช้

Skip/resize/rotation/เปลี่ยนแท็บต้องยกเลิก cue/timer/เสียงที่ค้าง รวม delayed down SFX และคืนค่าทุก layer; ไม่สร้าง command เพิ่มหรือเล่นเสียงค้างเป็นชุดเมื่อกลับมา โหมดปกติ/เร็ว/ลด motion ต้องจบที่ state และรางวัลเดียวกัน

ฉากที่เคยดูแล้วเป็นข้อมูล preference การนำเสนอ แยกจาก progression หากเลือกแนวทางนี้ ไม่ยกระดับ save format เพียงเพื่อ animation; การเพิ่มกฎต่อสู้จริงต้องผ่านงานออกแบบและเวอร์ชันตามปกติ

## 7. เกณฑ์ตรวจรับก่อนเผยแพร่

- บันทึกวิดีโอ/เฟรมต่อเนื่องเพื่อเทียบ impact sound, flash, recoil, damage number และ HP; ตั้งเป้าตรงกันภายในหนึ่งเฟรมภาพปกติ แล้ววัดจริง
- เทียบ replay/outcome/commands/HP/loot ก่อนและหลัง สำหรับความเร็วต่าง ๆ, skip ทุกช่วง, reload ระหว่างฉาก และกลับจาก background
- ตรวจโดนโล่ทั้งหมด/บางส่วน, หลบ, interrupt physical เทียบ energy, Guard รับแทน, counter/reflection/leech, AoE, ฮีลเต็ม HP, ตายระหว่างผลรอง และ boss power ครั้งเดียวต่อ round
- ตรวจข้าม intro/คัตอิน/ปิดฉากแล้วไม่มีการยืนยันเป้าหมายหรือให้รางวัลซ้ำ ไม่มีการทิ้งเสียงหรือค้าง input lock
- จับภาพพร้อมเอฟเฟกต์แรงสุดและทุก status panel ที่จอเล็ก ตรวจข้อความ/ร่าง/ปุ่มไม่ทับกันและพิกัด target ตรงเมื่อคืนสนาม
- วัด frame time บนมือถือจริงก่อนรับรองความลื่น ตั้งเป้า 60fps และมีโหมดลดรายละเอียด ไม่อ้างว่าผ่านจาก screenshot หรือ desktop emulation
- ทดสอบ SFX ที่ได้ยินจริงบน iPhone/Safari; รายงานเก่าเพลงดังแต่ SFX ไม่ดังยังไม่ถือว่าแก้แล้ว
- ให้ผู้เล่นลองฉบับเดิมและฉบับใหม่ทั้งรอบแรกและรอบฟาร์ม ประเมินน้ำหนักการโจมตี ความเข้าใจผล ความรำคาญจากการรอ และเวลาต่อไฟต์ก่อนล็อกค่าจริง

## แหล่งอ้างอิงภายนอก

- [What Features Influence Impact Feel? — Lin et al.](https://faculty.washington.edu/zkwen/articles/lin22features.pdf): วิเคราะห์องค์ประกอบ feedback และเสนอว่า hit-stop ความสอดคล้องของเสียง และการควบคุมกล้องอาจมีบทบาทต่อความรู้สึกปะทะ งานนี้ศึกษา action games; การนำมาปรับกับเกมเทิร์นเบสเป็นข้อเสนอการออกแบบ ไม่ใช่ผลทดลองกับ Fateweave
- [web.dev: How to create high-performance CSS animations](https://web.dev/articles/animations-guide): ใช้ transform/opacity เป็นหลักสำหรับชั้น DOM และตรวจผลต่อ rendering pipeline; ไม่ใช่หลักฐานรับรองประสิทธิภาพของ Phaser VFX
- [W3C: Technique C39 — prefers-reduced-motion](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html): เคารพความต้องการลด motion; Phaser/timeline ต้องอ่าน preference และมี fallback ของตนเองด้วย
