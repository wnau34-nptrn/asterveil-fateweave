### 1.1 Kragmor — ใช้กฎที่มีอยู่ทั้งหมด

ไม่ต้องมีกฎใหม่: `veilguard`, `charge`, `unstoppable`, `all`, เฟส encounter ใหม่ `wb-kragmor` v1

### 1.2 R1 ชาร์จทำลายได้ (Valdrakk)

- `IntentDefinition.breakable?: true` บนท่าชาร์จ · เมื่อเทิร์นชาร์จนั้นถูกยกเลิกด้วยการขัดจังหวะ/ผนึกที่มีอยู่ (`interruptedRound` ตรงกับรอบของมัน) → `EnemyState.staggerRound = รอบที่ท่าถัดไปในวงจะออก` แล้ว `enemyIntent` รอบนั้นคืนท่า `Staggered` (damage 0, `special: 'stagger'`) ที่ preview แสดงเหมือนกัน
- ชาร์จของ Valdrakk เป็นชนิดกายภาพ → Bash ของอัศวินตัดได้ (อาชีพเริ่มต้น) · ชาร์จพลังงานของบอสในอนาคตใช้ Sigil/Bash สะท้อนตามกฎเดิม · steadfast เดิมยังทำงาน (ตัดชาร์จแล้วรอบถัดไปตัดอีกไม่ได้ — แต่ Dive ถูกยกเลิกไปแล้ว)
- ตัดไม่ทันก็ยังมีทางรับ: Ward/Halo/Aegis/ฮีล · Seer เลื่อนชาร์จ+Dive ได้ตามกฎเดิม (ล้าง `staggerRound` เมื่อเลื่อน)
- ไม่มี encounter เดิมใช้ `breakable` → ไม่ต้อง bump encounter อื่น · encounter ใหม่ `wb-valdrakk` v1

### 1.3 R2 ราชสำนัก (Morvane)

- `EnemyDefinition.court?: { percent: 10; by: ['f2','f3','b2'] }` บนบอส: ดาเมจท่าของบอส × (1 + percent × จำนวนใน `by` ที่ยืนอยู่ ณ เทิร์นของบอส) ใช้ก่อน enrage/weaken ในสูตรเดิม · preview/intent แสดงตัวคูณ ("ราชสำนัก +20%")
- `IntentDefinition.summon?: EnemySlot[]` ท่าไม่มีดาเมจ: คืนชีพลูกน้องที่ระบุที่ล้มหรือยังไม่มา (HP เต็ม ล้างสถานะ Mark/กรด/พิษ/คำสาปของตัวนั้น) ตามกติกาสนามเต็ม/แถวเต็มของ `beginPhase` · เข้าคิวรอบถัดไปเหมือนตัวเรียกจากเฟส
- เฟสเดิม `summon` เรียกได้แค่ `reserve` ที่ยังไม่มา ส่วน R2 เรียกตัวที่ล้มกลับได้ด้วย (ใช้เฉพาะ encounter ที่มี `summon` บนท่า) · `wb-morvane` v1
- Seer เบนท่าเรียก (`summon`) ไม่ได้ (เป็นท่าล็อกเหมือน `charge`)

### 1.4 เทสต์ที่ต้องมีตอนสร้าง

ชาร์จถูกตัด → Dive หายทั้ง resolve และ preview; ไม่ตัด → Dive ลง; ตัดไม่ได้เพราะ steadfast; Seer เลื่อน; ราชสำนัก 0/1/2/3 ตัวยืน = ×1.0/1.1/1.2/1.3; เรียกกลับเมื่อสนาม/แถวเต็มข้าม; ตัวที่เรียกกลับไม่มีสถานะเก่า; ทุก encounter เดิม replay ได้ผลเดิม (ไม่ bump); preview = ผลจริง; deterministic replay

ทรัพยากรใหม่หนึ่งชนิดต่อบอส: **เศษคราก์มอร์ / เศษวัลดรัค / เศษมอร์เวน** ใช้ได้อย่างเดียวคือสร้างของของบอสตัวนั้น (ซื้อ/ขาย/แลกไม่ได้) เก็บได้ตัวละ 200

| ส่วน | เงื่อนไข | รางวัล | ออฟไลน์ |

| เข้าร่วม | ทุกครั้งที่นับ (รวมสามตัวไม่เกิน 5) | แร่ 4 ทอง 2 + **เศษบอสตัวนั้น 3** | ได้ |

| ส่วนรวมต่อบอส `<boss>:s-50` / `<boss>:s-100` | HP ส่วนกลางของบอสตัวนั้นลด 50% / 100% และเราเล่นตัวนั้นในรอบ (รับรอบนี้หรือรอบถัดไป) | ทอง 2 + เศษ 2 / เศษ 3 | ไม่ได้ (`offline`) |

- ทุกชิ้น: legendary (rarity 4) Lv11 เท่าเครื่องรางผู้คุม ไม่มี special ทั่วไป (พลังบอสแทน) ไม่มี +/Lv scaling ของพลัง · ใช้ `bossUsedRound` เดิม (หนึ่งพลังบอสต่อผู้สวมต่อรอบ รวมเครื่องรางผู้คุม) · พลังมีเงื่อนไขจึงไม่นับในคะแนนจัดอุปกรณ์อัตโนมัติ (กฎเดิม)

## 3. งบรายสัปดาห์

ตามสูตร P04-06/P11-04 (แร่เทียบ = แร่ + 2×ทอง + 12×เศษกลาง; ฝุ่น/ตำราไม่นับ)

| | เดิม (ผู้คุม) | ใหม่ (สูงสุด: 5 ครั้ง สามบอส ออนไลน์) |
|---|---|---|
| เข้าร่วม 5 ครั้ง | 60 (แร่ 6 ทอง 3) | 40 (แร่ 4 ทอง 2) |
| ส่วนตัว | 36 (เศษกลาง 3) | 24 (เศษกลาง 2) |
| ส่วนรวม | 18 (ทอง 3 + เศษกลาง 1) | 12 (ทอง 2 × สามบอส) |
| **ซื้อขายได้รวม** | **114** | **76** |
| เศษบอส | – | 35 เศษ ≙ 38 แร่เทียบ (≈1.1 ต่อเศษ) |

- **ที่มาของมูลค่าเศษบอส**: ตัดจากรางวัลบอสโลกเอง (114 → 76) ไม่แตะกวาดล้าง/กระดาน · สูตรรวม 409 + 672 + 76 + 38 = **1195 ≤ 1200** เท่าเดิม · คนล็อกอินอย่างเดียวยังไม่ได้อะไรจากบอส
- ของหนึ่งชิ้น ≈ 40 เศษ ≈ 44 แร่เทียบ + ค่าสร้าง 30 แร่/10 ฝุ่น (sink) ซึ่งถูกกว่าการหลอม legendary ทั่วไปมาก แต่จ่ายได้ช้าสุดแค่ ~1.6 สัปดาห์ต่อชิ้นจากเพดานเศษต่อสัปดาห์ — การจำกัดอยู่ที่เวลา ไม่ใช่มูลค่าแร่
- เศษกลางจากบอสลด 3 → 2 ต่อสัปดาห์ (OD-17 รวม 10/สัปดาห์ จากกระดานไม่เปลี่ยน) · ทองบอส 15 → 12–16 (ขึ้นกับเล่นกี่ตัว)

## 5. Server

- **DO `world-boss` ตัวเดียว สามแถบ** (load probe P11-04 ~0.1 ms/hit, Cloudflare staging P12 ผ่าน; สามบอสไม่เพิ่มจำนวน hit เพราะสิทธิ์รวมยัง 5) · SQLite ใน DO:
  - `bars (week, boss, hp, left_hp, attempts, opened, PRIMARY KEY(week, boss))` — แทน `weeks`; ย้ายแถวเดิมเป็น `boss='warden'` ตอน DO เปิดครั้งแรก (`ALTER`/copy ใน `blockConcurrencyWhile` ครั้งเดียว)
  - `hits` เพิ่มคอลัมน์ `boss` (แถวเก่า = `warden`) · id คงรูป `<account>:w<week>:a<n>` (เลขครั้งไม่ซ้ำข้ามสามตัวในรอบ) → retry/outbox เดิมใช้ได้
- **HP ส่วนกลางต่อบอส** = ครั้งที่จบแล้ว**บนบอสตัวนั้น**ในสัปดาห์ก่อน × 400 ภายใน [1500, 5,000,000] (เปลี่ยนจาก "บัญชี × 2500" เพราะผู้เล่นแบ่งสิทธิ์ไปสามตัว; นับครั้งทำให้ตัวที่คนชอบได้ HP มากขึ้นเอง) · สัปดาห์แรกของสามบอส: hit ผู้คุมของสัปดาห์ก่อน ÷ 3 ต่อตัว · คงไม่เพิ่มกลางสัปดาห์ ไม่โอน overkill
- **ledger receipt**: `wb:w<W>:a<n>` (payload มี `boss`), `wb:w<W>:p-2`, `wb:w<W>:p-4`, `wb:w<W>:<boss>:s-50`, `wb:w<W>:<boss>:s-100` · ของเก่า `wb:w<W>:s-50` คงความหมายเดิม · การสร้างของ (`craftBossItem`) เป็นคำสั่งเกมปกติ (ใช้จ่าย ไม่ใช่รางวัล) ไม่มี receipt แยก
