# ตรวจความสอดคล้องของสกิลและค่าสถานะ — 2026-10-24

เจ้าของถามว่ามีจุดไม่สมเหตุผลอื่นคล้ายดาเมจเวทอิง stat ผิดอีกหรือไม่ ตรวจจาก game branch หลัง PR #65 และทดสอบตัวอย่างด้วย resolver โดยไม่แก้เกม ขอบเขตรอบนี้คือสกิล ค่าสถานะ อัปเลเวล และเงื่อนไขเลือกเป้าหมาย ไม่ใช่การรับรองว่าตรวจทุกระบบครบแล้ว

## แสดงผลผิดจริง

1. `src/ui/character-metrics.ts:50` ใช้ fallback ว่า “ดาเมจพื้นฐานต่อเป้าหมาย / อิงพลังโจมตี” กับท่าที่มี power แต่ไม่ได้จัดเป็นเวท เช่น halo, bless, fury, revive, stonearmor ทั้งที่เป็นเปอร์เซ็นต์ป้องกัน บัฟ หรือชุบชีวิต สูตรจริงไม่ได้รับ Attack bonus แบบข้อความที่แสดง จึงทำให้ผู้เล่นเลือกอุปกรณ์ผิดได้ ควรแสดงชนิดค่า หน่วย และ scaling แยกตามผลของสกิล
2. `src/ui/character-metrics.ts:44` อ่าน base power ของ bulwark โดยตรงแทน skillPower ทดสอบ Knight ไม่มี talent และ bulwark Lv3: resolver ลดดาเมจ 64% แต่ summary metric แสดง 60% ควรใช้ค่าหลังเลเวล/โหนดจาก helper เดียวกับ resolver

## กติกาและการป้องกันการกดที่ควรทบทวน

3. Aegis ยังเลือกใช้ได้เมื่อทุกคนมีโล่มากกว่าหรือเท่าค่าที่จะให้ ทดสอบ Mage ไม่มี capstone มีโล่ 100 แล้ว cast Aegis: ใช้คำสั่งได้แต่ไม่มี barrier event ขณะที่ Ward เป้าหมายเดียวกันถูกบล็อก นี่เป็นการป้องกันการเสียเทิร์นที่ไม่สม่ำเสมอ ควรพิจารณาผลรองของ talent/skill-level ก่อนตัดสินว่าเป็น no-op ไม่บล็อกทุกกรณีโดยไม่ดูผลรอง
4. Heal ไม่ยอมให้เลือกคนเลือดเต็มแม้ผู้ใช้มี Afterglow ที่เปลี่ยนการรักษาส่วนเกินเป็นโล่ ทดสอบ full HP เลือกไม่ได้; ขาดเพียง 1 HP กลับเลือกได้และส่วนเกินสร้างโล่ได้ กติกาปัจจุบันชัดเจนใน resolver แต่ขัดความคาดหวังของการสร้างโล่จาก overheal ต้องตัดสินใจว่าจะอนุญาตเมื่อเกิดโล่/ผลรองที่มีประโยชน์ หรือเขียนเงื่อนไขให้ชัด
5. Revive Lv1 → Lv2 ยังชุบด้วย HP 25% เท่าเดิม แต่ให้ผู้ใช้โล่ 3 เพราะถูกจัดเป็น utility skill; Lv5 ยังมีประโยชน์จากลดคูลดาวน์ตามกติกา mastery ระบบทำตามสูตรที่ตั้งใจไว้ ไม่ใช่บั๊กคำนวณ แต่ผลการลงทุนไม่ตรงกับหน้าที่หลักของท่าชุบชีวิต ควรทบทวนรูปแบบอัปเกรดรายสกิล

## ข้อสังเกตด้านการออกแบบ (ไม่ได้ยืนยันว่าเป็นบั๊ก)

- การโจมตีปกติของ Mage ยังใช้ Attack ตามกติกาปัจจุบัน (PR #65 แยกเฉพาะสกิลเวท) หากต้องการให้การโจมตีธรรมดาเป็นการยิงเวทด้วย ต้องออกแบบชนิดโจมตีพื้นฐานต่ออาชีพเพิ่ม
- ระบบแนะนำอุปกรณ์เลือกน้ำหนักจากอาชีพ/แถวเป็นหลัก (`src/core/world/auto-equipment.ts:24`) ไม่ได้ประเมิน loadout จริง จึงไม่ใช่การรับประกันชุดที่เหมาะกับ build ทุกแบบ UI ระบุไว้แล้วว่าเป็นคำแนะนำ ไม่ใช่ดาเมจรับประกัน

## การตรวจยืนยัน

เขียน temporary Vitest probe เรียก characterSkillMetric, skillPower, levelBarrier, targetOptions และ resolveCommand: 1 test ผ่าน ยืนยันตัวเลขและเงื่อนไขข้างต้น แล้วลบ probe ออกจาก repository; log `/tmp/fateweave-logic-audit.log` ไม่มีการแก้ source, balance, save หรือภาพ ไม่มีการขอให้เปลี่ยนกติกาในรอบคำถามนี้
