## 1. หมุนกุญแจอุปกรณ์ (ไม่ต้องเข้าสู่ระบบใหม่)

กุญแจอุปกรณ์ `<deviceId>.<secret>` เดิมใช้ได้ตลอดไป ตอนนี้ secret ถูกเปลี่ยนอัตโนมัติ:

| ขั้น | ทำอะไร |
|---|---|
| เมื่อไร | เครื่องเข้าเกม (`enter`) และหมุนครั้งล่าสุดเกิน 24 ชม. (`ROTATE_EVERY_MS`, เวลาเก็บใน `fateweave-server-token-at:`) |
| เครื่อง | สร้างกุญแจใหม่ (id เดิม secret ใหม่) แล้ว **เก็บลงเครื่องก่อน** (`fateweave-server-token-next:`) จึงส่ง `POST /v1/token/rotate {token}` |
| server | hash ใหม่เป็นปัจจุบัน hash เดิมย้ายไป `prev_hash` ใช้ได้อีก 10 นาที (`ROTATE_GRACE_MS`) แล้วใช้ไม่ได้อีก · ส่งซ้ำด้วยกุญแจเดิม + กุญแจใหม่เดิม = สำเร็จซ้ำ · กุญแจใหม่ต่างไป = 409 `rotate_conflict` · id อื่น = 400 |
| คำตอบหาย | ครั้งหน้าเครื่องส่งซ้ำด้วยกุญแจถัดไปที่เก็บไว้ ถ้ากุญแจเดิมหมดอายุแล้ว (401) เครื่องลองกุญแจถัดไปก่อน **ไม่สร้างบัญชีทดลองใหม่** |
| ไม่มี storage | ไม่หมุน (กุญแจหายพร้อมหน้าอยู่แล้ว) |

ผล: กุญแจที่หลุดออกไปใช้ได้จนถึงการหมุนครั้งถัดไปของเจ้าของเครื่อง (ไม่เกินราว 1 วันที่เล่น + 10 นาที) · ยังไม่มี access token แบบไม่ต้องอ่าน D1 (วัดแล้ว D1 ต่อคำขอไม่ใช่คอขวด) และยังไม่ตรวจ “ใช้กุญแจเก่าซ้ำ” เพื่อเพิกถอนทั้งเครื่อง (เสนอทีหลัง)

## 2. สถิติรวมรายวัน (telemetry)

ตาราง D1 `telemetry_daily (day, kind, key, count)` · วันตามเวลาไทย · **ไม่มี account id อุปกรณ์ หรือ IP**

| kind | key | มาจาก |
|---|---|---|
| `session` | `enter` | Worker เมื่อ `/v1/session` สำเร็จ |
| `commander` | `created` | DO: เกมก่อน/หลังคำสั่ง |
| `run_start` | `<mapId>[:hard]` | DO: event `departed` |
| `run_end` | `<mapId>[:hard]:complete/withdrawn/wiped` | DO: event `settled` |
| `battle` | `<encounterId>:won/lost/left` | DO: ศึกจบ (wins/defeats หรือผลการเดินทาง) |
| `client_error` | `<code>:<place>` | เครื่อง `POST /v1/telemetry` เฉพาะ code/place จากรายการตายตัว ≤10 ต่อคำขอ 6 ครั้ง/นาที; เกมรายงานแต่ละคู่ครั้งเดียวต่อการโหลดหน้า (JS error, promise error, ปัญหาเชื่อมต่อที่แผงเซิร์ฟเวอร์แสดง) |
| `feedback` | หมวด | จำนวนความเห็น |

- เกมฝั่ง server นับจากสิ่งที่ server รันเอง (เครื่องบอกผลเกมเองไม่ได้) ส่งผ่าน header ภายใน `X-Fateweave-Telemetry` จาก DO ถึง Worker แล้ว Worker ลบออกก่อนตอบ · เขียน D1 หลังตอบ (`ctx.waitUntil`) ไม่กระทบคำตอบ · คำสั่งซ้ำ/ถูกปฏิเสธไม่นับ
- ไม่มีจำนวนผู้เล่นไม่ซ้ำต่อวัน (ต้องใช้ id) — ถ้าต้องการ เสนอแยก

## 3. ส่งความเห็นในเกม

- ปุ่ม “ส่งความเห็น / แจ้งปัญหา” ที่หน้าไตเติล และแท็บตั้งค่าของแผนที่/การต่อสู้ (โหมดเซิร์ฟเวอร์) → `<dialog>` เลือกหมวด (บั๊ก · สมดุล · ไอเดีย · อื่น ๆ) + ข้อความ ≤1000 ตัวอักษร
- `POST /v1/feedback {category, text, place}` → D1 `feedback` (account_id, หมวด, ข้อความตัด control char, หน้า, content version, เวลา) · ตรวจก่อนนับ 3 ครั้ง/10 นาที · บัญชีรอลบส่งไม่ได้ · **ลบพร้อมบัญชีตอน purge**
- ผู้ดูแล (แถว D1 `admins`): `GET /v1/account` ตอบ `admin: true` → ฟอร์มแสดง “ความเห็นล่าสุด” (`GET /v1/admin/feedback?limit&before`) และ “สถิติ 14 วัน” (`GET /v1/admin/telemetry?days`) · ทุกครั้งเขียน `admin_audit` (`feedback_read`/`telemetry_read`)
- หน้า privacy เพิ่มสถิติรวม ความเห็น และการหมุนกุญแจแล้ว
