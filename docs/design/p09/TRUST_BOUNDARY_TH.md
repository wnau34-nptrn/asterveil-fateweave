# P09-01 — Trust boundary: เซฟ offline เก่า กับเศรษฐกิจ online

11 พฤศจิกายน 2026 · ต่อยอด [GACHA_G01_MIGRATION_TH.md](../GACHA_G01_MIGRATION_TH.md) (ทางเลือก A/B/C) · **[โค้ด]** = ข้อเท็จจริง; **[เสนอ]** = ข้อเสนอ · ตัวเลขทั้งหมดเป็นร่าง

## 1. ทำไมต้องมีเส้นแบ่ง [โค้ด]

- เซฟอยู่ในเครื่องผู้เล่นทั้งหมด แก้ด้วย devtools ได้; `parseGame` ตรวจรูปแบบ เพดาน (`BANK_CAP` ทอง/แร่/ฝุ่น 9,999,999 ตรา 99,999) ความสอดคล้องของต้นไม้/ของ และ replay ศึกที่ค้าง **แต่ไม่ตรวจว่ารายได้ได้มาจริง** — เซฟที่ตั้ง bank เป็นเพดานผ่าน (เทสต์ `tests/cloud-save-envelope.test.ts`)
- `profile.seed` และตัวนับ `forge` มาจากเครื่อง ผลหลอม/สุ่มบนค่ายจึงเลือกได้ด้วยการแก้ seed
- ดังนั้น “ผ่าน replay” = เซฟเล่นต่อได้ตามกฎ ไม่ใช่หลักฐานว่าเป็นสิทธิ์ที่ server เคยแจก

## 2. หลักการ [เสนอ]

1. **ทางเดียว**: ยอดใน profile (ทอง แร่ ฝุ่น ตรา ตำรา ดาว ของ) ไม่ถูกแปลงเป็นตั๋ว/แต้มสุ่ม/ของที่ซื้อได้ โดยอัตโนมัติ — ไม่ว่าเซฟจะเก่าหรือใหม่
2. **สกุลออนไลน์อยู่บน server เท่านั้น**: ตั๋ว/แต้มกาชา และสิทธิ์ที่จะมีในอนาคต อยู่ใน ledger ของ server ไม่อยู่ใน `Profile` ไม่มีฟิลด์ในเซฟให้แก้
3. **การกระทำออนไลน์ทำบนก้อนคลาวด์**: เคลมรางวัล/สุ่ม ต้องอยู่สถานะ `synced`; server โหลด head → ใช้ฟังก์ชัน pure ชุดเดียวกับเกม (เช่นมอบสมาชิก/เศษ) → เขียน revision ใหม่ → ส่ง payload กลับ เครื่องไม่ประกาศผลเอง
4. **หลักฐานจากเครื่องให้ได้แค่สิ่งที่มีเพดานตามเนื้อหา และครั้งเดียวต่อบัญชี**: เช่น catch-up ของแผนที่ที่ `cleared` แล้ว คิดจากตารางเนื้อหา (สูงสุด = เคลียร์ทุกแผนที่) ผูก key `entitlement:<account>:<mapId>` แบบ unique แก้เซฟก็ได้ไม่เกินผู้เล่นที่เคลียร์ครบจริง
5. **ไม่ลงโทษเซฟที่แก้ใน PvE เดี่ยว**: เล่นต่อได้ ไม่ลบ ไม่ล้าง; ใช้ flag ความผิดปกติเป็น telemetry/support เท่านั้น
6. **สิทธิ์ผู้เล่นเดิมไม่หาย**: สมาชิก ดาว ของ ต้นไม้ ตำรา `veteran` thiran/wila ที่พักไว้ ทุกอย่างในเซฟเดิมยังเล่นได้ครบหลังผูกบัญชี (ตรงกับตาราง G01 §2)

## 3. ใครเป็นเจ้าของอะไร [เสนอ]

| ข้อมูล | เจ้าของ | เหตุผล |
|---|---|---|
| account ID, ตัวตนที่ผูก, device credential | server | ความปลอดภัย |
| revision/ประวัติเซฟ, เวลาที่บันทึก | server | ตัดสินขัดกัน/กู้คืน |
| เวลาจริง (วัน/สัปดาห์, รอบเควสต์, หมดอายุ) | server | นาฬิกาเครื่องเลื่อนได้ |
| seed ของการสุ่มออนไลน์ (กาชา รางวัลสุ่ม) | server | ห้ามเลือกผลได้ |
| ledger ตั๋ว/แต้ม, entitlement ครั้งเดียว, receipt ซื้อ (อนาคต) | server | ไม่ซ้ำ ตรวจย้อนได้ |
| ผล World Boss/การจัดอันดับ | server (replay คำสั่ง) | แต่สเตตัสยังมาจากเซฟ → ดูข้อตัดสินใจ D7 |
| ความคืบหน้า PvE: แผนที่ ทีม ของ ต้นไม้ ทอง/แร่/ฝุ่น/ตรา ยา ตำรา | **เครื่อง** (ตรวจด้วย replay+เพดาน) | เกมเดี่ยว ไม่กระทบคนอื่น |
| สุ่มบนค่ายเดิม (หลอม, กระดานจ้าง) จาก `profile.seed` | เครื่อง (คงเดิม) | ไม่แตะเศรษฐกิจออนไลน์; ถ้าต่อกับออนไลน์ภายหลังต้องย้าย seed ไป server |

## 4. เซฟเก่าเมื่ออัปโหลดครั้งแรก [เสนอ]

- อัปโหลดครั้งแรกของเซฟ offline บันทึก `origin=legacy` + digest ของเซฟต้นฉบับ (fingerprint) เก็บก้อนดิบไว้ในประวัติ
- ทั้งเซฟใช้เล่นต่อได้ทันที (ทางเลือก A ใน G01)
- wallet ออนไลน์เริ่มที่ 0 + ของขวัญเปิดระบบแบบคงที่เท่ากันทุกบัญชี (ถ้ามี) + catch-up ตามหลักข้อ 4
- เซฟเดียวกันอัปโหลดหลายบัญชี (fingerprint ซ้ำ): ยังเล่นได้ แต่ catch-up ที่คิดจากหลักฐานเครื่องให้ได้บัญชีเดียว (ร่าง) — ป้องกันฟาร์มบัญชีจากเซฟเดียว
- บัญชีสองบัญชีของคนเดียว: ไม่รวมยอด ให้ support เลือกบัญชีหลัก (G01)

## 5. สิ่งที่ยังเปิด

ตัวเลข catch-up/ของขวัญ, ผลต่อ World Boss/อันดับ, และการย้าย seed หลอมไป server ถ้าวันหนึ่งของหลอมมีผลออนไลน์ — ดู [README_TH.md](README_TH.md) ข้อ D3, D5, D7
