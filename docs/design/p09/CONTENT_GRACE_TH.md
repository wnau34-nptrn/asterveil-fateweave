# เวอร์ชันเนื้อหา: รับเวอร์ชันก่อนหน้าชั่วคราวระหว่าง deploy + ประกาศให้รีเฟรช — 2026-11-20

เจ้าของ 2026-11-20 (OD-57): "ให้เซิร์ฟเวอร์ยอมรับเวอร์ชันก่อนหน้าได้ชั่วคราวระหว่าง deploy แล้ว deploy เสร็จจะมีประกาศให้ทำการ Refresh version ใหม่" ไม่แตะกติกา เซฟ หรือรางวัล

## ปัญหา
เกมกับ API ต้องมี "เวอร์ชันเนื้อหา" (SHA-256 ของ `src/core` + `src/content`, `scripts/content-version.mjs`) ตรงกัน ไม่ตรงตอบ 409 `content_version` แต่ dev API deploy ภายในไม่กี่นาทีหลัง push ส่วนหน้าเกม (Pages) ต้องรอชุด Chromium (~40 นาที, P12) ช่วงนั้นผู้เล่นออนไลน์ได้หน้าจอ "เวอร์ชันเกมไม่ตรงกับเซิร์ฟเวอร์" และรีเฟรชก็ไม่หาย (เหตุการณ์ 2026-11-19 หลัง PR #307)

## ที่ทำ
1. **เซิร์ฟเวอร์รับเวอร์ชันก่อนหน้า** — `ApiDeps.previousVersions` + `previousUntil`; `contentAccepted()` รับเวอร์ชันปัจจุบันเสมอ และรับเวอร์ชันในรายการจนถึงเวลาหมดอายุ (`src/server/api.ts`) ตัวแปร Worker: `CONTENT_PREVIOUS` (เวอร์ชัน 16 hex คั่นจุลภาค ≤3) + `CONTENT_PREVIOUS_UNTIL` (เวลา ISO) ผิดรูปแบบ = ไม่มี grace (`contentGrace()` ใน `worker.ts`) คำตอบ 409 บอกเวอร์ชันของเซิร์ฟเวอร์ และระหว่าง grace บอก `previous`/`until` ด้วย
2. **workflow deploy คำนวณรายการเอง** — `scripts/content-grace.mjs` ถาม API ที่รันอยู่ (409 ด้วยเวอร์ชันปลอม) แล้วตั้ง `CONTENT_PREVIOUS` = เวอร์ชันที่รันอยู่ + ที่ยังรับอยู่ (ต่อโซ่ได้ถ้า push ถี่หรือ deploy ซ้ำ) ไม่รวมเวอร์ชันใหม่ ไม่เกิน 3 อยู่ **3 ชั่วโมง** (`GRACE_HOURS`) ปิดได้ด้วย `[no-grace]` ในข้อความ commit หรือ input `no_grace` ของ `workflow_dispatch` (ใช้เมื่อการเปลี่ยนที่หน้าเก่ารับไม่ได้ เช่น เปลี่ยนรูปแบบคำสั่ง/เปลี่ยนเวอร์ชันด่าน)
3. **ประกาศให้รีเฟรช** — build สร้าง `version.json` ({ build = commit CI หรือเวอร์ชันเนื้อหา }) ข้าง `index.html`; หน้าที่เปิดอยู่ตรวจเมื่อเปิด ทุก 5 นาที และเมื่อกลับมามองเห็น (`src/platform/update-check.ts`) ถ้า build ที่ออนไลน์ต่างจากที่หน้านี้รัน แสดงแถบ "มีเวอร์ชันใหม่พร้อมแล้ว" พร้อมปุ่ม **รีเฟรช** / **ภายหลัง** (`src/ui/update-banner.ts`) แถบขึ้นเมื่อ **Pages ใหม่ออนไลน์จริง** เท่านั้น จึงไม่เจอหน้าเก่าซ้ำ "ภายหลัง" ซ่อนจน build ถัดไป (เฉพาะแท็บนี้) ไม่รีเฟรชเอง และเกมบันทึกทุกคำสั่งทันทีจึงไม่เสียความคืบหน้า

## ข้อจำกัดที่ต้องรู้
- ระหว่าง grace เซิร์ฟเวอร์ตัดสินด้วยกติกาใหม่เสมอ (เซิร์ฟเวอร์เป็นผู้ตัดสิน) หน้าเก่าที่คาดผลต่างอาจเห็นผลไม่ตรงที่คาดไว้ในบางคำสั่ง ถ้าเป็นการเปลี่ยนกติกาที่รับไม่ได้ให้ใช้ `[no-grace]`
- หน้าที่เก่ากว่าเวอร์ชันที่รับ หรือเกิน 3 ชั่วโมง ยังเจอข้อความเดิม (409) และควรรีเฟรช
- ถ้า push ถี่เกิน 3 เวอร์ชันก่อน Pages ตามทัน เวอร์ชันเก่าสุดหลุดรายการ
- แถบประกาศอาจทับปุ่ม Setup บนหน้าเริ่มชั่วคราวจนกว่าจะกด "ภายหลัง"
- ไม่ครอบคลุม deploy ที่ API ล้ม (เว็บใหม่ API เก่า) ยังได้ 409 ตามเดิม
