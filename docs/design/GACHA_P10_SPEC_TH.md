## 3. หน่วยเศษ (ทำไม 10/50 ไม่ใช่ 20/100)

G00/G01 เขียนบนฐาน c4beb7b ที่ตัวซ้ำ = 20 และ ★5 = 200 หน่วย. P04-02 (OD-15/23) ลดหน่วยลงครึ่ง: ตัวซ้ำ = 10, ★5 = 100. สัดส่วนจึงคงไว้: **ตัวซ้ำ 20→10, ปลด 100→50 (= ตัวซ้ำ 5 ตัวเท่าเดิม)**, ไม่แก้ราคาดาว/เศษกลางในเซฟใคร. ส่วน "เศษ 1 หรือ 2 ชิ้น" ใช้ตามคำเจ้าของวันนี้เป็นชิ้นจริงในเกม — มูลค่าเศษต่อการสุ่มจึงสูงกว่าแบบจำลอง G01 ราว 44% (2.26 เทียบ 1.57 หน่วยปัจจุบัน/ครั้ง). ผลจำลอง §4 ยังไม่ทำให้คนโปรดถึง ★5 เร็วเกิน OD-07; ถ้าเจ้าของต้องการเท่าแบบจำลองเดิม ให้เปลี่ยนเป็นเศษ 1 ชิ้นเสมอหรือ 1–2 ที่น้ำหนัก 3:1 (bump `version`)

## 5. สัญญาธุรกรรม (ตรงกับ GACHA_DEVELOPMENT_PLAN §4)

- คำสั่ง `gachaPull {count: 1|10, config}` / `gachaExchange {heroId, config}` ผ่าน `processCommand` ซอง `{requestId, seq}` เดิมของ P09: server ตรวจทุกค่าใหม่; `config` ≠ `gacha.version` → ปฏิเสธ `config` (ไม่สุ่มด้วยกติกาที่ผู้เล่นไม่ได้ยืนยัน)
- Seed หนึ่งค่าต่อคำสั่งจาก server (`recordingSeeds`) เก็บใน log เท่านั้น ไม่อยู่ในเซฟ/มุมมองเครื่อง; สุ่มเฉพาะคำสั่งที่กติกายอมรับ (คำสั่งที่ถูกปฏิเสธไม่ใช้ seed) · 10 ครั้ง = 10×1 บน stream เดียวกัน
- หักตั๋ว + เพิ่มแต้ม + ผล + ประวัติ + log + ledger `gacha:<serial>` อยู่ใน commit เดียวของ Durable Object · requestId เดิม+payload เดิม → คำตอบเดิม ไม่หักซ้ำ · requestId เดิม+payload ต่าง → 409 `request_reused` · seq ชน (สองเครื่อง) → 409 `stale` · เล่นทีละเครื่อง (D12, 423)
- ประวัติ: 30 รายการล่าสุดในเซฟ + journal เต็มใน `reward_ledger` (คอลัมน์ `detail`) อ่านผ่าน `GET /v1/gacha/history?before=&limit≤50` · `/v1/verify` replay ได้ผลเดิม
- Telemetry รายวันไม่มี id (`telemetry_daily` kind `gacha`: full / shard:1 / shard:2 / exchange) เพื่อตรวจเรตจริงเทียบเรตประกาศ — ไม่ต้องมี D1 migration ใหม่ (wallet/journal อยู่ใน SQLite ของ DO ต่อบัญชีเหมือน ledger P09)
- `?server=off`: กติกาเดียวกัน seed จากเครื่อง ตั๋วได้จากแหล่งเดียวกันเท่านั้น และไม่ย้ายเป็นสิทธิ์ออนไลน์ (D24)

## 6. Rollback

ปิดตู้ได้โดยตั้ง `unlocks.gacha` สูงเกินแมพที่มี (ปุ่มหาย คำสั่งถูกปฏิเสธ `locked`) โดยไม่ลบ wallet/journal; เปลี่ยนเรต/ตู้ต้อง bump `gacha.version` (คำสั่งค้างของ version เก่าถูกปฏิเสธ ไม่ใช้ตั๋ว); ไม่ restore DB เก่า ใช้ compensating grant ที่ตรวจได้
