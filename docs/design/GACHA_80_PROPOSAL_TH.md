## 1. บริบทและสิ่งที่เปลี่ยนจากข้อเสนอเดิม

- เกมปัจจุบันมี 15 อาชีพ อาชีพละหนึ่งตัวที่เปิดรับใหม่; `thiran`/`wila` พักตาม OD-14 และต้องเก็บสิทธิ์ของเซฟเก่า
- มีบอร์ดจ้างด้วยทอง สมาชิก ตัวซ้ำและอัปดาวแล้ว แต่ยังไม่มีตั๋วกาชา แต้มแลก ผลสุ่ม ประวัติธุรกรรม บัญชีผู้เล่น หรือฐานข้อมูลรางวัลจริง; Worker ปัจจุบันมีเพียง `/health`
- เป้าการเล่นเดิมคือ 20–30 นาที สัปดาห์ละ 3–5 ครั้ง และปั้นคนโปรดตัวแรกถึง ★5 ประมาณ 7–10 ครั้งเล่น ไม่บังคับเข้าเกมทุกวัน (OD-06/07)
- เจ้าของเสนอพิจารณา 80 หรือ 100 แต้มเพื่อแจกตั๋วได้บ่อยขึ้น ผู้ช่วยแนะนำ **80 แต้มเป็นกรณีหลัก**; 100 เป็นทางเลือกสำหรับเทียบผล ยังไม่ได้ถือว่าเจ้าของอนุมัติตัวเลขหรือการพัฒนา runtime
- “80 แต้ม” ในเอกสารนี้หมายถึง **80 แต้มสัญญาแลกตัวละครหนึ่งครั้ง** ไม่ใช่ 80 แต้มแลกตั๋วสุ่มหนึ่งใบ
- ข้อเสนอเก่า 30 แต้ม/ฟรี 40–48 ใบ และผลจำลองเก่าเป็น baseline อ้างอิงเท่านั้น ห้ามอ้างว่าเป็นผลยืนยันของ 80 แต้ม; เอกสารนี้เสนอฟรี 80–96 ใบและทดสอบเพดานโบนัส 100 ใบต่อรอบ 28 วัน

| ฟาร์มเจาะจง | กรณีจำลอง 20 เศษ/เที่ยวครั้งแรก 4 ครั้งต่อสัปดาห์; ไม่ขายสิทธิ์เพิ่มเพดานในต้นแบบ |

ตัวแรกต้องใช้บทบาทหลักได้จากเส้นทางพัฒนาปกติ ไม่ย้ายสกิลหลักไปล็อกหลังการสุ่มตัวซ้ำ ท่าหรือร่างเลื่อนอาชีพในอนาคตไม่กลายเป็นกาชาร่างใหม่ทับตัวเดิม

ค่า 20/100/200 เป็นร่างเพื่อเทียบ economics แม้สอดคล้องตัวซ้ำเดิม 1/2/3/4 ตัวก็ยังไม่ใช่ migration rule ที่อนุมัติ เศษกลางเติม 100% เป็นข้อเสนอเปลี่ยนจากตราทดแทนเดิมที่มีข้อจำกัด ต้องตรวจบัญชีเก่า/ใหม่/คอขวดแร่ด้วย

ห้ามนำเศษประจำตัวที่ยังมีสิทธิ์ใช้ในขั้นพัฒนาอนาคตไปแปลงเงียบ ๆ ก่อนกำหนดนโยบาย promotion และ overflow ให้ครบ ไม่ตัดรางวัลเพราะช่องทีมเต็ม: สมาชิกยังเข้าคลังตัวละคร และให้เลือกจัดทีมภายหลัง

## 4. บทบาทกาชา บอร์ด และเนื้อเรื่อง

- เนื้อเรื่อง: คนพื้นฐานและการสอนอาชีพ; เมื่อเคยได้จากกาชาแล้วถึงจุดรับฟรี ต้องชดเชยเศษอย่างชัดเจนและรับครั้งเดียว
- บอร์ดจ้าง: ทางรับคนฟรีแน่นอนและสัญญาฟาร์มเป้าหมายที่มีความคืบหน้าถาวร; การเปลี่ยนบอร์ดเดิมต้องระบุการเก็บสิทธิ์/ต้นทุนทองเดิม ไม่ลบทางรับเดิมทันที
- กาชา: ได้คนก่อนจุดรับฟรี ลุ้นสะสมและเร่งทรัพยากร; ไม่มีตัวเฉพาะตู้ที่จำเป็นต่อเนื้อเรื่อง
- ทดลองตัว: ยืมบิลด์มาตรฐานได้ก่อนเลือกปั้น; ไม่ให้การกดลองหรือแอนิเมชันเพิ่มทรัพยากรจริง
- ★5 ไม่ใช่จุดจบคอนเทนต์: ใช้การจัดทีม เรื่อง อุปกรณ์และของตกแต่งเป็นเหตุผลเล่นต่อ ไม่เพิ่มเพดานเพื่อดูดสต็อกอย่างเดียว

| งานรายสัปดาห์ | สัปดาห์ละ 4; นับร่วมกับชัยชนะ/งานรายวัน ไม่บังคับ 7 วัน | 16 |

เผื่อกรณีโบนัสพิเศษได้สูงสุด 100/28 วันสำหรับ stress test; ไม่ถือว่าได้ 100 ทุกเดือน และการคืนของที่เสียหายจริงไม่ใช่งบโบนัสแจก ตั๋วจากโหมดที่ยังไม่เกิดอาจจัดสรรชั่วคราวในกิจกรรมทดสอบก้อนเดียว เมื่อเปิดโหมดให้ย้ายงบเดิม ไม่บวกสะสมใหม่

## 8. อัตราสุ่มที่ใช้ศึกษา ไม่ใช่ค่าที่ล็อก

กรณีหลัก A: ตัวเต็ม7.5%; ที่เหลือ92.5%เป็นเศษ1หรือ2เท่ากัน สุ่มชื่อเท่ากันใน15คน ไม่มี rate-up; ได้ตัวซ้ำ20 เศษ; 80แต้มเลือกตัว ยังต้องเทียบ B=5%, C=10% และกรณีเสี่ยงที่คงอัตรา10%+เศษ1–5เดิม

เมื่อทุกผลเป็นตัวที่มีแล้วและเลือกแลกเป็นตัวซ้ำ มูลค่าเศษเทียบเท่าต่อ pull โดยประมาณ:

- เดิม30/48: 0.10×20 +0.90×3 +20/30 =5.3667; ×48 =257.6/28วัน
- ใหม่80/96/A: 0.075×20 +0.925×1.5 +20/80 =3.1375; ×96 =301.2/28วัน
- รวมฟาร์ม320/28วัน: เดิม577.6 →ใหม่621.2 เพิ่มประมาณ7.55%; ไม่ได้เท่ากัน แม้เศษต่อครั้งลดลง

นี่เป็น steady-state mass comparison ไม่ใช่เวลาถึงตัวใหม่หรือผลเมื่อสุ่มชื่อที่ยังไม่มี และไม่ใช่เหตุผลเพียงพอให้เลือกเรต A เพราะความรู้สึกของการสุ่มต้องทดสอบด้วย โอกาสสิบครั้งไม่เจอตัวเต็มของ A ≈45.86% หากไม่มีการันตีเสริม ต้องแสดง “โอกาสได้ตัวเต็ม” และผลเศษจริง ไม่โฆษณาสิบครั้งว่ารับประกันตัว หากผลทดสอบรู้สึกได้แต่เศษ ให้ทบทวน UI/รางวัล/เรตและจำลองใหม่ ไม่เติมการันตีสิบครั้งเงียบ ๆ

80/128 และ100/160 รักษาสิทธิ์แลก1.6ครั้ง/28วันเท่าข้อเสนอ30/48 แต่ถ้าไม่ปรับรางวัลระหว่างทาง จำนวนตัว/เศษจะเพิ่มมาก จึงไม่ใช่การเปลี่ยนหน่วยที่รักษาเศรษฐกิจเดิม

## 9. หน้าจอและความสนุก

- หน้าตู้: ยอดตั๋ว, เป้าแลก, แต้ม52/80และ“อีก28แต้มแลกได้”, อัตรา/รายชื่อ/ผลตัวซ้ำ, ประวัติ, ปุ่มสุ่ม1/10และแลกตัว; เลือกเป้าไม่ใช่เพิ่มเรต
- ก่อนใช้ตั๋ว: แสดงจำนวนใช้/คงเหลือ; ก่อนแลกคนที่มีแล้วแสดงผลเป็นเศษ ยืนยันกับ profile/ราคา version เดิม
- หน้าผล: แยกตัวใหม่/ตัวซ้ำ→เศษ/เศษ; เน้นเป้าหมายและข้อความ“ใกล้ปลด/ใกล้อัพดาว”จาก state จริง; แต้มเพิ่มตามจำนวน pull ที่บันทึกสำเร็จเท่านั้น
- แอนิเมชันสั้น กดข้ามได้ reduced-motion ทำงาน; skip/background/resize/reloadไม่สุ่มใหม่ ไม่แจกซ้ำ; ปุ่มสุ่มต่อแสดงต้นทุนรอบใหม่
- ทุกคนระดับเดียว ใช้ชื่อ อาชีพและวิธีจัดทีมสร้างคุณค่า; ไม่ใช่เพียงเพิ่มจำนวนครั้งที่กดแล้วซ่อนมูลค่าต่อครั้งที่ลดลง
- Artwork R2: ในบทสนทนามีเพียงภาพข้อความอ้างถึง ART-UI-GACHA-001; ไม่พบไฟล์เต็มใน game branch ที่ตรวจ จึงยังไม่มีผลตรวจ layout/artboard เต็มภาพ และไม่คัดลอกภาพเข้าเอกสารนี้

## 10. สิ่งที่ต้องสรุปก่อนใช้จริง

1. เลือก80หรือ100และช่วงงบ80–96/โบนัส100 หลังผลจำลองและ playtest; ไม่ถือว่าการขอ push เอกสารคืออนุมัติตัวเลข

3. Migration dupes/seals/stars/ตัวพัก/รางวัลเรื่องซ้ำ/active expedition/เพดานเศษ พร้อมตารางสิทธิ์และผลต่อบัญชีเก่า
4. บัญชี/ย้ายเครื่องและ trust ของเซฟเก่า; premium wallet/seed/เวลา/ผลสุ่ม/ledger ต้องเป็นของ server ไม่เชื่อ client seed หรือยอดใน localStorage
