# P11 แชท — ออกแบบรอบแรก (2026-11-15)

สถานะ: ทำแล้ว (PR #261) · owner อนุมัติตัวเลขร่างและ guest พิมพ์ได้ 2026-11-16 (OD-46) · ไม่แตะกติกา/เซฟ/สมดุล (เซฟยัง v64)

ลำดับ OD-13: World Boss → **แชท** → ทดสอบภายนอก · ไม่มี PvP async/Co-op · ไม่มีการจ่ายเงิน

## 1. ช่องแชท

- รอบนี้มี **ช่องเดียว: "แชทโลก" (`world`)** — ทุกบัญชีบนเซิร์ฟเวอร์เห็นข้อความเดียวกัน
- ไม่มีแชทส่วนตัว (DM) ไม่มีห้องค่าย/กิลด์ ไม่มีรูป/ลิงก์/สติกเกอร์ — ลดพื้นที่ล่วงละเมิดก่อนทดสอบภายนอก
- โครงสร้างข้อมูลมี `channel` ไว้แล้ว เพิ่มช่องภายหลังได้ (เช่น ช่องช่วยเหลือ หรือช่อง World Boss) โดยไม่เปลี่ยน API
- ออฟไลน์ (ไม่ได้เล่นผ่านเซิร์ฟเวอร์) = ปุ่มแชทปิดพร้อมเหตุผล "แชทใช้ได้เมื่อเล่นผ่านเซิร์ฟเวอร์"

## 2. สถาปัตยกรรม (ใช้ของเดิม)

- Durable Object เดียว `Chat` (ชื่อ `chat`) แบบเดียวกับ `WorldBoss` — `src/server/chat.ts` (`ChatHost` + store SQLite + `handleChatRequest`)
- Worker (`api.ts`) ตรวจ bearer token / สถานะบัญชี / IP gate แล้วส่งต่อ DO ด้วย account id ที่ตรวจแล้ว (DO ไม่เชื่อข้อมูลจากเครื่อง)
- อ่านแบบ **polling** (`GET /v1/chat?after=<id>`) ทุก 8 วินาทีเฉพาะตอนหน้าแชทเปิดและแท็บมองเห็น — ไม่ใช้ WebSocket รอบนี้ (ง่าย ทนเน็ตหลุด ไม่มีการเชื่อมค้าง); ถ้าผู้เล่นมากขึ้นค่อยย้ายเป็น WebSocket hibernation ใน DO เดียวกัน
- ไม่ใช้ content-version/session header (แชทไม่ใช่เนื้อหาเกม) — อยู่กลุ่มเส้นทางบัญชีเหมือน feedback
- ตัวกรองข้อความ `src/core/chat/filter.ts` เป็นฟังก์ชันบริสุทธิ์ ใช้ร่วมกันทั้งเครื่องผู้เล่น (เตือนก่อนส่ง) และเซิร์ฟเวอร์ (ตัดสินจริง)

| เส้นทาง | ใช้ทำอะไร |
|---|---|
| `GET /v1/chat?after=` | ข้อความใหม่กว่า `after` (สูงสุด 50 ล่าสุด) + สถานะ mute ของตัวเอง + สิทธิ์เขียน |
| `POST /v1/chat` `{ text }` | ส่งข้อความ → 201 ข้อความที่บันทึก (หลังกรอง) |
| `POST /v1/chat/report` `{ id, reason }` | แจ้งข้อความ (`abuse`/`spam`/`personal`/`other`) |
| `GET /v1/admin/chat` | ผู้ดูแล: ข้อความที่ถูกแจ้ง/ถูกซ่อน + mute ที่มีผล (บันทึก `admin_audit`) |
| `POST /v1/admin/chat/hide` `{ id, hidden }` | ผู้ดูแล: ซ่อน/คืนข้อความ (audit) |
| `POST /v1/admin/chat/mute` `{ accountId, minutes }` | ผู้ดูแล: ห้ามพิมพ์ 1 นาที–30 วัน, `0` = ยกเลิก (audit) |

## 3. ข้อความและการจำกัด (ร่าง)

- ยาว 1–160 ตัวอักษร (code point) หลังตัดช่องว่างซ้ำ/อักขระควบคุม/อักขระมองไม่เห็น; ไม่มีขึ้นบรรทัดใหม่
- **ปฏิเสธ** (บอกเหตุผล): ลิงก์/โดเมน, อีเมล, ตัวเลขยาว ≥ 8 หลัก (เบอร์โทร/เลขบัตร — ความเป็นส่วนตัว), อักษรซ้ำยาวเกิน 10 ตัว, ข้อความซ้ำกับข้อความก่อนหน้าของตัวเองภายใน 60 วินาที
- **ปิดคำหยาบ** ด้วย `***` (รายการคำสั้น ๆ ไทย/อังกฤษใน `filter.ts`; owner เพิ่มได้) — ไม่ปฏิเสธ เพื่อไม่ให้ผู้เล่นหงุดหงิด; หลีกเลี่ยงคำที่ชนคำในเกม (เช่น "หีบ")
- อัตราต่อบัญชี (นับใน DO จึงแม่นทุก isolate): 1 ข้อความ / 4 วินาที, 8 / นาที, 60 / ชั่วโมง
- อัตราต่อเครือข่าย IP (gate `RateLimit` DO เดิม): ส่ง 30 / นาที — กันสร้างบัญชี guest หลายบัญชีมาสแปม
- อ่าน: ตัวกรองใน isolate 1 ครั้ง / วินาที / บัญชี (เครื่องจริงอ่านทุก 8 วินาที)
- แจ้ง: 10 ครั้ง / 10 นาที / บัญชี; แจ้งข้อความตัวเองไม่ได้; คนเดิมแจ้งซ้ำนับครั้งเดียว

## 4. การดูแล (moderation)

- ผู้ดูแล = แถวใน D1 `admins` เดิม (owner เพิ่มเอง ไม่มีรหัสลับ) — ผู้ดูแลเห็นแผงจัดการในหน้าแชท
- **ซ่อนอัตโนมัติ** เมื่อมีผู้แจ้งต่างบัญชีกัน 3 คน (ร่าง) — ผู้ดูแลคืนได้
- ผู้ดูแลเห็น account id ของผู้เขียนเฉพาะในแผงจัดการ; ทุกการอ่าน/ซ่อน/mute ลง `admin_audit`
- ผู้เล่นทุกคน "ซ่อนค่ายนี้" ได้เอง (เก็บใน localStorage ของเครื่อง ไม่ส่งเซิร์ฟเวอร์ ไม่อยู่ในเซฟ)
- สวิตช์ของ owner (`CHAT_WRITE` ใน wrangler vars): `all` (ค่าเริ่ม) = guest พิมพ์ได้, `linked` = เฉพาะบัญชีที่ผูก Google, `off` = อ่านอย่างเดียว; ไม่มี binding `CHAT` = แชทปิดทั้งหมด (503)
- บัญชีสถานะ `deleting`/`suspended` พิมพ์และแจ้งไม่ได้

## 5. ความเป็นส่วนตัวและการเก็บข้อมูล

- ชื่อที่แสดง = **ชื่อแฝง** `ค่าย-XXXXX` จาก SHA-256 ของ account id (ย้อนกลับไม่ได้ ไม่เผย account id) — ไม่ใช้ชื่อผู้บัญชาการ/ชื่อค่ายที่ผู้เล่นพิมพ์เอง (ลดพื้นที่ตั้งชื่อหยาบ และไม่ต้องอ่านเซฟ)
- เก็บข้อความ 7 วัน หรือ 500 ข้อความล่าสุด (อันไหนถึงก่อน); ข้อความที่ถูกแจ้งเก็บต่อได้ถึง 30 วันเพื่อการตรวจ; mute ที่หมดอายุลบทิ้ง
- ลบบัญชี (cron purge เดิม) → ลบข้อความ รายงาน และ mute ของบัญชีนั้นใน DO แชทด้วย ก่อนลบแถว D1
- ไม่มี IP ในข้อมูลแชท (IP ใช้แค่เป็นกุญแจนับอัตราใน `RateLimit` DO ซึ่งหมดอายุเป็นนาที)
- หน้าแชทเตือน "อย่าใส่ข้อมูลส่วนตัว"; หน้านโยบายความเป็นส่วนตัว (`public/privacy.html`) เพิ่มหัวข้อแชทแล้ว

## 6. กรณีล่วงละเมิดที่คิดไว้

| กรณี | รับมือ |
|---|---|
| สแปมจากบัญชีเดียว | อัตรา 4 วินาที/8 ต่อนาที/60 ต่อชั่วโมง + ห้ามข้อความซ้ำ 60 วินาที |
| สแปมจากหลายบัญชี guest | การสร้าง guest จำกัดต่อ IP อยู่แล้ว + ส่งแชทจำกัด 30/นาที/เครือข่าย IP; owner ตั้ง `CHAT_WRITE=linked` ได้ทันที |
| ลิงก์ฟิชชิง/โฆษณา | ปฏิเสธลิงก์และโดเมนทั้งหมด |
| แจ้งเท็จรุมซ่อน | ต้อง 3 บัญชีต่างกัน, ผู้ดูแลคืนได้, การแจ้งจำกัดต่อบัญชี |
| ด่าทอ/คุกคาม | ปิดคำหยาบ, แจ้ง → ซ่อน, ผู้ดูแล mute, ผู้เล่นซ่อนค่ายนั้นเองได้ |
| เปิดเผยข้อมูลส่วนตัว | ปฏิเสธตัวเลขยาว/อีเมล; แจ้งเหตุผล `personal` |
| HTML/สคริปต์ในข้อความ | แสดงด้วย `textContent` เท่านั้น; ตัดอักขระควบคุม/bidi |
| ข้อความยาว/ไบต์มหาศาล | ตัดที่ Worker 2 KB ก่อนอ่าน JSON, 160 ตัวอักษรหลังกรอง |
| DO แชทล่ม | เกมเล่นต่อได้ตามปกติ หน้าแชทบอก "เชื่อมต่อแชทไม่ได้" |
