# หน้าแรกแบบกระชับ (title-compact) — mockup ที่เจ้าของอนุมัติ

13 พฤศจิกายน 2026 · เจ้าของ: “อนุมัติตาม mockup และที่คุณแนะนำ ทำได้เลย” · งาน UI เท่านั้น (DOM/CSS ของหน้าแรก) ไม่แตะกฎ เซฟ ตัวเลข หรือ server API

## ปัญหาเดิม (ภาพจริง 390px)

- โหมดเซิร์ฟเวอร์: ปุ่มเต็มความกว้าง 3 ปุ่ม (เดินทางต่อ / เริ่มเกมใหม่ / บัญชี·Google·รหัสกู้คืน) + ข้อความ 2 บรรทัด ดันขึ้นบังตัวละครถึงกลางจอ; ข้อเสนอนำเข้าเซฟเดิมบังสูงกว่า
- สรุปเซฟไม่มีพื้น อ่านยากบนภาพ; “เริ่มเกมใหม่” (ลบค่าย) เด่นเท่า “เดินทางต่อ”

## สิ่งที่อนุมัติ (ดู `compare-server.webp`, `compare-import.webp`, `mock-settings-390.webp`, `mock-local-390.webp`, `mock-new-390.webp`; HTML ต้นแบบ `mockup.html` — ชื่อค่าย/ตัวเลขเป็นตัวอย่าง ไม่ใช่ข้อมูล)

1. **กรอบล่างกรอบเดียว** (navy glass, สูง ~150px, ขอบล่าง 18px + safe area): บรรทัดสรุปเซฟ (ชื่อค่าย · สถานะ + ชิปก้าว/ชนะ หรือทีม/แร่) + ปุ่มหลักปุ่มเดียว (สูง ~50px) + บรรทัดเล็ก “ชายแดนแอสเตอร์เวล”
2. **ปุ่มตั้งค่า (เฟือง) มุมขวาบน** 44px → แผงตั้งค่าจากด้านล่าง: บัญชี (Google, รหัสกู้คืน — เปิด account panel เดิม; เฉพาะโหมดเซิร์ฟเวอร์), เสียง (เพลง/เอฟเฟกต์ ใช้ settings เดิม), การบันทึก (บันทึกบนเซิร์ฟเวอร์ ↔ เล่นในเครื่องแทน, ใช้สวิตช์ `?server=off` เดิม), **เริ่มเกมใหม่** สีแดง ต้องยืนยัน (ย้ายออกจากหน้าหลักเมื่อมีเซฟ)
3. **ป้าย “เซิร์ฟเวอร์ทดลอง”** มุมซ้ายบน (เฉพาะโหมดเซิร์ฟเวอร์) แทนข้อความ 2 บรรทัด
4. **ข้อความแจ้ง** (`titleNote`, migration note) เป็นป้ายลอยใต้โลโก้ หายเองในไม่กี่วินาที (`role=status`; reduced motion = ไม่มีแอนิเมชัน)
5. **นำเข้าเซฟเดิม (D11)**: กรอบเดียวกัน — หัว “พบเซฟเดิมในเครื่องนี้” + ชิป, ปุ่มหลัก “นำเข้าเซฟเดิม →”, ปุ่มรอง “เริ่มใหม่บนเซิร์ฟเวอร์” (44px), บรรทัดเล็ก “นำเข้าได้ครั้งเดียวต่อบัญชี · เซฟในเครื่องยังอยู่”
6. ไม่มีเซฟ: ปุ่ม “เริ่มเกม →” ปุ่มเดียว

ข้อกำหนดเดิมยังใช้: touch ≥ 44px, focus คีย์บอร์ด, ข้อความ DOM, กรอบภาพเดียวกว้างไม่เกิน 480px ([UI_INPUT_RULES](../../../context/UI_INPUT_RULES.md))
