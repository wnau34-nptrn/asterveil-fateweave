# แชตโลก ตลาดกลาง และกระดานเควสต์รายวัน/รายสัปดาห์

27 ตุลาคม 2026 (Asia/Bangkok) · เจ้าของขอเพิ่มสามระบบเข้าเกมและขอคำแนะนำ ขอบเขตรอบนี้เป็นแผน/สเปกตั้งต้น ยังไม่เปิด runtime หรือ backend ตัวเลขทั้งหมดที่เสนอเป็นค่าทดลอง

อ่านร่วม [แผนรวม](../DEVELOPMENT_PLAN_TH.md), [World Boss/กวาดล้าง](WORLD_BOSS_SWEEP_TH.md) และ [Game Detail](../GAME_DETAIL_TH.md)

## 1. ทิศทางที่แนะนำ

สามระบบช่วยกันคนละด้าน: แชตสร้างชุมชนและชวนปราบ World Boss ตลาดกลางทำให้ของที่เราไม่ใช้มีประโยชน์ต่อคนอื่น กระดานเควสต์เสนอเป้าหมายและแหล่งทรัพยากรที่เลือกทำได้ การเปิดต้องสัมพันธ์กับบัญชี/เศรษฐกิจ server P09 ไม่ย้ายการจ่ายเงินหรือรางวัลไปไว้ใน UI

รุ่นแรกให้เริ่มกระดานเควสต์ก่อน → แชตโลกหลังบัญชีพร้อม → ตลาดกลางหลังสินทรัพย์/ธุรกรรมตรวจสอบได้ การเตรียมข้อมูล/หน้าจอ/ทดสอบ local ทำล่วงหน้าได้ แต่ไม่กล่าวว่าการสื่อสารหรือซื้อขายข้ามผู้เล่นทำงานในเกม offline แล้ว

## 2. แชตโลก

- ช่องโลกแยกตามเซิร์ฟเวอร์และภาษา พร้อมช่องซื้อขาย/ชวนร่วมกิจกรรมเมื่อปริมาณข้อความมากพอ ไม่เปิดทุกช่องว่างพร้อมกันตั้งแต่คนเล่นน้อย
- แสดงชื่อผู้บัญชาการ/ค่ายและข้อมูลตัวตนที่ไม่สับสน เปิดดูprofile/บล็อก/รายงานได้ ห้ามการตั้งชื่อหรือmarkupทำให้ดูเป็นประกาศระบบหรือผู้ดูแล
- แชร์ลิงก์ไอเทมจากIDจริงหรือประกาศ World Boss แบบที่เซิร์ฟเวอร์สร้างได้ ไม่ให้ข้อความสร้างปุ่มซื้อ/คำสั่งซื้อหรือHTMLเอง การกดลิงก์รายการขายต้องเปิดตรวจรายละเอียดและยืนยันในตลาดเสมอ
- มีปิดเสียง ซ่อนแชต บล็อก รายงาน และขอบเขตการเก็บประวัติที่กำหนดชัดก่อนเปิด; มีเครื่องมือผู้ดูแลจำกัดสิทธิ์ ตรวจประวัติการดำเนินการได้
- จำกัดความยาว/ความถี่จากserver แสดงเหตุผลเมื่อส่งไม่ได้ ทดสอบสแปม/การเลี่ยงmute/reconnectและXSSจากข้อความ ไม่ใช้การกรองคำอย่างเดียวแทนการดูแล
- บนจอ390pxใช้แผงเปิดปิดได้ ไม่บังเจตนาศัตรูหรือเป้าหมายกลางศึก ไม่เพิ่มแถบแจ้งเตือนทุกข้อความ; accessibility/reduced motionและfocusเป็นงานตรวจรับ

ค่าความยาวข้อความ rate limit ประวัติที่เก็บ และกำลังดูแลยังต้องกำหนดจากผู้ใช้งานจริง ไม่เปิดระบบก่อนมีผู้รับผิดชอบการดูแล แชตไม่มีรางวัลจากจำนวนข้อความเพราะจะจูงใจspam

## 3. ตลาดกลางรุ่นแรก: ตั้งราคาขายด้วยทอง

แนะนำ **รายการขายราคาคงที่ ใช้ทองที่ server ตรวจสอบได้** ผู้ซื้อเลือกสินค้าและกดยืนยัน ได้ของชิ้นจริง ผู้ขายได้รับทองหลังหักค่าธรรมเนียม ไม่มีสกุลเงินตลาดใหม่โดยอัตโนมัติ การเสนอราคา/barterหรือแลกตรงระหว่างสองคนเป็นงานต่อยอด ไม่บังคับทำพร้อมรุ่นแรก

| ประเภท | แนวทางเริ่มต้น |
|---|---|
| อุปกรณ์ดรอป/คราฟต์ที่ยังไม่ผูกตัว | ขายได้เมื่อที่มาและการลงทุนทั้งหมดอยู่ในserver ledger; ต้องถอดออกจากตัวและไม่ถูกlockอื่น |
| ของที่ซื้อจากตลาด | ผูกบัญชีทันทีในต้นแบบ เพื่อลดการวนซื้อไปขายต่อ; แสดงก่อนยืนยัน |
| ของที่สวมใช้แล้ว | ผูกบัญชีในฐานแนะนำใหม่; ของเก่าต้องมีmigrationชัด ไม่ยึดของหรือแอบลดทุน |
| วัตถุดิบ/สูตร/ของตกแต่งในอนาคต | เพิ่มทีละallowlist หลังตรวจsupply/demandและการผูกบัญชี; ไม่เปิดทั้งinventoryโดยdefault |
| ตัวละคร เศษดาว ตั๋วกาชา ของเควสต์/รางวัลเฉพาะสิทธิ์ | ไม่นำเข้าตลาดรุ่นแรก เพื่อรักษาเส้นทางสะสมและสิทธิ์เนื้อเรื่อง |

มีตัวกรองอาชีพ/ช่องใส่/ระดับ/affix/ราคา แสดงค่าทั้งหมดและเงื่อนไขสวมได้ก่อนซื้อ ดูราคาขายสำเร็จแบบaggregateได้เมื่อมีข้อมูลเพียงพอ ไม่แสดงราคาlistingว่าเป็นราคาขายจริง

ค่าต้นแบบเพื่อจำลอง: ค่าธรรมเนียม5%จากยอดขายสำเร็จเท่านั้น ไม่มีค่าลงประกาศล่วงหน้าและไม่เก็บค่าเสียหายเมื่อลงแล้วขายไม่ได้ ต้องกำหนดrounding/ขั้นต่ำของค่าธรรมเนียมเพื่อกันราคาจิ๋วเลี่ยงภาษี รวมจำนวนช่องขาย อายุประกาศและเพดานราคา/ยอดเงินก่อนเปิดจริง ไม่ขายช่องลงประกาศในรุ่นทดลอง

ตลาดช่วยหาของที่ขาด แต่ยังมีทางฟาร์ม/คราฟต์ของรับมือบอสเอง บอสหลักไม่บังคับซื้อจากผู้เล่นอื่น ประเมินการฟาร์มทอง/อุปกรณ์จากกวาดล้าง กระดานเควสต์และ World Boss ร่วมกันก่อนเลือกค่าธรรมเนียมหรือราคาที่เหมาะสม

## 4. ธุรกรรมและสิทธิ์ไอเทม

รายการขายถือของในescrow: itemUIDเดียวต้องไม่ถูกสวม คราฟต์ ย่อย โอน หรือลงขายซ้ำได้ระหว่างlisting การเปลี่ยนราคาทำผ่านrevisionและlockเดียวกัน ไม่แก้item payloadจากclient

ซื้อสำเร็จต้องเปลี่ยนสถานะlisting/หักgold/โอนitem/ตั้งbinding/บันทึกยอดรับสุทธิและfeeในtransactionที่สอดคล้องกัน ห้ามวางธุรกรรมหลายบัญชีบนDOแยกกันแล้วสมมติว่าatomicเอง ต้องออกแบบD1 transactionหรือcoordinator+reconciliationที่ตรวจพิสูจน์ได้ก่อนimplement

ตรวจพร้อมกัน: ผู้ซื้อสองคน รายการหมดอายุพร้อมซื้อ cancelพร้อมซื้อ จำนวนเงินไม่พอ retryหลังtimeout serverล้มระหว่างขั้นตอน และคลังเต็ม ผู้ซื้อ/ผู้ขายต้องกู้ผลได้ผ่านreceipt ไม่ได้เงิน/ของซ้ำ เมื่อขายไม่ออกคืนของชิ้นเดิม; ถ้าพื้นที่ไม่พอใช้claim inboxที่ไม่ทิ้งของหรือยึดค่าธรรมเนียมซ้ำ

ปิดself-buyและตรวจสินทรัพย์ที่ไม่eligibleตามserver ledger กฎเวลาจากserver ส่วนอุปกรณ์/ทองจากเซฟofflineเดิมต้องมีนโยบาย P09 ก่อนเข้าตลาด ห้ามเชื่อยอดแก้ได้ในเครื่องแล้วใช้ซื้อของที่โอนไปผู้อื่นได้ หากพิสูจน์ที่มาไม่ได้ให้คงสิทธิ์ใช้งานเดิมและแยกeligibilityซื้อขาย พร้อมอธิบายชดเชย/เส้นทางเข้าสู่online economyก่อนเปิด ไม่กำหนดอัตราแปลงโดยพลการในรอบนี้

## 5. กระดานเควสต์รายวัน/รายสัปดาห์

แนะนำกระดานเดียวในค่าย แยกแท็บรายวัน/รายสัปดาห์/สัญญาจ้าง เควสต์เรื่องและเควสต์สะสมเดิมยังอยู่ ไม่เปลี่ยนเควสต์ค่ายหกงานที่claimครั้งเดียวให้วนรับได้เงียบๆ

ค่าต้นแบบ: รายวันสามงานสั้นที่ทำร่วมกับการเล่นปกติได้ รายสัปดาห์ห้างานที่คืบหน้าจากหลายกิจกรรม ไม่บังคับเข้าเล่นทุกวันเพื่อผ่านรายสัปดาห์ ตัวอย่างชนิดงาน:

| ช่วง | ตัวอย่าง | เงื่อนไขออกแบบ |
|---|---|---|
| รายวัน | รับทรัพยากรจากด่านที่ปลดแล้ว/ทำสัญญาจ้าง/ใช้ทีมผ่านศึก | มีทางเลือกงานประเภทเดียวกัน ไม่บังคับตัวกาชาหรืออาชีพที่ยังไม่มี |
| รายสัปดาห์ | เคลียร์กิจกรรมหลายเที่ยว/ใช้กลไกรับมือบอส/ทำเรื่องเสริม | ไม่เท่ากับทำdailyครบเจ็ดวัน ไม่บังคับจ่ายทอง/ซื้อของ/สุ่มเพื่อผ่าน |
| Onlineกิจกรรม | ร่วม World Boss | แสดงหลังระบบ/กิจกรรมพร้อม และมีทางเลือกเทียบเท่าช่วงบอสปิดหรือระบบมีปัญหา |

Progressรับอัตโนมัติจากเหตุการณ์ที่serverยืนยันหลังปลดกระดาน ไม่ต้องรับเควสต์ทุกครั้งก่อนเล่น แสดงตัวนับและเงื่อนไขชัด รางวัลใช้ทรัพยากรเดิมตามงบ P04 เช่นทอง/แร่/ตำรา/เศษดาว; ไม่เพิ่มdailycoin/weeklycoinอีกสองชนิด

ฐานลดภาระที่แนะนำ: dailyที่ได้รับสิทธิ์แล้วเก็บงานค้างได้ถึงสามชุด และมีช่วงclaimย้อนหลังที่แจ้งชัด ไม่พกแต้มทุกวันทบไม่มีที่สิ้นสุด; จำนวนชุด ระยะclaim และกติกาเปลี่ยนprogressจากกิจกรรมหนึ่งไปนับชุดใดต้องจำลองก่อนเลือกจริง weeklyทำได้เป็นช่วงภายในสัปดาห์ การล็อกอินอย่างเดียวไม่มอบงานย้อนหลังทั้งหมดโดยไม่มีเงื่อนไข

Daily/weekly boundaryระบุtimezoneเดียวบนหน้าจอและใช้serverเวลา เก็บperiodIDและquestInstanceID; เปลี่ยนนาฬิกา/เดินทางข้ามtimezone/โหลดเครื่องอื่นไม่สร้างชุดเพิ่ม คำสั่งclaimผูกperiodและreceiptครั้งเดียว การเปลี่ยนobjectiveversionกลางperiodต้องรักษาความคืบหน้า/ชดเชยอย่างมีบันทึก

กวาดล้างนับได้เฉพาะobjectiveที่ระบุว่ารับทรัพยากร/กวาดล้าง ไม่ปลอมcombat eventsเพื่อผ่านงานใช้สกิล ขัดจังหวะ สำรวจหีบ หรือบทสนทนา ไม่ให้การซื้อขายตนเอง/ส่งแชต/ลงประกาศซ้ำเป็นช่องปั๊มรางวัล
