# ระบบเพื่อน + แชทส่วนตัว 1:1 (OD-56) — 2026-11-19

เจ้าของ 2026-11-19: "เพิ่มระบบเพื่อน และ chat 1:1" (OD-56) ต่อจาก [CHAT_CHANNELS_TH.md](CHAT_CHANNELS_TH.md) §2 (ทำตามข้อแนะนำเดิมทั้งหมด) ไม่แตะกติกา เซฟ หรือรางวัล — สถานะทั้งหมดอยู่บนเซิร์ฟเวอร์ ไม่มีการเปลี่ยนรูปแบบเซฟ

## 1. ผู้เล่นเห็นอะไร
- หน้าต่างแชท → แท็บ **เพื่อน** (เดิม "แชทส่วนตัว · เร็ว ๆ นี้"): รหัสเพื่อนของฉัน (คัดลอก / ขอรหัสใหม่ แตะสองครั้ง), ช่องใส่รหัสเพื่อน, คำขอที่ได้รับ (รับ / ปฏิเสธ / บล็อก), รายชื่อเพื่อน (n/50) พร้อมจุดข้อความใหม่, ⋯ → ลบเพื่อน / บล็อก (ยืนยันด้วยการแตะซ้ำ), คำขอที่ส่งไป (ยกเลิก), ค่ายที่บล็อกไว้ (เลิกบล็อก)
- แตะชื่อเพื่อน → ห้องแชทส่วนตัว: ‹ เพื่อน / ชื่อ / บล็อก, ข้อความ, ⋯ ที่ข้อความของเพื่อน → แจ้ง 4 เหตุผล, ช่องพิมพ์ 160 ตัว
- ปุ่มแชทบนค่ายมีป้ายตัวเลขข้อความส่วนตัวที่ยังไม่อ่าน แท็บเพื่อนมี "ใหม่ n"; แถบแชทใสบนค่ายยังเป็นแชทโลกอย่างเดียว
- ชื่อที่เห็นคือชื่อแฝง `ค่าย-XXXXX` เดิม · ออฟไลน์ปุ่มแชทยังปิดพร้อมเหตุผล · ขนาด 390px ปุ่ม ≥44px, ใช้คีย์บอร์ดได้, Esc ปิด

## 2. กติกา (ฝั่งเซิร์ฟเวอร์ตัดสิน)
- **รหัสเพื่อน** 8 ตัวจากชุดอักษรไม่กำกวม (ไม่มี 0/O/1/I) แสดง `XXXX-XXXX` สุ่ม ไม่ได้มาจาก id บัญชี เก็บใน D1 ขอใหม่ได้ (รหัสเดิมใช้ไม่ได้ทันที คำขอที่ส่งมาแล้วยังอยู่) พิมพ์ตัวเล็ก/เว้นวรรค/ขีดได้
- **ส่งคำขอด้วยรหัส** เป็นการค้นหาทางเดียว ต่างฝ่ายต่างขอ = เป็นเพื่อนทันที **ไม่ให้เดารหัสได้**: รหัสไม่มีจริง, ค่ายนั้นบล็อกเรา, บัญชีรอลบ, กล่องคำขอของเขาเต็ม → ตอบเหมือนกันหมด (404 `friend_code_unavailable`)
- เป็นเพื่อนต้อง **ยอมรับทั้งสองฝ่าย** · ลบเพื่อนมีผลทั้งสองฝ่าย · **บล็อกระดับบัญชี** (ทุกเครื่อง): ตัดเพื่อนและคำขอทั้งสองทาง คนถูกบล็อกส่งคำขอ/ข้อความไม่ได้ บล็อกได้จากเพื่อน คำขอเข้า/ออก หรือในห้องแชท
- **แชท 1:1** เปิดเฉพาะเพื่อนกันสองฝ่ายและไม่มีใครบล็อกใคร Worker สร้าง id ห้อง `dm:<a>:<b>` จากบัญชีที่ยืนยันแล้ว + บัญชีของเพื่อน (อุปกรณ์ส่งแค่ `ref` สุ่ม 16 hex ที่ผูกกับแถวของตัวเอง ไม่เคยเห็น id บัญชี) ไม่ใช่เพื่อนแล้ว → 403 `not_friends`
- ตัวกรองเดียวกับแชทโลก (ลิงก์/อีเมล/เลขยาว/คำหยาบ), mute ของผู้ดูแลมีผลด้วย, `CHAT_WRITE` มีผลด้วย
- **แจ้งข้อความส่วนตัว**: เก็บ 5 ข้อความก่อนหน้าไว้กับรายงาน ผู้ดูแลเห็นเฉพาะข้อความที่ถูกแจ้ง + บริบทนั้น (ไม่เห็นห้องทั้งห้อง) การเปิดดูบันทึก `admin_audit` (`chat_read`) แจ้งแชทโลกไม่ไปโดนข้อความส่วนตัว
- **ข้อความใหม่**: ตัวบอกว่าอ่านถึงไหนต่อบัญชีต่อห้องใน DO แชท (เปิดห้อง = อ่านแล้ว, ตอบ = อ่านแล้ว)
- **ลบบัญชี** (purge): รหัส, เพื่อนทั้งสองฝ่าย, คำขอ, บล็อก (ทั้งที่บล็อกและถูกบล็อก) ใน D1 + ทุกห้องแชทส่วนตัวของบัญชีนั้น (ข้อความทั้งสองฝ่าย), ตัวบอกอ่านถึงไหน, บริบทรายงานที่มีบัญชีนั้น ช่วงรอลบ บัญชีนั้นหายจากรายชื่อของคนอื่นและส่งข้อความหาไม่ได้ (กลับมาถ้ายกเลิกการลบ)
- การอ่าน: polling แบบแชทโลก ไม่มี WebSocket — รายชื่อทุก 10 วินาที ห้องที่เปิดทุก 4 วินาที **เฉพาะตอนแท็บเพื่อนเปิดและหน้าจอมองเห็น** ป้ายบนค่ายอ่านซ้ำได้ไม่เกินนาทีละครั้งตอนเข้าหน้าค่าย

## 4. ที่เก็บและสวิตช์
- D1 migration `cloudflare/migrations/0007_friends.sql`: `friend_codes`, `friend_requests`, `friends` (สองแถวต่อคู่ แต่ละฝ่ายมี ref ของตัวเอง), `friend_blocks` — อยู่ข้างตาราง accounts แบบ P09 ลบพร้อมบัญชีใน `purgeDue`
- ข้อความส่วนตัวอยู่ใน DO `Chat` เดิม (ตาราง messages ช่อง `dm:`) + ตาราง `reads`, `report_context` Worker เท่านั้นที่เรียก DO
- **สวิตช์ `FRIENDS`** (Worker variable ใน `cloudflare/wrangler.json`, ค่าเริ่ม `on`): `off` = เส้นทาง `/v1/friends*` และห้องส่วนตัวตอบ 403 `friends_off` (แท็บเพื่อนแสดง "ระบบเพื่อนปิดชั่วคราว") แชทโลกไม่เปลี่ยน ปิดได้ทันทีที่ Cloudflare dashboard → Worker `asterveil-api-dev` → Settings → Variables (ไม่ต้อง deploy โค้ด; deploy ครั้งต่อไปจะใช้ค่าใน wrangler.json อีก ให้แก้ไฟล์ด้วยถ้าจะปิดถาวร) ข้อมูลไม่หายเมื่อปิด
- เส้นทาง: `GET /v1/friends`, `POST /v1/friends/{request,respond,cancel,remove,block,unblock,code}`; แชท `GET /v1/chat?channel=dm&friend=<ref>`, `POST /v1/chat/send|report` + `{ channel: 'dm', friend }`

## 5. คำถามให้เจ้าของ (ทำตามข้อแนะนำไปก่อน ไม่ได้รอ)
1. บล็อกควรซ่อนข้อความของค่ายนั้นในแชทโลกด้วยไหม — ตอนนี้ **ไม่** (แชทโลกยังใช้ "ซ่อนค่ายนี้บนเครื่องนี้" แยก เพราะชื่อแฝงในแชทโลกผูกกับบัญชีที่ Worker ไม่ส่งให้อุปกรณ์)
2. เพื่อนสูงสุด 50 พอไหม
3. ช่วงทดสอบภายนอกจะเปิด 1:1 ไว้หรือปิดด้วย `FRIENDS=off` — ตอนนี้ **เปิด**
