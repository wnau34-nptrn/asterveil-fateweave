## 2. รูปแบบภาพที่ใช้ร่วมกัน

**โทน:** แฟนตาซีวาดสีแบบเดิม พลังฟ้า–ทอง/มิ้นต์สำหรับทีม ม่วงรอยแยกสำหรับศัตรู เส้นหลักคม ขอบแสงนุ่ม ฝุ่นอยู่ต่ำ ประกายระเบิดในวงเล็กและหายเร็ว คงตัวละคร/อาวุธ/ภูมิทัศน์เดิม

**ลำดับความเด่น:** การตัดสินใจ/เป้าหมาย/HP → จุดปะทะ → บรรยากาศ ฉากเปิดเต็มกรอบเฉพาะก่อนเริ่มศึก; ระหว่างไฟต์ HUD ไม่เคลื่อนตามการสั่นและคำสั่งสำคัญต้องอ่านได้

**ตำแหน่ง:** มี anchor อย่างน้อย `foot`, `bodyContact`, `castOrigin` ต่อ actor; จุด impact อยู่บนร่าง ไม่ใช้ foot anchor วงพื้นแทนรอยโดนทุกท่า แก้ค่าด้วยข้อมูล layout ของ canvas CSS pixels ไม่ใช้ขนาด texture/DPR เป็นพิกัด UI

**ข้อมูลจริง:** เอฟเฟกต์เดินทางถึง resolved target เสมอ รวม Guard รับแทน/หลบ/โล่ ไม่มีชื่อ CRITICAL จาก SFX `crit` และไม่มีภาพ AoE จากชื่อ Quake/Storm ถ้าผลจริงเป็น single-target

## 3. จังหวะและ cue

ค่าปกติของทุก action อยู่ใน coverage.json; base attack 600ms, support ส่วนใหญ่ 500–750ms, offensive skill 750–1,000ms และท่าผู้คุมรอยแยก 1,200ms เวลานี้รวมการอ่านผลและคืนท่า ไม่บวกหยุด 1,000ms เดิมท้าย stage

| Preset | เตรียม | เดินทาง/รวมพลัง | apply/contact | รับแรง/ผลรอง | คืนท่า/จบ |
|---|---|---|---|---|---|
| โจมตีธรรมดา D=600ms | 0–90 | 90–210 | 210 | 210–420 รวม visual hold 40ms | 420–600 |
| กายภาพสกิล D | 0–0.18D | 0.18–0.38D | 0.38D | ถึง 0.78D รวม hold 50–70ms | ถึง D |
| เวทสกิล D | 0–0.25D | 0.25–0.45D | 0.45D | ถึง 0.80D รวม hold 35–60ms | ถึง D |
| Support D | 0–0.20D | 0.20–0.40D | 0.40D | ถึง 0.75D; ไม่มีแรงกระแทก/hold | ถึง D |
| บอสท่าหนัก D=1,200ms | 0–360 | 360–540 | 540 | 540–980 รวม hold ไม่เกิน 90ms | 980–1,200 |

หากผลรองทำให้ต้องอ่านนานกว่า D ให้ขยายจบ stage ตาม cue สุดท้ายพร้อมช่วงอ่านอย่างสั้น ไม่ตัด reaction ทิ้งและไม่ซ้อนผลของ actor ถัดไป ตัวเลข proposal นี้ไม่ใช่เวลาที่วัดจาก baseline

ที่ **contact** cue เดียว: เริ่มเสียงสัมผัส + flash + recoil + ตัวเลข + HP/barrier projection ที่เกี่ยวข้อง การเปลี่ยน status/log/inspector ต้องใช้ projection เดียวกัน ไม่เผยทั้ง final state ก่อน travel ถึงเป้า

ผลที่ต่อเนื่อง เช่น counter/reflect/leech/ฮีลแล้วให้โล่ ใช้ลำดับจริงจาก resolver ถ้า event ไม่มีข้อมูลพอสร้าง intermediate state ให้เผยเป็นกลุ่มที่ cue เดียวจนมี trace ที่ตรวจได้ในเฟส 1 ห้ามเขียนสูตรคำนวณผลใหม่ใน UI

**ความเร็ว:** เริ่มต้น normal 1× และ fast 1.5× ทั้ง cue รวม hold ต้องถูกย่อจาก clock เดียวกัน ไม่ใช้ timer อีกชุดเปิดคำสั่งก่อนภาพจบ Fast mode ยังคงข้อความ/ตัวเลขอ่านได้; ปรับจากการเล่นจริงในเฟส 4

**ลดการเคลื่อนไหว:** ปิด shake/zoom/afterimage/particle เคลื่อน ใช้ไอคอน/ตัวเลข/ข้อความและ fade สั้นโดยยังมีจุด apply เดียวกัน ไม่ทำให้ผลจริงเปลี่ยน ไม่ผูกความเร็วเกมหรือการใช้เทิร์นกับ tween

## 4. น้ำหนักเอฟเฟกต์และข้อมูลบนจอ

| ระดับ | ใช้กับ | ค่าเริ่มต้นให้ทดลอง |
|---|---|---|
| support | heal/mark/guard/song/status | ไม่มี shake/hold; glow เฉพาะผู้รับ |
| light | โจมตีปกติ/ลูกศร | field shake 1–2 CSS px; contact flash ไม่เต็มจอ |
| heavy | bash/slam/ท่าปิดคอมโบ | shake 2–3px; แสง/สะเก็ดเพิ่มเล็กน้อย |
| boss | ท่าหลัก/ปิดฉากบอส | shake ไม่เกิน 4px ในต้นแบบ; คัตอินสูงสุด 0.4s รวมอยู่ในเวลา D |

ทุกตำแหน่งคืนฐานก่อนเลือกเป้า ไม่ขยับกรอบเกมหรือ DOM target buttons ตาม shake ห้ามนำตัวเลขความแรงไปขยาย damage จริง

ตัวเลขปกติใช้ขนาดที่อ่านได้เดิมเป็นฐาน กำหนดช่อง damage/heal/barrier ให้แยกกันและเลี่ยงพื้นที่ HP/status; เมื่อเป้าเดียวมีหลายผล ให้เรียงตาม event หรือใช้สองช่อง ไม่ลอยซ้อนข้อความตรงเดียว ตรา/เครื่องหมายอยู่ใน reserved panel เดิม เอฟเฟกต์ตกแต่ง pointer-transparent

ชื่อเสียงสัมผัสเป็น cue งานศิลป์ ไม่ใช่กติกาใหม่ การโจมตีพื้นฐานอาจใช้ภาพต่างกันตามอาชีพโดย resolver ใช้ action `attack` เดิม Mage/Priest ใช้แสงยิง, Archer ลูกศร, Spear แทง, Knight/Duelist/Scout เส้นอาวุธ, Warden ค้อน, Alchemist เส้น/ละอองตามอาวุธเดิม, Bard คลื่นเสียง ทั้งหมดเป็นข้อเสนอภาพที่ต้องเทียบ art จริงก่อนทำ

## 5. Storyboard ผู้คุมรอยแยก

ใช้ Sentinel ทอง–ม่วงของ `rift-warden` เดิม ชื่อ “ผู้คุมรอยแยก” ไม่ใช้วาร์กอธ ไม่เพิ่มอาวุธ องค์ประกอบร่าง ปีก ผู้ติดตาม หรือเรื่องราวใหม่ ข้อความฉายาเริ่มต้นละไว้จนจำเป็นเพื่อให้ชื่ออ่านทัน ไม่มีเสียงพากย์ในชุดแรก

| Shot / ช่วงเวลา | ภาพที่ต้องจัด | เสียง/ข้อความ | เปลี่ยนผ่าน |
|---|---|---|---|
| B01 / 0–0.5s | ปลายภาพแผนที่หรี่ลง เส้นรอยแยกม่วงเปิดกลางกรอบ | rift-open ต่ำ; duck เพลงชั่วคราว | fade สั้นต่อจาก transition เดิมเพียงชุดเดียว |
| B02 / 0.5–1.2s | เงา Sentinel ค่อยเผย แสงตามรอยเกราะและเศษหินเล็ก | charge/stone movement | เคลื่อนชั้นฉากช้าต่างกัน; ไม่ zoom ทั้ง HUD |
| B03 / 1.2–2.2s | ภาพใกล้เกราะ/ศีรษะที่ไม่เปลี่ยนดีไซน์ | แสดงชื่อบอสหนึ่งบรรทัด | แผ่นชื่อไม่บดปุ่มข้าม |
| B04 / 2.2–2.8s | ลงน้ำหนัก วงฝุ่นต่ำและแสงรอยเกราะ | heavy-step/metal-stone; เข้าสู่เพลง boss เดิม | impact เฉพาะชั้นฉาก |
| B05 / 2.8–3.2s | คืนสนาม/ตำแหน่งจริง แล้วแสดง HP/intent | คืนระดับเพลงตามผู้ใช้ตั้ง | เข้าจุด Start/ลำดับเริ่มศึกจริง ไม่ออกคำสั่งเอง |

**Farm 0.8s:** 0–0.2 เผยรอยแยก/เงา → 0.2–0.55 ชื่อบอส → 0.55–0.8 คืนสนาม; ไม่มีการเปิดฉากเต็มซ้ำก่อนชุดนี้

**Reduced-motion:** ไม่มี parallax/shake/zoom; เปลี่ยนฉากด้วย fade สั้น ชื่อคงอ่านได้บนหน้าเริ่มศึก ไม่บังคับให้ผู้เล่นอ่านใน 100ms

**ข้าม:** ปุ่ม “ข้าม” ≥44px อยู่มุมบนใน safe area ของกรอบเกมตั้งแต่ต้น ยกเลิก cue/เสียง/duck ทั้งหมด คืนระดับเสียงเดิมและไปจุดเริ่มศึกเดียวกับการดูจบ กรอง pointer/key ที่ปิดฉากไม่ให้กด Start/เป้าหมายต่อเอง

**เคยดูแล้ว:** preference แยก progression ค่าเริ่มต้นฉากเต็มครั้งแรก; การดูจบหรือกดข้ามโดยเจตนานับว่าเคยดู การ reload/ปิดแท็บกลางฉากไม่เขียนว่าเคยดู และเมื่อกลับมาพบ active encounter ที่บันทึกไว้ให้ resume ศึกแทนเล่น intro วน เฟส 1–3 ต้องตรวจ compatibility จริงก่อนลงรายละเอียด storage

## 6. Storyboard ท่าหลักและพ่ายแพ้

**Crushing Blow (รวม 1.2s):** เกราะชาร์จทอง 0–360ms → ลงท่า 360–540 → impact/เสียงหิน/HP 540 → hold 70–90 และฝุ่น/รับแรงถึง 980 → คืนท่า 1,200 ถ้า cancel/interrupted ให้ใช้รูปท่าที่ถูกหยุดและข้อความที่ตรง event แทนการทุบสำเร็จ Guard ต้องเชื่อมผู้คุ้มกันและผู้รับจริง

**Rift Bolt (รวม 1.2s):** รวมพลังม่วง 0–300ms → ลูกพลัง/ลำแสงมีต้นทางเดินทางถึงเป้า 300–540 → impact 540 → โล่หรือ HP รับผลจริงพร้อมสลายแสง → จบ 1,200 ไม่มีภาพโดนเพื่อนคนอื่นเพิ่ม

คัตอินดวงตา/แกนเกราะ 0.25–0.4s เป็นทางเลือกเฉพาะครั้งแรกของท่าหลักและนับรวมเวลาท่านั้น ไม่บังคับในรอบฟาร์ม ไม่สร้างเฟสคลั่งหรือโบนัสโจมตีจาก HP ต่ำ

**Defeat 1.8s หลังผลชนะจริง:** 0–80ms hold โจมตีสุดท้าย → 80–500 เกราะแตกรอยแสง → 500–1,150 ทรุด/พลังสลาย → 1,150–1,500 คืนแสง → 1,500–1,800 เข้า reward view รางวัลต้องเป็นผลที่ commit แล้ว; ประกาย legendary แสดงเมื่อมี item จริง ปุ่มข้ามใช้ final outcome เดิมและไม่สุ่มซ้ำ

## 7. ข้อตกลงที่ต้องทำต่อในเฟส 1

1. นิยาม projection/trace โดยใช้ค่าที่ resolver ยืนยัน โดยเฉพาะผลรองที่ event ไม่มี snapshot/provenance พอ
2. แยก update HP/status/log ออกจาก `scene.sync → paint → stopEffects` เพื่อไม่ล้าง animation ที่ cue impact
3. รวม JS timer, Phaser timer/tween และ delayed down SFX ให้ยกเลิกด้วย session/stage เดียวกัน
4. ตรวจ initial enemy turns และ commit-before-playback; intro/skip ต้องไม่ทำให้เทิร์นเร็วหรือ reward ซ้ำ
5. ใช้ source fingerprints เทียบก่อนลงมือ หาก runtime เปลี่ยนให้สร้าง baseline ใหม่ ห้ามอ้างรอบนี้ว่ารับรองโค้ดใหม่

ครบเฟส 0 เมื่อ catalog ไม่มีช่องตกหล่น, baseline ที่ระบุไว้ทำซ้ำได้และตรวจ state จริง, สเปกกับ brief นี้พร้อมใช้งาน เฟส 1–5 ยังไม่ถูกทำเครื่องหมายเสร็จ
