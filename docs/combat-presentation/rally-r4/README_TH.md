# Rally R4 — คำสั่งตั้งรับพร้อมกัน

27 ตุลาคม2026 · **ออกแบบใหม่ตามคำขอเจ้าของ · artwork proposal ยังไม่แทน runtime**

[เปิดดูสามจังหวะที่390px](index.html) · [ภาพจุดเด่น](rally-peak-390.png) · [แผ่นสามจังหวะ](rally-board.png)

**คอนเซ็ปต์: Knight ส่งสัญญาณ → ทีมเตรียมรับแรงปะทะพร้อมกัน** แยกภาพผู้ส่งและผู้รับชัดเจน แทนเครื่องหมายพื้นอย่างเดียวของ R3

1. Knight เริ่มคลื่นคำสั่งข้างตัว สีน้ำเงิน–เงิน มีแสงทองเล็กเป็นจุดเริ่ม เพื่อนยังไม่แสดงการตอบรับ
2. คลื่นแผ่ออกเป็นสามแนว ขณะเส้นโค้งสั้นบนพื้นตอบรับพร้อมกันทั้งสี่คน เว้นตัว/ชุด/รองเท้า/HP
3. คลื่นและแสงตอบรับจางลง ไม่สื่อว่าสถานะหมดหรือโล่แตก

กลไกอ้างอิงปัจจุบัน: Rally Guard/ตั้งรับหมู่ของ Knight ลดความเสียหายครั้งแรกที่แต่ละคนได้รับ ค่าพื้นฐาน35% จนถึงเทิร์นถัดไปของ Knight ภาพไม่อ้างว่าฮีลหรือเพิ่ม barrier; talents/levelอาจปรับกลไกและค่าได้ตามข้อมูลเกมจริง

ต้นฉบับ ImageGen1536×1024 RGBA alpha0–254 มี6ภาพ: แถวบน3จังหวะคำสั่ง แถวล่าง3จังหวะตอบรับ แยก source/promptที่ `incoming/ART-VFX-DEFENSE-001/proposals/rally-r4/` เก็บ original byte-for-byte พร้อม promptรอบแรกและรอบปรับ ไม่มี scriptวาด/แก้pixelของต้นฉบับ

วางคำสั่งข้าง Knight สูงสุด68×42px, dx85/dy22จากbody; ตอบรับสูงสุด90×14px, feet dy27 ใช้scaleร่วมในแต่ละแถว รูปทั้งหมดคอมโพสิตบนภาพสนามจริง390×844เดิม UI/HPคงเดิม ไม่มี AIวาดตัวละครหรือUIใหม่ เป็นภาพออกแบบ ไม่ใช่ผลต่อสู้หรือคลิปruntime

`build.py` วิเคราะห์alphaและสร้างmanifest/hashเท่านั้น; `viewer.js` คอมโพสิตสองส่วนตามphase; `capture.mjs` สร้างภาพ390px/1170×950และตรวจcontrolในbrowser

```sh
python docs/combat-presentation/rally-r4/build.py
# เมื่อ Vite เปิดที่5173:
node docs/combat-presentation/rally-r4/capture.mjs
```

ตรวจต้นฉบับและcompositeสามจังหวะที่390pxด้วยตา ผ่านcontrolเทียบสนามเปล่า/น้ำหนัก/คืนค่า/เลื่อนphase ไม่มีpageerrorหรือstorage write; lint/diffผ่าน Chromium cloud ไม่ใช่เครื่องจริง

R4เป็นข้อเสนอใหม่ตามคำขอออกแบบ ไม่ได้อนุมานว่าเจ้าของอนุมัติR3หรือท่าอื่น Production source/atlas/moduleและคลิปเดิมยังไม่เปลี่ยน รอเลือกภาพแล้วจึงต่อruntime/อัดRallyใหม่ในPR#77ใบเดิม ไม่เริ่มตระกูล3
