## 1. ใช้เอกสารนี้อย่างไร

เจ้าของขอรวบรวมข้อมูลทั้งหมดและส่งแผนเข้า GitHub เอกสารนี้เป็นจุดเริ่มอ่านลำดับงาน รวมของที่มีจริง แผน A–D/C12 เดิม งานวิจัย และทิศทางใหม่เรื่องทีมสูงสุดห้า/เลเวลร่วม/บอสใช้กลไก ไม่ใช่รายงานว่าระบบใหม่ทำเสร็จแล้ว และการเผยแพร่แผนไม่ทำให้ตัวเลขเสนอทั้งหมดกลายเป็นค่าที่ผ่านสมดุล

สถานะในแผน:

- **มีแล้ว:** ตรวจจาก source หลัง C12 Batch 1; การทดสอบเก่าเป็นหลักฐานของรุ่นนั้น ไม่ใช่ผลยืนยันระบบใหม่
- **ทิศทางเจ้าของ:** เป้าหมาย 15×2, แนวห้าดาวแล้วเลื่อนขั้นต่ออีกห้าดาว/พัฒนาท่าเดิม และคำขอเลเวลเท่ากันเพื่อสลับเล่น
- **ฐานแนะนำ:** รายละเอียดที่เราเลือกเสนอให้เดินงานออกแบบต่อ เช่น เลเวลร่วมทั้งค่าย ทีมสูงสุดห้า หนึ่งคลาสขั้นสูงต่ออาชีพ บอสมีหลายวิธีรับมือ
- **ค่าทดลอง:** สูตรแต้ม/ดาว เวลาเข้าถึง อัตราแจก และอัตรากาชา ต้องมีแบบจำลองและผลทดสอบก่อนใช้จริง

แผนนี้จัดลำดับงานใหม่เพื่อแก้ฐานข้อมูลและระบบทีมก่อนขยายเนื้อหาที่พึ่งพามัน ภายในแต่ละระยะให้ทำสเปก → กฎ/ข้อมูล → migration → UI → validation → ส่งมอบ ไม่เปิดทั้งระบบพร้อมกันใน PR เดียว ไม่สร้างขั้นขออนุมัติซ้ำสำหรับงานที่ได้รับมอบหมายแล้ว; หากผลทดลองเปลี่ยนทิศทางสำคัญให้รายงานเหตุผลและผลกระทบ

## 3. เป้าหมายเกมและสิ่งที่คงเอกลักษณ์

เกมสำรวจแผนที่ช่องสี่เหลี่ยม เดินทีละช่องสี่ทิศ คุมค่ายทหารรับจ้าง อ่านเจตนาศัตรูและจัดทีมให้รับมือได้ มีความเสี่ยงระหว่างเที่ยวและทางกลับค่าย ไม่มีธาตุ ไม่มีเพิ่มเทิร์น/เพิ่ม SPD จากดาว ต้นไม้ Bond หรือสัตว์เลี้ยง กฎคำนวณแยกจากภาพและใช้ preview/replay เดียวกัน

ฐานใหม่เพื่อพัฒนา: สะสมสมาชิกได้ครบทั้งแค็ตตาล็อก เลเวลร่วมทั้งค่าย สลับบิลด์และตัวที่ถือครองได้โดยไม่เก็บ Lv ซ้ำ ทีมสูงสุดห้าคนเป็นต้นแบบที่ต้องพิสูจน์บนจอแนวตั้ง 390px; ศัตรูหนึ่งถึงห้า ไม่บังคับทุกศึกเต็มสิบตัว

ความก้าวหน้ารายตัวอยู่ที่การเลือกต้นไม้/p ดาว ขั้นอาชีพ อุปกรณ์และความผูกพัน กลไกที่ต้องใช้ผ่านบอสหลักต้องเข้าถึงได้จากการเล่นแน่นอน ตัวใหม่จากกาชาเพิ่มทางเลือกและความชอบ ไม่เป็นกุญแจเฉพาะชื่อเพื่อผ่านเรื่อง

## 8. เกณฑ์คุณภาพและการปล่อยแต่ละชุด

1. สเปกระบุที่มาของกฎและข้อเปลี่ยนจากแผนเดิม; แยก code-complete, test-complete และผล playtest มนุษย์
2. กฎเปลี่ยนต้องอยู่ใน pure resolver/content ก่อน UI; preview=resolve=replay, no double reward, stable IDs, legal targets, no cooldown/turn loops
3. แก้เซฟต้องมี fixture ของรุ่นที่รองรับ อธิบายการชดเชยและการย้อนกลับ กรณีศึกค้างตรวจตามกฎของมัน; เพิ่ม version ตาม schema จริง ไม่จอง v44 ไว้ให้ Batch2 โดยไม่ดูงานที่แทรก
4. รัน typecheck/lint/unit/build สำหรับ runtime; UI/input เพิ่ม focused browser tests และภาพ390px; full browser suiteตามCI; docs-onlyตรวจเนื้อหา ลิงก์และdiff ไม่ต้องอ้างว่าทดสอบgameplayใหม่
5. สมดุลเปรียบฐานกับรุ่นใหม่ด้วย policy/seed/ทุนเท่ากัน และ audit แยกต้นเหตุของ regression; ไม่ใช้simอย่างเดียวตัดสินความสนุกหรือความเข้าใจ
6. บอสหลักมีสองคำตอบที่ทดลองผ่านจริง หนึ่งทางรับประกันการเข้าถึง ตรวจทุก starter route ที่เกี่ยวข้อง; ไม่มี exclusive gacha hard gate
7. สลับตัว Lvเดียวกันแล้วท่าจำเป็นใช้งานได้จริง แม้ดาว/ตำราน้อย; ตรวจชดเชยความต่างอุปกรณ์โดยไม่แจกของซ้ำ
8. เส้นทางส่งมอบ: task branch → PR ไป `feature/fateweave-initial-prototype` → checks → merge → Pages ตาม workflow เดิม; บันทึก handoff/commit/หลักฐาน/ข้อจำกัดทุกครั้ง ไม่เปลี่ยน visibility หรือข้ามสาขาไป `main`
