# R5 — โหมด server: เดินตามจังหวะนิ้ว ไม่รอเซิร์ฟเวอร์ทีละก้าว (20 พ.ย. 2026)

เจ้าของ: “ต่อ R5 เลย” — ต่อจาก R3/R4 ([บันทึก](../perf-r3-r4-2026-11-20/README_TH.md)) และรายงาน audit (C3) บน branch `claude/perf-audit-2026-11-20` ไม่เปลี่ยน API, protocol (requestId/seq), กติกา หรือเซฟ: เซิร์ฟเวอร์ยังได้คำสั่ง `move` ทีละคำสั่งตามลำดับเหมือนเดิม

## ปัญหาเดิม

`game-shell.ts` เก็บก้าวที่กดระหว่างรอคำตอบได้ 1 ก้าว (`nextMove`, ล่าสุดชนะ) และก้าวนั้นยังไม่ขยับตัวละครจนคำตอบกลับ — RTT 300 ms กดทุก 200 ms ก้าวหาย 1/8 และก้าวที่ค้างขยับช้า 230–290 ms

## สิ่งที่เปลี่ยน (`src/ui/game-shell.ts`)

- `guesses`: ก้าวที่แสดงบนเครื่องแล้วแต่ยังไม่ยืนยัน (สูงสุด 3 ช่องล่วงหน้า) แต่ละก้าวเดาจากตำแหน่งที่เดาไว้ก่อนหน้าด้วยกติกาแผนที่สาธารณะชุดเดียวกับเซิร์ฟเวอร์ (`applyCommand` บนเครื่อง) ตัวละครขยับทันที
- ส่งไปเซิร์ฟเวอร์ทีละคำสั่งตามลำดับเมื่อคำตอบก่อนหน้ากลับ (คำขอเดียวต่อครั้งเหมือนเดิม; seq ต่อเนื่อง)
- คำตอบตรงกับที่เดา (`moved` ช่องเดียวกัน) → รับสถานะเซิร์ฟเวอร์ ตัวละครค้างที่ก้าวไกลสุด แล้วส่งก้าวถัดไป
- คำตอบไม่ตรง (เจอศึก, อีเวนต์, ถูกปฏิเสธ, ไปคนละช่อง) → ทิ้งก้าวที่เหลือ แล้วแสดงสถานะจริงของเซิร์ฟเวอร์ตามเดิม (ตัวละครกลับไปช่องที่เกิดเหตุ)
- ก้าวที่เดาว่าทำมากกว่าเดิน (ดันหิน, คันโยก, รูน, ทางลับ) หรือถึงเป้าหมาย ไม่ต่อคิวจนกว่าจะยืนยัน; มีหน้าต่าง/เรื่องเล่า/ศึกเปิดขึ้น หรือเกิดปัญหาเซิร์ฟเวอร์ → ล้างคิว

## ความเสี่ยงที่ยอมรับ

ถ้าเดินล่วงหน้าแล้วเซิร์ฟเวอร์สุ่มเจอศึกที่ก้าวแรก ตัวละครจะเห็นเดินไปไกลสุด 3 ช่องแล้วกระโดดกลับไปช่องที่เจอศึก (เดิมไม่เกิด เพราะไม่แสดงล่วงหน้า) ปรับเพดาน `MAX_AHEAD` ได้
