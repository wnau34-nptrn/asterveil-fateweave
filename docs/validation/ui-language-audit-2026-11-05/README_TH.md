## ข้อค้นพบ (เรียงตามผลกระทบ)

ค่าทั้งหมดเป็น computed CSS ที่ 390×844 เว้นแต่ระบุ

1. **หัวหน้าต่างมี 9 แบบ ปุ่มปิดอยู่ 5 ตำแหน่ง 2 รูปทรง ปุ่มย้อนกลับมี 3 แบบ** — แผ่นค่าย: ธงไอคอน + หัวเรื่อง 19px ชิดซ้าย, ปิดที่ (333, 11) (ทีมเลื่อนเป็น y 19); ช่าง: ย้อนกลับ + หัวเรื่อง 20px **กึ่งกลาง** ปิดที่ (321, 17) เพราะกรอบเยื้อง 8px; กระเป๋า: ย้อนกลับ (13, 11) + หัวเรื่องกึ่งกลาง; ตัวละคร: หัวเรื่อง 16px "ชื่อ · Lv · ★" ปิดที่ (336, 18) ไม่มีย้อนกลับ; ไดอะล็อกแผนที่: หัวเรื่อง 20px ปิดที่ (336, 8); ข้อมูลต่อสู้และคำอธิบายสกิล: ปุ่มปิด **มุม 10px** (ที่อื่น 50%); สรุปเดินทาง 28px/700 และรางวัลศึก 24px ไม่มีปุ่มปิด ย้อนกลับเป็นไอคอนในหัว (ช่าง กระเป๋า), เป็นปุ่มข้อความในเนื้อหา ("กลับไปป้ายจ้าง"), หรือเป็นปุ่มใน dock ("กลับไปแก้ไข" ใน review ช่าง/อัปดาว คู่กับปุ่มย้อนกลับในหัวของช่าง) ผู้เล่นต้องหาปุ่มใหม่เมื่อย้ายงาน (ตรงกับข้อ #10 ของรายงาน Codex 4 พ.ย.)
2. **ปุ่มหลัก (ทอง) มี 13 แบบ** — มุม 10/18px, สูง 44/48/52/56px, ฟอนต์ 13–18px น้ำหนัก 500/600, ไล่สี 3 สูตร (แนวตั้ง 2 สูตร, เฉียง 110°/115° ในช่างและอัปดาว) ไม่มีแบบไหนใช้ token `--primary-fill` (135°) ตำแหน่งก็ต่างกัน: dock ล่างติดขอบ (ช่าง y775, สรุป y778), กลางเนื้อหา (อัปดาว y663, เควสต์ในการ์ด), ปุ่มในแถวรายการ (ปรุงยา/ตลาด เป็นปุ่มรอง) ปุ่มรองมี 16 แบบ ทั้งเกมพบตระกูลสไตล์ปุ่ม 106 แบบและแผง 63 แบบที่ 390×844
3. **CSS แทบไม่ใช้ token Luminous Veil** — `font-size` 638 จุดใช้ token 1 จุด; `border-radius` 310/21; `padding` 483/15; `gap` 453/1; `box-shadow` 141/31; สี hex ไม่ซ้ำ 416 ค่า รัศมีที่ใช้จริงมี 14 ค่า (10, 12, 50%, 9, 999, 99, 14, 8, 16, 18, 11, 24, 20, 0) ขณะที่ token มี 6/10/16/24/pill นี่คือสาเหตุเชิงโครงสร้างของข้อ 1–2: ทุกหน้าตั้งค่าเอง
4. **ข้อความต่ำกว่า 12px ยังเหลือในหน้าต่างตัวละคร แผนที่ และต่อสู้** (หลัง #168 แก้การ์ดทีม/ต้นไม้แล้ว) — ตัวละคร 10–11px (ชื่อในแถบสมาชิก, ป้าย +N) 12–25 จุดต่อหน้า; HUD แผนที่ 9–10px (ตัวเลข HP, ป้าย "+แต้ม"); ต่อสู้ 7–9px (ชิปรอบ, ตัวเลข SPD ในคิว); ชนะศึก 9–10px; ชื่อในแถบตัวละครของหน้าทีม 11px; กระเป๋าแผนที่ 11px CSS มี `font-size` ต่ำกว่า 12px 188 จุด (8px 23, 7px 5)
5. **แผ่นบริการทับแถบนำทางไม่เหมือนกัน** — ทีมและหน้าต่างตัวละครหยุดเหนือแถบนำทาง (เห็นแถบ) แต่จ้าง กระเป๋า ฟาร์ม ปรุงยา ช่าง แผนที่ กระดานเควสต์ เต็มจอ (แถบหาย) ผู้เล่นสลับงานจากแถบได้บางหน้าเท่านั้น
6. **กรอบหน้าต่างต่างกัน** — แผ่นค่ายเต็มกว้างขอบทองจาง 25%; ช่างเยื้อง 8px ขอบทองทึบ + พื้น radial (ขอบข้างเห็นชัด); ตัวละครไม่มีขอบ; ไดอะล็อกแผนที่ไม่มีขอบ; ข้อมูลต่อสู้เยื้อง 19px ขอบขาวฟ้า — ขัดกับหลัก "ไม่มีกรอบขอบข้างในหน้าต่างเต็มจอ"
7. **การ์ดรายการ/แถว ledger ไม่เป็นแบบเดียว** — ช่างใช้ตาราง หน่วย/มี/ใช้/ได้รับ/หลังทำ (ดี); อัปดาวใช้ตาราง มี/ใช้/หลังทำ คล้ายกันแต่หัวคอลัมน์ต่าง; ปรุงยาและตลาดใส่ราคาในปุ่ม ("ปรุง · แร่ 6 ผง 2", "ซื้อ · 60"); จ้างใส่ราคาในปุ่ม; ช่างและกระเป๋าใช้ปุ่มแนวตั้ง 4–5 ปุ่มข้างการ์ด
8. **320×568**: review สร้างอาวุธ dock ล่างสูงเกือบครึ่งจอ เนื้อหา review เหลือพื้นที่เลื่อนน้อย (ใช้งานได้ ปุ่มอยู่ในจอ) ไม่พบการเลื่อนแนวนอนและไม่พบปุ่มที่กดได้ต่ำกว่า 44px ในทั้ง 3 ขนาด

## ส่วนที่ "ควรเหมือนกัน" vs "ตั้งใจต่างกัน"

- **ควรเหมือนกัน**: กลุ่ม C, D, E, ไดอะล็อกของ F, G และข้อมูล/คำอธิบายใน H — หัวหน้าต่าง ปุ่มปิด/ย้อนกลับ ปุ่มหลัก ปุ่มรอง การ์ดรายการ แถว ledger/ราคา ป้ายสถานะ แถบพับ ขนาดตัวอักษรขั้นต่ำ token รัศมี/ระยะ/เงา
- **ตั้งใจต่างกัน (คงไว้)**: ภาพเต็มจอของ A, ฉากค่ายและแถบนำทางของ B, HUD ลอยบนแผนที่ (D-pad, ปุ่มบริบท) และ HUD ต่อสู้ (คิว SPD, dock คำสั่ง, เป้าหมายบนสนาม) — ใช้ token สี/ตัวอักษรร่วมกัน แต่ไม่ต้องใช้โครงหน้าต่างบริการ

## สิ่งที่ต้องรักษา (จากรายงาน Codex 4 พ.ย. และการตรวจนี้)

- review ของช่าง/อัปดาวที่แยกผล "รับประกัน" ออกจากส่วนสุ่ม และตาราง มี/ใช้/ได้รับ/หลังทำ ก่อนจ่าย, stale/repeat guard และ receipt เดิม
- ขั้นยืนยันถอนตัวที่มีอยู่แล้ว (ไม่เพิ่มขั้นซ้ำ)
- สรุปเดินทางที่มีปุ่มกลับค่ายติดล่างแม้รายการยาว; ต่อสู้ 390×650 ยังเห็นทีมและคำสั่งครบ
- ภาพบรรยากาศค่าย/สนามรบ ตัวละคร และแผงกระดานเควสต์ใหม่ (#166) ที่ใช้รูปแบบการ์ด + ปุ่มรับในการ์ด
- พื้นที่แตะ ≥ 44px ที่ผ่านแล้วทุกหน้า และไม่มีการเลื่อนแนวนอน

## ข้อเสนอ (ส่งต่อใน `docs/handoffs/ART-UI-LANGUAGE-001.md`)

ชุด component ร่วม 8 ชิ้น: (1) หัวหน้าต่างหนึ่งแบบ ย้อนกลับซ้าย/หัวเรื่องชิดซ้าย/ปิดขวา ตำแหน่งคงที่ (2) การ์ดรายการ (3) ปุ่มหลักหนึ่งปุ่มต่อช่วงใน dock ล่าง (4) แถว ledger/ราคา (5) ป้ายสถานะ (จำนวน vs แจ้งเตือน vs ล็อก/ขาด) (6) แถบพับ (7) แผ่นข้อมูลทึบเหนือพื้นภาพ (8) สเกลตัวอักษร 12px ขั้นต่ำ — ทุกค่าอ้าง token ใน `tokens.css` (เพิ่ม token ที่ขาดได้ เช่น ขนาดหัวเรื่อง/ปุ่ม) และต้นแบบหน้าตัวแทนครบทุกกลุ่ม C–H
