# ใช้ URL เดียวสำหรับ atlas ของบอสบนแผนที่และในศึก

ภาพบอสบนแท่นใช้ `unitsUrl('units')` ร่วมกับตัวโหลด Phaser. ตัวกำหนด revision และ base path อยู่ที่เดิม. ตำแหน่งของเฟรมบน atlas และขนาดที่แสดงใช้ค่าเดิม.

## วัดก่อนและหลัง

เทียบ baseline `827756f` กับแพตช์ โดยใช้ production Pages build บน localhost และ Chromium SwiftShader ที่ viewport 390×844, DPR 3, touch และ reduced motion. เริ่มจากเซฟ v68 ใกล้แท่นบอสผู้คุมรอยแยก แล้วเดินขึ้นหนึ่งช่อง. ทดสอบสามคู่รอบสลับก่อน/หลัง ใช้ browser context ใหม่สำหรับ cold run และเปิดซ้ำใน context เดิมสำหรับ warm run. เซิร์ฟเวอร์ทดสอบตั้ง HTTP cache ของ asset เป็น 600 วินาที และปิด service worker เพื่อวัด HTTP cache โดยตรง.

| ตัววัดเฉพาะ `units.webp` | ก่อน | หลัง |
|---|---:|---:|
| Cold · URL ที่เบราว์เซอร์ใช้ | 2 | 1 |
| Cold · ดาวน์โหลดจากเครือข่าย | 2 | 1 |
| Cold · ข้อมูลโอนรวมตาม Resource Timing | 3,970,444 bytes | 1,985,222 bytes |
| Warm · ดาวน์โหลดจากเครือข่าย | 0 | 0 |

ตัวโหลด Phaser ยังขอ atlas ตามปกติ แต่ได้ผลจาก HTTP cache ใน cold run หลังแก้. ประหยัดประมาณ 1.89 MiB ทุกรอบที่เริ่มแบบ cold ในการทดสอบนี้.

ค่ามัธยฐานจากกดเดินเข้าช่องบอสจนปุ่มเริ่มศึกเปิดใช้ได้ใน cold run อยู่ที่ 1,847 → 1,413 ms และ warm run อยู่ที่ 1,370 → 1,334 ms. วัดสามรอบในเครื่องเพื่อเปรียบเทียบทิศทาง เวลาบนมือถือจริงและบนเซิร์ฟเวอร์เผยแพร่ยังไม่ยืนยัน.

ตรวจภาพก่อนและหลังที่ 390px โดยภาพสนามที่เก็บไว้เหมือนกันทุกพิกเซล. เทสต์ Playwright ตรวจว่าภาพบอสบนแผนที่ใช้ URL ที่มี revision และเส้นทางเข้าสนามมี URL ของ atlas เพียงแบบเดียว.

## ผลทดสอบ

Typecheck, lint และ production Pages build ผ่าน. Playwright ตรวจเส้นทางเดินแผนที่และเข้าศึกทั้ง dev และ production build. ภาพสนาม desktop ก่อนและหลังเหมือนกันทุกพิกเซลด้วย. ชุด unit ผ่าน 2269 กรณีและข้าม 24 กรณี. เทสต์ boss-balance ที่หมดเวลาในชุดรวมผ่านเมื่อรันแยก.
