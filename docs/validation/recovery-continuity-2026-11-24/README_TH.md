# การคืนท่าหลัง contact — 24 พฤศจิกายน 2026

Baseline `827756f` บน `feature/fateweave-initial-prototype`. ใน Chromium ทดสอบ production Pages build บน localhost, `server=off`, `sw=off`. จอ 390×844 ใช้ touch, DPR 3 และ CPU throttle 4×. Desktop 1366×1000 ใช้ DPR 1. ทั้งสองใช้ SwiftShader.

## ผลของแพตช์

เมื่อ cue มาถึงกลางท่าเตรียม ให้ท่าคืนตัวเริ่มจาก transform ที่วาดล่าสุดและ ease กลับฐาน. เฟรม contact และระยะเวลาเดิมยังใช้ตามคิวเดิม. ใน regression test แบบ thrust (เฟรมล่าสุดเมื่อผ่าน 50 จาก 100 ms) พิกัด x ก่อน cue คือ 109 ทั้งสองรุ่น. หลัง update 16 ms โค้ดเดิมกระโดดไป 117.77 ส่วนโค้ดใหม่กลับมาที่ 108.89. เมื่อครบช่วงคืนตัว ทั้งตำแหน่ง มุม และ scale ตรงค่าเริ่มต้น.

## วัดเทียบก่อนและหลัง

ตัวเลขเป็น browser rAF ต่อช่วงและ Long Tasks API. rAF รวมงานของหน้าและการนำเสนอภาพ, ไม่ใช่ตัวนับเฟรม Phaser. ความหน่วงปุ่มเดินใช้เวลาจาก click event ถึง rAF ครั้งที่สอง วัดเพียงสองครั้งต่อรอบ. ค่า memory คือ JS heap ณ ท้ายเส้นทาง.

| เส้นทาง | FPS ก่อน → หลัง | p95 เฟรม ms | Long tasks | Heap MiB |
|---|---:|---:|---:|---:|
| ศึก 390px | 11.1 → 10.2 | 283.3 → 449.9 | 4 → 5 | 11.1 → 12.7 |
| ศึก desktop | 24.4 → 20.6 | 83.4 → 116.7 | 1 → 2 | 13.8 → 14.1 |
| เดินแผนที่ 390px | 4.3 → 4.6 | 916.6 → 1116.7 | 18 → 14 | 8.8 → 9.2 |
| เดินแผนที่ desktop | 7.7 → 6.5 | 300 → 350 | 6 → 6 | 10.1 → 10.1 |

ศึก 390px ใช้บัฟเฟอร์ 1134×1431 ทั้งสองรอบ. เดสก์ท็อป 468×593. การเดินที่ 390px วัด click ถึง rAF ครั้งที่สอง 240/293 → 867/429 ms. ค่าแผนที่ซึ่งไม่ผ่านโค้ดที่แก้ก็ผันผวนมาก. ตัวอย่างรอบเดียวต่อขนาดจอไม่เพียงพอที่จะระบุว่าเฟรมศึกที่ช้าลงมาจากแพตช์. ผลนี้ยังไม่ใช่การวัด GPU time, เสียงจากลำโพง หรือมือถือจริง.

เส้นทางเดินโหลดรวม 23.1 MiB ทั้งก่อนและหลังบน 390px รวม preload. พบ URL สองแบบของ `units.webp` ที่โหลดแยกกันประมาณ 1.89 MiB ต่อครั้ง. ข้อเสนอ PR ถัดไปคือใช้ asset URL ที่มี revision แบบเดียวกันบนโทเคนแผนที่และ loader แล้วเทียบ cold/warm load ก่อนพิจารณาเปลี่ยน prefetch policy.

CDP นับ layout และ style recalculation รวมทั้งเส้นทางศึก desktop ได้ 23/67 → 23/66 ครั้ง และ 390px ได้ 26/81 → 25/82 ครั้ง. CDP รอบนี้ไม่แยกเวลาที่ใช้ใน GPU. เมนู 390px มี p95 316.6 → 516.6 ms และ long tasks 4 → 8 ครั้ง. โค้ดที่แก้ทำงานเฉพาะในฉากศึก จึงใช้ผลจากเส้นทางแผนที่และเมนูเป็นตัวเทียบความผันผวนของสภาพแวดล้อม.
