## Staging load test ที่มีการสุ่มพร้อมกัน — ผ่าน 2026-11-22

Workflow `Cloudflare staging load test` (run 44970708223, ref `claude/p10-gacha-load`, `trio=now` เฉพาะสำเนา staging, Worker+D1 ชั่วคราวถูกลบหลังจบ; ไม่แตะ dev API): 4 runner × 5 บัญชี = 20 บัญชี. แต่ละบัญชีได้ตั๋วจริงจาก trio p-2/p-4 (2+2 = 4 ใบ เพราะนำเข้าเซฟเริ่มกระเป๋าว่างตาม D24) แล้วทุกบัญชีสุ่มพร้อมกัน ครั้งละ 1 ใบ: ส่งคำขอเดิมสองครั้งพร้อมกัน + คำขออีก id ที่ seq เดียวกัน

| ต่อ runner | ผล |
|---|---|
| ตั๋ว/สุ่มสำเร็จ/แต้มเพิ่ม/journal | 20/20/20/20 ทุก runner, ตั๋วเหลือ 0 |
| คำขอซ้ำได้คำตอบเดียวกัน | 20/20 (หักตั๋วครั้งเดียว) |
| คำขอแย่ง seq ถูกปฏิเสธ 409 | 20/20 (ไม่หักตั๋ว) |
| บอสโลก/แชทที่รันพร้อมกัน | 25 ครั้ง retry ตรง 25, แชท 49/49, ไม่มี 5xx |

รอบแรกพบ `429 rate_limited` เมื่อเทสต์ยิง 12 คำสั่งในไม่ถึงวินาที (เพดาน 10 คำสั่ง/วินาที/บัญชีทำงานตามออกแบบ ไม่หักตั๋ว) จึงเว้น 1 วินาทีต่อการสุ่มในเทสต์
