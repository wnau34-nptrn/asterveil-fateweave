# ผังสกิลแบบ popup และตีบวกต่อเนื่อง — 2026-11-08

เจ้าของอนุญาตให้แก้ทั้งสองจุด: “ดำเนินการแก้ไขในเกมได้” หลังหารือเรื่องเปิดรายละเอียดทันทีและกดตีบวกครั้งละหนึ่งขั้นต่อได้เมื่อทรัพยากรพอ

- แตะโหนดในผังสกิลแล้วเปิด native modal ภายในกรอบเกม แสดงรายละเอียด ขั้น แต้มคงเหลือ และปุ่มอัพ 1 แต้ม ใช้ข้อมูลและเหตุผลที่อัพไม่ได้ชุดเดิม
- แผงคงเปิดและอัปเดตหลังอัพ ปิดด้วยปุ่ม X, Escape หรือแตะด้านนอก คืน focus และตำแหน่ง scroll เดิม ลิงก์จากหน้าสกิลเปิดรายละเอียดโหนดได้เช่นกัน
- ตีบวกเป็นคำสั่งครั้งละหนึ่งขั้นจากปุ่มที่แสดงค่าใช้จ่าย หลังสำเร็จมีข้อความผลจริงและเตรียมขั้นถัดไปทันที ไม่ผ่านหน้าตรวจรายการ/ดูขั้นถัดไปซ้ำ
- ตรวจ profile, uid, target และทรัพยากรอีกครั้งก่อนส่งคำสั่ง ปุ่มที่ส่งไปแล้วใช้ซ้ำไม่ได้ ดับเบิลคลิกและคีย์ค้างไม่เพิ่มหลายขั้น
- เพิ่ม Lv, หลอมสี, สุ่มคุณสมบัติ, ถ่ายโอน และรีไซเคิลยังใช้ขั้นตอนเดิม ไม่มีการแก้ rules/save/content/balance

## การตรวจ

- `tests/enhancement-review.test.ts`: 8 ผ่าน ครอบคลุมปุ่มใช้ครั้งเดียว, stale profile/target, ข้ามขั้น, ทรัพยากรไม่พอหลังตีสำเร็จและเพดาน
- `tests/browser/skill-popup-enhancement.spec.ts`: เปิด/ปิด popup, focus/scroll, ดูโดยไม่ใช้แต้ม, อัพและคงแผงเดิม, โหนดเต็ม/ล็อก, ตีต่อและเพดาน; 320×568, 390×650, 390×844 และ desktop 1366×768
- ชุด regression เดิมปรับให้ปิด modal ก่อนเลือกโหนด/สมาชิก/แท็บอื่น และใช้ปุ่มตีบวกโดยตรง การตรวจ scrollbar ใช้จอมือถือสั้น เพราะย้ายรายละเอียดออกแล้วผังไม่จำเป็นต้องเลื่อนในจอสูง
- ตรวจภาพจริง 390px ทั้ง popup และหลังตีบวกสำเร็จแล้ว ปุ่มอยู่ในกรอบและไม่มี error overlay; browser connector ไม่มีเครื่องมือให้เรียกในเซสชัน ใช้ Chromium `/usr/bin/chromium` ผ่าน Playwright ตาม skill ของ repository
- ภาพทดสอบอยู่ภายนอก repository ที่ `/tmp/fateweave-popup-qa/`; quality/browser ของ PR ผ่านครบก่อน merge
- Chromium touch emulation เท่านั้น ยังไม่ได้ทดสอบ Safari/iPhone จริง
