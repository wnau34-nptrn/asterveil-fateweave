## ขอบเขตที่นำเข้า

หน้าตีบวกที่เลือกชิ้นแล้วเป็นหน้าคำสั่งเฉพาะ: ชิ้น/ผู้สวม → ขั้นปัจจุบันและถัดไป → ผลต่อผู้สวม → รายละเอียดที่พับอ่านได้ → ค่าใช้จ่าย/ยอดมี/ยอดเหลือ → ตรวจรายการ/ยืนยัน Dock แยกจากเนื้อหาที่เลื่อน จอสั้นเลื่อนเนื้อหาได้โดยไม่ต้องค้นหาปุ่มท้ายหน้า

คำสั่งอื่นของช่างยังอยู่ครบใน “งานอื่นของช่าง” ของหน้าตีบวก ชุดนี้ยังไม่ทำ task launcher เต็มรูปแบบหรือเปลี่ยนหน้าคำสั่งอื่นตาม Artwork (UXD-02–05) และยังไม่ย้ายแท็บดาว/สกิล (UXD-06–07)

ใช้ภาพ/ชื่อ/ค่าสถานะ/ค่าใช้จ่ายจากเกมจริง รักษาค่าตีบวกทีละ1ขั้นและกฎเดิม ไม่แก้ core/battle, core/save, ราคา, RNG หรือ save schema

## Baseline และผลที่ตั้งใจ

ก่อนเปลี่ยน ใช้ `forge-shots.spec.ts` เก็บหน้าเลือกชิ้น/ตีบวก/reviewที่390pxจาก runtimeเดิม ผล:หน้าชิ้นที่เลือกมี4แท็บหลักและ5วิธีพัฒนาพร้อมกัน ผลต่อผู้สวมอยู่ในรายละเอียดพับอ่าน ชิ้นและส่วนตกแต่งกินพื้นที่ก่อนถึงผล/ราคา

จากปุ่มพัฒนาของสวมถึงหน้าตีบวก1tap แล้วตรวจรายการอีก1tap ทั้งก่อนและหลัง ไม่อ้างว่ารอบนี้ลดจำนวนtap; ผลที่แก้คือการจัดลำดับข้อมูล ความชัดของ review และการย้อนกลับที่รักษาบริบท

baselineดาวและสกิลยังใช้กฎ/ทางเข้าเดิม: อัปดาวจากหน้าทีมไม่มีreviewแยก ส่วนอ่าน/เพิ่มLvอยู่สกิลและปลด/ติดตั้งอยู่ความถนัด บันทึกเส้นทางและfixturesในbrowser testโดยไม่เปลี่ยนพฤติกรรมรอบนี้

## กลไกสำคัญ

- `ForgeWorkbench` ยืนยันได้จากreviewของprofileเดียวกัน ตรวจเป้าหมายเป็นขั้นถัดไปและทรัพยากรอีกครั้งก่อนเรียกhost หลังconfirmล้างreviewทันทีเพื่อไม่ส่งซ้ำ
- การเปลี่ยนชิ้น/ช่อง/ผู้ทดลอง/จำนวนหรือprofileทำให้reviewเดิมใช้ไม่ได้ การเปิด/เปลี่ยนpreview/ยกเลิกไม่persist
- success feedbackมาจาก `forged/enhance` ที่commitจริงในGameShell ไม่เดาจากการกดปุ่ม แล้วย้ายfocusไปข้อความผล ไม่ส่งต่อเป็นconfirmของขั้นถัดไป
- Escapeในreviewตีบวกกลับไปแก้ไขก่อน; Escapeจากหน้าตีบวกกลับต้นทาง คำสั่งเก่าอื่นยังใช้การปิดชั้นเดิม
- เก็บreturn contextในUIชั่วคราว: underlying sheet, hero/tab, filter, picked item, scrollและfocus ไม่เพิ่มfieldในsave ย้อนจากโรงตีเหล็กไปตัวละครเดิมได้และปิดตัวละครแล้วกลับหน้าทีมหรือกระเป๋าเดิม
- ถ้าเข้าforgeจากกระเป๋าโดยตรง ปิดแล้วกลับรายการกระเป๋าและปุ่มชิ้นเดิม ใช้filtersเดิม

## ไฟล์และแนวทางต่อ

- forge-workbench.ts: presentationหน้าตีบวก/preview/dock/review/success; ไม่แยกเป็นframeworkใหม่ งานถัดไปค่อยextractส่วนที่พิสูจน์ว่าซ้ำจริง
- character-panel.ts + lobby-ui.ts: suspend/resumeและบริบทหน้าต้นทาง
- game-shell.ts: ส่งeventสำเร็จให้หน้าUIก่อนrender
- components.css: styleเฉพาะpilot ไม่ทับรูปแบบคำสั่งอื่นหรือdesktop scrollbarของงานก่อน
- enhancement-review.test.ts: staleprofile, reviewใช้ครั้งเดียว, เปลี่ยนpreviewแล้วยืนยันเดิมไม่ได้
- enhancement-pilot.spec.ts: จอสั้น/ปกติ/desktop, profileไม่เปลี่ยนขณะpreview/cancel, ทรัพยากรถูกหักครั้งเดียว, ย้อนกลับfilter/slot/scroll/focus, ของขาดหลายชนิด/ขั้นสูงสุด
- forge-navigation.ts: เทสต์คำสั่งเก่าเปิดdisclosureอย่างผู้เล่นก่อนใช้แท็บเดิม ยังตรวจค่าเงิน/ทุน/ผลคำสั่งเดิมครบ

เกณฑ์ขั้นนี้: typecheck/lint/unit/buildและfocusedbrowserผ่าน, เปิดดูภาพ390px, requiredCIผ่านก่อนmerge/Pages ผลการรันจริงและลิงก์PR/deployจะบันทึกในCODEX-TO-CLAUDE.md ไม่ถือว่าการเก็บภาพเป็นผลhuman usability
