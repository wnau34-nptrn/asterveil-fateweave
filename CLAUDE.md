# Fateweave development instructions

Work only in `asterveil-fateweave`. Never modify, reset, merge, push to, or import private code/assets/history from `asterveil-rise-beyond` (reading its design documents for concept adaptation was approved by the owner on 2026-10-14). Preserve existing target-repository work. Never commit secrets or supplied concept images without explicit authorization. The user explicitly authorized GitHub Pages publication after the initial prototype; the Pages workflow is within that scope. Do not change repository visibility/access permissions, configure other hosting or automatically merge without separate authorization.

## Current architecture

- Phaser 4.2.1 + strict TypeScript + Vite. Framework rules are different from Godot; Godot Lock documents are not requirements here.
- `src/core/battle` owns serializable authoritative state, stable IDs, beat-stamped commands, legal targets, deterministic resolution, preview and replay. No Phaser/browser imports or clocks/random damage in rules.
- Typed `src/content` definitions own actor values, announced intent schedule, hero lanes, class skills, cooldowns and tunable numeric rules.
- `BattleScene` adapts state into disposable shapes/text, pointer selection and VFX. No damage or resource mutations in scenes or tweens.
- `BattleUI` owns temporary skill selection, floating explanations and presentation lock; it commits once, saves immediately and projects state into DOM. Never allow selection alone or background/resume to confirm a command.
- `core/save` accepts an injected storage port and validates saves by command replay. `platform/browser-storage` handles browser API access.
- CSS tokens (`src/ui/tokens.css`, Luminous Veil) define the navy-glass HUD; self-hosted OFL subset fonts Kanit/Noto Sans Thai live in `public/assets/fonts`; Phaser uses original generated unit and backdrop atlases with code-native input, HP/status labels and short VFX. Generated artwork and asset frame mapping live in `game/visuals`; HUD text and controls must remain DOM-native.

## Development rules

1. Keep exactly one primary action per actor turn and one turn per surviving actor each round. Skip dead queue entries and freeze the real target when the enemy starts its turn.
2. Add new rules to the pure resolver and content before wiring UI. Preview must use the same resolver, not duplicate arithmetic.
3. Use meaningful tests for HP boundaries, restrictions, Guard/interruption, Mark follow-ups, formation targeting, cooldowns, barriers/healing, outcomes, preview equality and deterministic replay. Keep a winning offensive route and viable defensive interventions. The balance regression suite compares basic attacks with both target priorities and four-class offensive/defensive routes; choices must have visible consequences without forcing one fixed combo.
4. State is independent of animation. Restart, resize and tab suspension must never change the committed command outcome.
5. Validate all targets and actions again at commit. Downed actors cannot act; reject stale beats.
6. If encounter data or rule semantics change, bump `EncounterDefinition.version`; saves from the old version must be rejected safely.
7. Keep DOM text/controls responsive, touch targets >=44px, readable unavailable-action reasons, immediate casting on a valid marked character, reduced-motion support and keyboard focus.
8. Run `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. For UI/input changes also run relevant Playwright gameplay tests and inspect screenshots of real canvas content.
9. Report tested browsers/devices honestly. Chromium touch emulation does not verify iOS Safari or real devices.
10. Do not add empty architecture folders, backend, accounts, cards, formation switching, skill trees (except the owner-scoped passive talent tree, 2D-1b) or final asset production without a scoped task. Expedition systems follow the approved phase plan in `docs/EXPEDITION_DESIGN.md`; their draft numbers still need owner approval.

## Expedition (single game, no practice mode)

The game is one expedition on a **2D square-tile board** with free four-direction one-tile hops (buttons, arrow keys/WASD, adjacent taps). Never add path-finding auto-movement, linear nodes, dice, cards or room selection. The owner approved adapting Rise Beyond's non-combat *concepts* (Threat-style encounter chance, camps, carried HP, loot/equipment, events, elites, quests); never import its code, data, names or art. Rules, phase status and the approved mercenary decisions (no fixed heroes; roster 4+4; ★1 start, duplicates upgrade; unique class mechanics) are in `docs/EXPEDITION_DESIGN.md`.

- `src/core/world` is the pure, serializable expedition simulation (move, encounter chance and loot from `(seed, rolls)`, fog, rest/revive, chests, finish battle). No DOM, Phaser, clocks or `Math.random` in rules. `src/content/world` owns maps/zones/pools.
- Enemy intents target party slots (`targetSlot`, deployment order), never hero ids. The world deploys the roster's 1–4 `deployed` members via `withParty`; the reserve (≤4) is swapped only at camps. Stars scale max HP/Attack/skill power (`starred`, `skillPower`), never SPD; hiring, upgrades, dismissal and choosing the 4 + 4 happen only in the Lobby (`core/world/profile.ts`, `ui/lobby-ui.ts`); camps and the map entrance only swap the brought 8 and allow withdrawal.
- Battles start from a `BattleEntry` (per-hero HP; 0 = down and out of the queue). The world stores only the entry and hero commands and derives results by replay. World rules decide camps, defeat and rewards; battle rules never change for the world. Choosing not to fight happens before a battle.
- `core/save/expedition-save.ts` owns the single versioned save (key `asterveil.fateweave.expedition.v1`, envelope version 16 `{ profile, run }`; v1–v15 migrate; a run from an older map version settles home as withdrawn; runs settle into the profile in the same write), validates every field and replays an active battle; incompatible data starts a new expedition. Finished battles are applied in the same write as their last command. Practice keys are deleted, never read. Follow save-version rules when changing the state shape.
- `GameShell` switches title/commander/lobby/world/battle views (Home → create commander once → Lobby → Map; the commander never fights); `WorldUI` renders the board as a full-screen DOM tile map (ART-UI-WORLD-001 R2 art chosen by `game/visuals/world-art.ts`) with a floating HUD: zone/danger/info capsules, slim party row, objective dialog, ghost D-pad lower left, contextual action lower right (phone portrait: D-pad bottom-centre with the action in its centre cell, for one-handed play; enabled only as camp **พัก**, which opens the camp sheet, or **เปิด** on an unopened chest), and a pack capsule for resources. No sidebar, joystick, auto-pathing or invented interactions. `BattleUI.open(session)` runs one battle and commits through the session. Lore (2026-10-16): a new company's first expedition opens with the prologue (`ui/story-ui.ts`: the commander wakes in the ruins of the Asterveil frontier, Vargoth the demon chief speaks) and `startPrologue` starts the `first-clash` battle ("ศึกแรก", Vargoth's vanguard) before the first step; winning plays his retreat. Advice runs only in that battle, voiced by the hero whose turn it is (`heroVoice`). Never use the term ม่านเวล; the world is แอสเตอร์เวล and the threat is รอยแยก. The battle view stays laid out while hidden and the Phaser loop sleeps while exploring.
- New mercenary classes live in `src/content/heroes/mercenaries.ts` (catalog = teaching party + `map.mercenaries`); add each class mechanic to the pure resolver with tests, an advisor branch and a win check, one class at a time. Battle spots follow slots/lanes, never hero ids. Art must follow `docs/handoffs/ART-PLACEMENT-RULES.md` (party faces right, enemies face left). Each class's ★3 skill and ★5 passive are `HeroDefinition.unlocks`; world `starred` adds the skill to `actions` and sets `passive`, and the resolver reads `passive` (`hasPassive`), never stars. Use `targetKind` for target groups instead of action lists in the UI.
- Encounter enemy ids are the two field positions `raider` (back, normal) and `brute` (front, large); `EnemyDefinition.art` picks the illustrated frame (`game/visuals/assets.ts` `actorArt`, foes atlas from ART-CHAR-MERC-ENEMY-001). Physical-looking foes use physical moves, energy-looking foes energy moves. Bump an encounter's version when its content changes. Monster levels (2D-1): encounters have a reference `level`; the world fixes a random battle's level from the tile (`monsterLevelAt`) and fights it through `withLevel` (HP/damage only, never SPD). Member levels add stats with stars in `starred`; EXP is granted in `finishBattle` and tapered by `expPercent`. Keep the advisor-wins-from-60%-HP regression and the full-expedition run in `tests/world.test.ts` passing; numbers are drafts until playtested. Balance simulation (4E): `tests/sim/balance-sim.ts` plays whole companies with the pure rules (`npm run sim` writes `docs/validation/balance-sim/REPORT.md`; `npm test` keeps a small guard sweep); rerun it after changing numbers. Elites/mini-boss/boss fight at map fight levels (`EliteDefinition.level`, `map.bossLevel`, stored in the battle at start).
- Talent tree (2D-1b): passive nodes only, no new battle buttons. Trees live in `src/content/heroes/talents.ts` (`map.talents`); members store spent ranks (`MemberProgress.talents`), spent/reset only in the Lobby (`learnTalent`/`resetTalents`); `starred` turns them into stat percents plus `HeroDefinition.talents`, and the resolver reads that (`talentRule`, `hasCap`, `capAmount`), never the member. 0 points must leave every definition unchanged.
- Equipment (2D-2): pure rules in `core/world/equipment.ts`, numbers in `map.equipment`. Items store only slot/rarity/level/class/affix names/special; values derive from the rules. Drops roll in `finishBattle` from the run's (seed, rolls); found items ride in `run.found` and settle home (lost on a wipe); equip/unequip/salvage only in the Lobby. `starred` turns gear into flat HP/Attack/SPD, skill percent and `HeroDefinition.gear` (heal bonus, starting barrier, legendary specials) read by the resolver. SPD only from boots/charms and the wind set. Sets (2D-3): `Item.set` from the zone's `sets` (boss: any); 2-piece stats and 4-piece rules come from `map.equipment.sets` through `gearTotals`. Forge (2D-4): `core/world/forge.ts` (enhance always succeeds; fuse/reroll roll from the profile's `(seed, forge)`), only in the Lobby. Map potions (2D-5): brewed in the Lobby (`brew`), packed on `depart` (≤ `carry` each), used only outside battle (`usePotion`); repel skips encounter rolls and pressure.
- Events and elites (3A): `map.elites` fight when stepped into (beaten for the run: `run.elitesDefeated`); `forced` elites stand on one-tile gates with no way around, the others can be bypassed (tests check the geometry); `map.events` tiles open a choice dialog instead of rolling (`chooseEvent`/`eventChoiceReason`, numbers in `map.eventRules`); event fights are battles of kind `event` with a `source`. The rift seal (3B): the boss is `sealed` until `map.quest.need` objectives are done (`questDone`/`questComplete`, derived from run state); `mini` elites are mini-bosses paying `eventRules.miniBoss`. Puzzles (3C): `map.puzzles` (runes, levers, boulders, secret walls) with pure rules in `core/world/puzzles.ts` and `move`; doors and secrets sit on '#' tiles of `rows` and open per run state (`solved`, `secrets`); puzzle steps never roll encounters. Side quests (3D): one per camp NPC in `map.sideQuests`; `settle` adds run progress (herbs from `map.herbs` only if not wiped) into `profile.quests`, claimed once in the Lobby (`claimQuest`); the quest card sits in the NPC's sheet. Shrine wounds live only on run members and are applied by `wounded` in `memberDef`. Bump `map.version` when the board changes.
- Camp NPCs (ART-CHAR-NPC-001): six staff (`NPC_IDS`) stand at stations in the lobby scene (drawings aria-hidden behind members; tap buttons in the HUD open their service sheet), idle by CSS, work in turn, greet on open, cheer on success; sheets show the NPC's bust and a live Thai line (`npcText`). NPCs never fight and have no rules of their own. On portrait phones the scene and NPC tap targets pan sideways in `.lobby-pan` (`--pan: 3`) and open centred on the fire; NPC frames animate by `transform` only (never `background-position`) from 320 px-cell runtime atlases.
- Item art (ART-UI-EQUIP-001): painted gear/potion/emblem atlases in `public/assets/ui/equip`, mapped by `game/visuals/equip-art.ts` and drawn by `ui/equip-art.ts` (`gearArt` with a code-drawn rarity frame and set emblem, `potionArt`); never bake rarity into art.
- Currencies: gold coins (`gold`) pay only for hiring/dismissal refunds; ore pays for star upgrades, brewing, the forge and the merchant; veil dust for the forge and brewing; seals for upgrades and rerolls.
- World and battle views must fit every tested viewport without document scrolling, with ≥44px controls. `platform/viewport.ts` sizes `#app` from the live layout viewport (`--app-h`, not `100dvh`) and supplies `--safe-top` (with an iOS status-bar fallback); use `var(--safe-top)`, never `env(safe-area-inset-top)` directly. The battle canvas renders at devicePixelRatio (`BattleScene.fit`): lay out with `viewW`/`viewH` in CSS pixels, never `this.scale` size, and create text through `this.text` so it gets the same resolution.

## SPD rounds and floating skill popup

`roundOrder` sorts living heroes and enemies by descending SPD, breaking ties by permanent definition index (heroes then enemies). Freeze `order`/`turnIndex` throughout the round, skip defeated actors, and re-sort at each round boundary. `currentHeroId` reads the current queue slot; foreign actors must fail in `actionReason`, preview and replay. Enemy templates cycle per source/round, execute only on their own turns, and determine real targets at turn start. Forecasts assume today's survivors remain alive; never promise a future target unchanged after deaths.

Each hero command resolves that actor plus subsequent automatic enemies until the next hero or outcome. `beginBattle` also handles faster-enemy opening turns. Commit/save once before presenting independent `TurnStage` frames in actual order; adjacent heroes must not acquire a false enemy stage. UI progression, skip, visibility and reload never repeat damage. `beat` is an actor-turn serial for stale command rejection; user-facing timing is `round`.

Mark lasts 2 rounds including application. Bash/Strike/Bolt/Ward/Heal cooldowns use 2 absolute rounds, Prayer 3. Guard protects the displayed next enemy target/source until consumed or the Knight returns; Bash cancels a chosen enemy's next physical turn, never energy. Earlier content saves start fresh. Preserve two distinct four-survivor plans per encounter and explicit blind Attack policy defeats.

The current/next SPD queue stays in the phase band at every viewport, four compact or six large slots, without document scrolling. Owned skill buttons retain nonmodal floating descriptions, keyboard focus return, delayed closing-touch filtering and direct ≥44px field targets. Other actors remain support recipients only. Cooling skills are readable but cannot cast. On the shortest portrait fields preserve nonoverlapping ally targets and staggered grounded units.
